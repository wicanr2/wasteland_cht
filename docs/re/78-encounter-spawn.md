## 1. 流程

```
0x16890  denom ← 標頭[+0x2F]；＝ 0 → retn
         sub_18E41(denom)；≠ 1 → retn            ; 1／denom 的機率

loc_168A5（找空槽）:
         section 15 的第 n 筆（n 從 0 到 標頭[+0x32]）
         記錄[3] | 記錄[5] | 記錄[7] ＝ 0 → 用它   ; **只看三組的「型別」**
         都沒空 → retn

loc_168CF（決定敵人）:
         kind ← sub_18E41(標頭[+0x31])           ; 擲 1..種類數
         sub_12A4C(kind)                          ; 定址敵人資料表第 kind 筆
         idx ← sub_12A8D() ＝ 那一筆的 +0x05 & 0x0F
         記錄[0] ← ds:AA60h[idx]                  ; 第一道距離門檻
         記錄[1] ← ds:AA6Dh[idx]                  ; 第二道
         ds:AA34h ← ds:AA7Ah[idx]                 ; 要走幾步

0x16906（決定位置）:
         dir ← sub_18E41(9) − 1                   ; 0–8
         ＝ 4 → 放棄                              ; 方向 4 是原地
         從隊伍座標沿 dir 走 ds:AA34h 步，
         每一步都要：座標非 0、沒有別的隊伍（sub_16840）、
                     nibble ＝ 0（空地，sub_17C20）
         任一步不合 → 放棄

loc_1695B（寫下去）:
         記錄[4] ← sub_18E41(敵人資料 +0x04 >> 4)  ; 這一組幾隻
         記錄[3] ← kind
         ds:46B3h ← 0x0F                           ; **第 1 層 ＝ nibble 15**
         jmp sub_17D50                             ; 寫進地圖
```

`sub_12A4C` 用的基址是記錄區標頭 `+0x04`／`+0x05`、stride 8——
與 `Block.EnemyData()` 是同一張表（`docs/re/32` §8.1）。

## 2. 方向跳表 `ds:AAB1h`

九個 word，每支只有一兩行：

| 方向 | 位址 | 動作 |
|---:|---|---|
| 0 | `0x16508` | `dec bl` ＝ y−1（上） |
| 1 | `0x1650D` | `inc bl` ＝ y+1（下） |
| 2 | `0x16512` | `dec dl` ＝ x−1（左） |
| 3 | `0x16517` | `inc dl` ＝ x+1（右） |
| 4 | `0x18016` | **原地**（`sub_164ED` 的收尾本身） |
| 5 | `0x16510` | x−1, y−1 |
| 6 | `0x16506` | x+1, y−1 |
| 7 | `0x1650B` | x−1, y+1 |
| 8 | `0x16515` | x+1, y+1 |

`dl` ＝ x、`bl` ＝ y。擲到 4 就放棄這一次——**原地不能放敵人**。

## 3. 三張 13 項表

```
ds:AA60h  0f 0f 28 41 5a 28 41 5a 41 5a 28 41 5a
ds:AA6Dh  0f 0f 28 41 5a 28 41 5a 41 5a 28 41 5a
ds:AA7Ah  01 01 01 03 04 01 03 04 03 04 01 03 04
```

前兩張一模一樣（15／40／65／90），進記錄 `+0x00`／`+0x01`——
那是遭遇掃描的兩道距離門檻（`docs/re/39`）。第三張是要走幾步（1／3／4）。

索引來自敵人資料表第 kind 筆的 `+0x05` 低 4 位，所以**同一種敵人永遠是同一組
門檻與距離**。

## 4. 為什麼出生點永遠不會遇襲

地圖 0 的出生點 (55,62) 九宮格裡一格 `nibble 0` 都沒有：

```
1 0 0 0 1
0 0 2 1 1
1 1 6 2 0     ← 隊伍在中間
1 1 1 1 1
```

多數敵人的 `dist` ＝ 1，只走一步，而周圍沒有空地——**生成器每次都放棄**。
2000 次嘗試 0 次成功，換到空曠處（(12,2)，九宮格 9 格空地）之後 2000 次生成 6 次。

這不是 bug，是地形：Ranger Center 門口本來就打不起來。

## 6. 這一輪學到的（寫成規則）

- **「接上去了但沒反應」要逐關量，不要重讀程式碼。** 生成器第一版接上之後
  仍是 0 次，逐關印出來才發現卡在「周圍沒有空地」——那不是 bug。
  **每一關印一個數字，比把程式碼再讀一遍快得多。**
- **驗收環境要選對。** 在出生點測遭遇永遠測不到，因為那裡地形就是打不起來的。
  **選測試位置本身是一個要驗證的假設。**
- **三張表裡有兩張一樣，不代表其中一張是多餘的。** `ds:AA60h` 與 `ds:AA6Dh`
  內容相同，但它們填的是記錄的兩個不同欄位（兩道距離門檻）——
  出貨資料剛好讓兩道門檻相等而已。**照結構抄，不要因為值相同就合併。**
