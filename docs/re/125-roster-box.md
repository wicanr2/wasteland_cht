## 1. `sub_16F70`：名單框（列 14–23、欄 0–39）

`sub_1728C`（切到名單模式）的最後一步就是它。

```
0x16F70  ds:46B9h ＝ 0 → retn                 ; 不在名單模式就不畫
0x16F95  ds:4680h ← 0B1E1h；游標 ← (0, 0Eh)
         逐 byte 畫到 0 為止                   ; **列 14：橫幅上半**
0x16FB8  ds:4680h ← 0B20Ah；游標 ← (0, 0Fh)
         逐 byte 畫到 0 為止                   ; **列 15：橫幅下半**
0x16FDB  列 ＋1，到列 23（`cmp 8DD1h, 17h`）為止：
           (0, 列) ← 0Dh；(39, 列) ← 13h      ; 兩邊
0x16FFC  (0, 23) ← 10h；12h 一路畫到欄 39；11h ; 下緣
0x17017  再跑 7 次 sub_1702E                   ; 七個成員各畫一行
```

**列 14 與列 15 合起來是一條雙倍高的橫幅**——上半與下半各一張字模表，
不是「上緣 ＋ 表頭」兩件事。

## 2. 兩張字模表與那個組別指示

| 位址 | 檔案位移 | 內容 |
|---|---|---|
| `ds:B1E1h` | `0x180B1` | `9B 57 5B 57 9E 9C…9F 9A`（40 格，橫幅上半）|
| `ds:B20Ah` | `0x180DA` | `A1 95 99 95 A4 A2…A5 A0`（40 格，橫幅下半）|

索引 1 與索引 3 是**執行期填的**（`0x16F7E` 起那五行）：

```
al ← ds:4654h（目前組）；ds:B1E2h ← al ＋ 57h；ds:B20Bh ← al ＋ 95h
al ← ds:4657h（組數 −1）；ds:B1E4h ← al ＋ 57h；ds:B20Dh ← al ＋ 95h
```

畫出來就是實機截圖左上角那個 `1<1`（`docs/re/54` 的 `54-doc-menu.png`）。
上半用字模 `0x57 + n`、下半用 `0x95 + n`——**同一個數字的上下兩半**。

## 3. 一行從欄 1 開始，不是欄 0

```
0x1738A  sub_1738A(al ＝ 序號)：
           ds:4673h ← al ＋ 0Fh      ; **列 ＝ 序號 ＋ 15** → 第 1 個成員在列 16
           ds:4672h ← 1              ; **欄 ＝ 1**
0x1708B  sub_1708B（畫一行）：
           印序號（`sub_1769C`）→ 印 `>`（`sub_19DC3`）  ; 欄 1、2
           sub_171B9                                    ; 名字，接著印 → 欄 3
           ds:4672h ← 11h                               ; AC（**絕對欄**）
           ds:4672h ← 15h／18h／1Ch／20h                ; AMM／MAX／CON／WEAPON
```

⚠ **欄 0 是框線，不是名單的一部分。** 行首那一欄少算的話整份名單往左移一格、
壓在框線上，而畫面上只是「名單貼著左邊」——看起來像排版風格，不像錯。

⚠ `AC` 以後的欄座標是**絕對值**（直接寫 `ds:4672h`），不跟著行首移動。
把它們當成「相對行首的位移」會整批右移一格。

## 6. 這一輪學到的（寫成規則）

- **「游標設在哪」與「欄位寫在哪」是兩回事。** 一行的起點由 `sub_1738A` 設，
  後面每一欄自己再設一次絕對欄——只讀畫欄位那一支會漏掉起點，
  而漏掉的症狀是整行左移一格，看起來像排版而不像錯。
- **框與內容常常是同一支畫的。** 名單框的「上緣」其實是橫幅的上半，
  把它當成單純的框線就會多畫一條線、少一行字。
