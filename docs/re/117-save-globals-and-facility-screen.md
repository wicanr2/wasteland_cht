## 1. 目前地圖是 `ds:4655h`，不是隊伍槽表的 `+0x0A`

存檔／讀檔搬的是同一塊 14 bytes（`docs/re/27` §7）：

```
sub_18801（存檔）  [0x464E + i] → [0x71A9 + i]，i ＝ 0…13
sub_18744（讀檔）  [0x71A9 + i] → [0x464E + i]，i ＝ 0…13   ; 0x187ED 那個迴圈
```

讀完之後載地圖的是 `sub_18350`：

```
0x18350  al ← ds:4655h
0x18353  cmp al, ds:46E0h        ; 與「已經載進來的那一張」比
0x18357  相同 → 什麼都不做
0x18362  call sub_1841F          ; 不同 → 載新的（bit7 的編號在這裡查表換算）
```

> **原版決定「開場在哪張地圖」的唯一依據是 `ds:4655h`，也就是那 14 bytes 的
> 相對位移 7。** 隊伍槽表的 `+0x0A`（`docs/re/30` §3.1）是「每一組各自在哪」，
> 切組（`View`）時才會用到——**讀檔那條路一眼都沒看它**。

推論等級：**已確認**（三支函式逐行讀出 ＋ 實機驗證，見 §1.2）。

### 1.1 那 14 bytes 目前解出來的欄位

| 相對位移 | 位址 | 內容 | 出處 |
|---:|---|---|---|
| 0、1 | `ds:464Eh`／`464Fh` | 地圖視窗原點 | `docs/re/25` §2.1 |
| 2–4 | `ds:4650h`–`4652h` | 32-bit 累計刻數的低三個 byte | `docs/re/27` §7 |
| 5 | `ds:4653h` | **這一組隊伍槽表上有幾個人** | `docs/re/110` §3、`sub_19B81` 的迴圈上界（§3）|
| 7 | `ds:4655h` | **目前地圖**（bit7 設的要查 `ds:BF1Ch` 換算）| 本節 |
| 8 | `ds:4656h` | **已經用掉的最大角色記錄編號**（雇用時 ＋1 當新記錄，7 人上限比的也是它）| `docs/re/110` §3 |
| 10–12 | `ds:4658h`–`465Ah` | 分的小數／分／時 | `docs/re/27` |
| 13 | `ds:465Bh` | 文字捲動速度等級（0–8）| `docs/re/106` |

位移 6（`ds:4654h`）與 9（`ds:4657h`）**未解**：兩者在戰鬥與設施的程式碼裡
都有讀者（`0x12640`、`0x1512E` 等），但還沒定名。

### 1.2 實機驗證

```bash
tools/go.sh run ./cmd/wl-save -dir workplace/dosbox/game -map 10 -at 30,25
tools/dosbox.sh "wait:6;key:Return;wait:3;key:p;wait:4;shot:40-map"
```

只寫隊伍槽表 `+0x0A` 時：原版出現在**世界地圖（資源 0）的 (30, 25)**——
時鐘對得上（存檔裡的 02:12），所以存檔確實讀進去了，錯的只有地圖。
兩個地方都寫之後：原版出現在**高池鎮（資源 10）的 (30, 25)**，
與 remake 同一格。

⚠ **這種錯不會有任何錯誤訊息**：畫面上是一張正常的地圖、隊伍站在正常的格子上，
看起來只是「傳送到奇怪的地方」。

## 2. 設施畫面：進了店就切成名單模式

實機截圖 `42-shop.png`（高池鎮 `Store`，走上傳送格答 `Y`）：

```
欄 1…13、列 1…11    店主的圖（ALLPICS，96 × 84，視窗原點 (8, 8)）
欄 1…13、列 12      **招牌 `Store`**（置中）
欄 15…38、列 1…13   選單／訊息區，外框上緣寫 `ESC`、下緣寫 `POOL MONEY`
列 14…17            **隊伍名單照常在**（表頭 ＋ 四行）
列 24               **指令列照常在**（`USE ENC ORDER DISBAND VIEW SAVE RADIO`）
```

> **設施畫面就是戰鬥畫面那一套版面**（`docs/re/105` §2）：`sub_1728C` 把畫面切成
> 名單模式，右上那一塊是 `sub_19727` 設的選單區。差別只在左邊那一格畫的是
> 店主而不是敵人，說明字串是招牌而不是敵人名字（`docs/re/115` §1：
> 肖像框畫的是 `ds:46FAh` ＋ `ds:7201h`，**跨畫面模式活著**）。

`docs/re/54` 量的是**站在門口、還沒進去**的那一張（圖畫在地圖視窗上，右邊的地圖
照常露出來）。兩張是不同時刻的畫面，不衝突。

推論等級：**已確認**（實機截圖 ＋ `docs/re/42` §1 的第一行 `sub_1728C`）。

### 2.1 進場要選人

```
Welcome to the shop.        ← 招呼字串（地圖記錄 +0x05，ds:0DBF4h）
Who wants to enter?         ← 字串 2；隊伍只有一人時不問
```

選完之後：

### 2.2 買清單一頁九行，滿了在外框下緣寫 `MORE!`

```
    PRICE      ITEM
1)      10  Book
2)      10  Canteen
3)      15  Crowbar
4)      15  Gas mask
5)     300  Geiger counter
6)      10  Hand mirror
7)       1  Jug
8)      50  Map
9)      10  Match

```

九行是清單元件的一頁（`sub_16DB4` 畫、`sub_16D34` 等按鍵）。翻頁是 `I`／`K`
或方向鍵、選擇是 `1`–`9`、`P` 是集中金錢（§3）、`ESC` 離開——四種出口都在
`sub_16D34` 的按鍵表裡。

## 3. 順帶更正：`P` 是**集中金錢**，不是換人

`docs/re/42` §1 把商店主迴圈的 `'P'` 記成「`sub_19B81` 換下一個人」。
實機截圖的外框下緣寫著 `POOL MONEY`，而 `sub_19B81` 讀出來是：

```
0x19B81  ds:CCD2h ← al                 ; 收款人
0x19B84  ds:CCD3h ← 1                  ; 從第 1 個成員開始
loop:
  相同 → 跳過
  sub_19614(那個人)；sub_19A9C          ; 選人、取他的錢
  sub_198BC(0)                          ; **把他的錢清成 0**
  sub_19614(收款人)；sub_19895           ; 選回收款人、把錢加上去
  ds:CCD3h ＋＋，< ds:4653h（人數）→ 繼續
```

**把其他隊員身上的錢全部搬給選中的那個人**。同一段也印證了
`ds:4653h` ＝ 這一組的人數（§1.1）。

推論等級：**已確認**（整支讀完 ＋ 畫面上的按鍵標籤）。

## 6. 這一輪學到的（寫成規則）

- **同一個狀態存在兩個地方時，要問「讀的人看哪一個」。** 隊伍槽表與全域狀態
  都有「地圖」，remake 兩邊都讀得回來所以自己驗不出問題——
  **只有原版能仲裁**。這正是 oracle 存在的理由。
- **`-keys` 是逐字元送的。** 寫成 `"up,Y"` 會送出 `u`、`p`、`,`、`Y`：
  `u` 開了 `USE` 選單，截圖看起來像「remake 的設施畫面壞掉了」。
  **對拍之前先確認自己的送鍵管道**，否則對到的是自己的工具。
- **畫面上的按鍵標籤是最便宜的斷言檢查。** `POOL MONEY` 六個字直接推翻了
  筆記裡「`P` 是換人」那一句——那句寫在筆記裡快兩個月沒人質疑。
