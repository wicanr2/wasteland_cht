## 1. 角色記錄 `+0x28` 是八個狀態位元

`ds:CF4Eh` 那張表就是 `01 02 04 08 10 20 40 80`——**八個位元遮罩**，
地圖腳本用索引 0–7 挑一個（`docs/re/34` op 10／11／12／17）。

`sub_1C510` 把這個 byte 攤成選單：逐位右移，設起來的就印
`\x10` ＋ `('1' ＋ 序號)` ＋ `) ` ＋ 疾病表的第（序號 ＋ 1）條。
疾病表是 `ds:DCEDh`（`docs/re/17` 表 8），所以位元的名字直接讀得出來：

| bit | 遮罩 | 名稱 | 隨時間惡化 |
|---:|---:|---|:-:|
| 0 | `0x01` | Radiation poisoning | |
| 1 | `0x02` | Wasteland Herpes | |
| 2 | `0x04` | Bug byte | |
| 3 | `0x08` | Sewer rot | |
| 4 | `0x10` | Desert dust | ✓ |
| 5 | `0x20` | Rabies | ✓ |
| 6 | `0x40` | D6 | ✓ |
| 7 | `0x80` | D7 | ✓ |

「隨時間惡化」那一欄來自 `sub_12440` 的 `and al, 0F0h`——**高四位才會讓人越來越糟**，
低四位只是掛著（§2）。推論等級：**已確認**。

`+0x28` 非 0 時名片行會反白（`0x17102` → `sub_19E2A`），
所以 `docs/re/15` 記的「非 0 → 反白」仍然成立——但那是**顯示的副作用，不是欄位的語意**。

## 2. 每 16 刻的體力處理：`sub_12440`

時鐘每 16 刻呼叫一次（`docs/re/27` §6）。對隊伍每個人（上限 `ds:4656h`）：

```
死了（CON 兩個 byte 都 0）                → 跳過
狀態 +0x28 & 0xF0 ≠ 0                     → 惡化分支
CON < 0                                   → 重傷分支
0 < CON < MAXCON                          → 恢復分支
CON ≥ MAXCON                              → 跳過
```

| 分支 | 節奏 | 做什麼 |
|---|---|---|
| **恢復** | `ds:4722h & 0x3F ＝ 0`（目前選中的角色是 `& 0x7F`） | `sub_12537` ＝ **CON ＋1** |
| **重傷**（CON 為負但 ≥ −10） | 每次都做 | `sub_12537` ＝ CON ＋1，接著把 `+0x26/+0x27`（受傷前備份）算術右移一位寫回 CON；歸零就補成 1 |
| **重傷**（CON < −10） | 每次都做 | `sub_1251E` ＝ **CON −1**，而且 **CON 掉破 −50 就直接歸零（死亡）** |
| **惡化** | `ds:4722h & 0x3F ＝ 0` | `sub_1254A` ＝ CON −1；歸零時設成 −1 繼續往下掉 |

⚠ 兩支小函式的方向容易看反：`sub_19CE9` 是**減法**（`CON −= dl:al`，`docs/re/19` §4），
所以 `sub_12537` 傳 `0xFFFF` 是 **加 1**，`sub_1254A` 傳 `1` 才是減 1。

節奏換算：`ds:4722h` 是刻計數，`& 0x3F ＝ 0` 表示**每 64 刻**一次。
荒野一步 4 分鐘、室內 15 秒（`docs/re/27` §3），所以恢復速度隨所在地圖差很多。

推論等級：**已確認**。

## 7. 這一輪學到的（寫成規則）

- **「這個設施是什麼」先看它印哪張字串表。** 追流程要讀幾十條指令，
  而 `mov cx, <表基址>` 只有一行，而且表的內容直接就是答案。
- **傳 `0xFFFF` 給一支減法函式等於加 1。** 這種寫法在 16-bit 程式裡很常見，
  照字面讀會把「恢復」寫成「惡化」——**看到常數是 `0xFF`／`0xFFFF` 就先確認被呼叫者的方向**。
