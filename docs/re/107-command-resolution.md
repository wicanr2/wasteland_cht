## 1. `0x12CC0`：結算階段的分派迴圈

```
0x12CC0  al ← ds:4654h；sub_13924         ; 選這一組
loc_12CC8: bl ＝ 1 … ds:4653h（每個成員）
0x12CCE    sub_172BB(bl)；jb 跳過          ; CON ≤ 0 的人不結算
0x12CD7    al ← [ds:46D8h + bl]           ; 這個人的指令碼
0x12CDD    shl al, 1；bl ← al
0x12CE1    ax ← [bx − 5A98h]              ; ← ds:A568h[指令碼]
0x12CE5    ds:4661h ← ax
0x12CEB    sub_19EB4(ds:A567h)            ; 間接呼叫
```

> **`ds:A43Bh` 是下令階段（檢查前提、選參數），`ds:A568h` 是結算階段（做動作）。**
> 兩張表都是 10 筆、都用指令碼當索引，位址差 `0x12D`。
> 只看到前一張就會得出「原版也不執行動作」——而那是錯的。

`ds:A568h`（`tools/dump_word_table.py … 0xA568 10 --code`）：

| 指令碼 | 結算處理程式 | 做什麼 |
|---|---|---|
| 0 沒下令 | `0x12CFD` | `retn` |
| 1 Hire | `0x132AC` | 真的把人加進隊伍（§6） |
| 2 Attack | `0x12CFD` | `retn`——攻擊在另一個迴圈結算（`0x1AE78`，`docs/re/90`） |
| 3 Weapon | `0x130B1` | **真的換裝備**（§2） |
| 4 Run | `0x12CFD` | `retn`——逃跑在 `sub_130C8` 那一輪 |
| 5 Evade | `0x13223` | 印字串 82「`\x0B evades.`」，就這樣（§5） |
| 6 Load | `0x13228` | **真的裝填**（§3） |
| 7 Use | `0x13265` | **真的施用**（§4，部分未解） |
| 8 全隊逃 | `0x12CFD` | `retn` |
| 9 | `0x0000` | 空 |

推論等級：**已確認**。

## 2. Weapon（`0x130B1`）：換裝備是**切換**

```
0x130B2  字串 0x66 ＝ 102「\x0B swaps equipment.」
0x130B9  bl ← 成員；al ← [ds:46DAh + bl]   ; 下令階段選的槽號
0x130C1  sub_1949E(al)                     ; ← 裝上或卸下
0x130C5  jmp sub_17033                     ; 重畫那個人的名片行
```

`sub_1949E(槽號)`——**槽號是 1-based**（`sub_19AC8`：`位移 ＝ 槽號 × 2 ＋ 0xBB`，
槽 1 → `+0xBD`，與 `docs/re/103` §3 的 `EquipIndex` 對上）：

```
選到的槽 ＝ 記錄 +0x1F（武器欄）或 +0x25（護甲欄）
  → sub_194E8：把那一欄清 0（護甲順便把 +0x1A 的 AC 也清 0）    ← **卸下**
否則
  al ← 物品編號 → sub_17AE0（物品表定址）→ sub_199F1（物品類別）
  類別 ＝ 0x0F  → +0x1A ← 物品表 +0x06（AC）；寫進 +0x25       ← 穿護甲
  否則                                      寫進 +0x1F         ← 拿武器
```

> **同一支既裝也卸**，判準是「選到的槽是不是已經裝著的那一格」。
> 類別 15 走護甲欄、其餘走武器欄，兩個欄位互不干擾——
> **可以同時裝一把武器與一件護甲**。

推論等級：**已確認**。

## 3. Load（`0x13228`）：裝填會把整個彈匣吃掉

```
0x1322B  sub_15C96                       ; 有沒有裝備武器
0x1322E  jns loc_1323D                   ;   有 → 往下
0x13230  dec bl；sub_19ACD(成員)          ;   沒有 → 先自動裝一件
0x13238  sub_15C96；js retn              ;   還是沒有 → 靜靜結束
loc_1323D:
0x13240  sub_19614(成員)                 ; 定址角色記錄
0x13243  sub_15CA4                       ; 這把武器吃不吃彈匣（物品表 +0x07）
0x13246  jz  → 字串 0x42 ＝ 66「's weapon can't be reloaded.」
0x13248  sub_1968C                       ; 在物品陣列裡找那種彈匣
0x1324B  jnb loc_13257                   ;   找到 → 往下
0x1324D      字串 0x41 ＝ 65「has no more clips.」
loc_13257:
0x13257  sub_196DB                       ; ← 真的填（下面）
0x1325A  字串 0x68 ＝ 104「\x0B reloads.」
0x13262  jmp sub_17033                   ; 重畫名片行
```

`sub_196DB(bl ＝ 彈匣所在的槽)`：

```
0x196DF  sub_196C9 → bl                  ; 裝備武器的槽 → 記錄位移
0x196E2  inc bl                          ; ＋1 ＝ 武器的**附屬 byte**
0x196E8  al ← [記錄 + bl]
0x196EE  bit7 設 → 0x1971B：字串表 2 第 152 條「Your weapon is jammed.」，結束
0x196F6  sub_19AB6                       ; ← 把彈匣那一槽的**兩個 byte 都清 0**
0x196F9  sub_196B2                       ; 物品表 +0x07（彈藥編號）
0x19706  al ← 武器附屬 byte & 0xC0        ; 保留高 2 位
0x1970E  al |= 物品表 +0x04（彈匣容量）
0x19718  [記錄 + 武器附屬] ← al
```

> **附屬 byte ＝ 高 2 位旗標 ＋ 低 6 位彈數。** 裝填 ＝ `(舊值 & 0xC0) | 容量`。
> 這與 `docs/re/103` §2 的 `AMM` 欄三道閘是同一組欄位，**現在低 6 位的語意有直讀佐證了**。

> ⚠ **bit7 ＝ 這把武器卡彈，不能裝填。** 字串是表 2 第 152 條，
> 與表 1 第 56 條（攻擊時的「武器卡彈」）**同一句話、不同表**。
> `docs/re/103` §2 把 `sub_19E2A` 記成「兩處都指向這件武器不能用，但沒有直讀」——
> 直讀在這裡：`0x196EE` 的 `js`。

⚠ **裝填會把彈匣整件消耗掉**（`sub_19AB6` 清兩個 byte，不是減 1）。
彈匣是一次性的物品，不是「有幾發子彈」。

推論等級：**已確認**。

## 4. Use（`0x13265`）：主結構已解，兩支子函式未讀

```
0x13268  字串 0x69 ＝ 105「\x0B uses...」
0x13278  di ← ds:46B7h；al ← [bx+di]      ; 隊伍槽 → 角色編號
0x13280  al ← [bx − 5603h]                ; ← **ds:A9FDh[角色編號]**
0x13284  ds:A557h ← al                    ;   （docs/re/41 §7 那個「未解的 byte」）
0x1328B  al ← [ds:46DAh + 成員]           ; 下令階段選的參數
0x13292  dl ← al & 0x0F                   ; **低 4 位是一個欄位**
0x13297  sub_17C69(al, dl)
0x1329E  sub_13C58(bl ＝ ds:A557h)        ; 拿 A9FD 那個 byte 去做事
0x132A1  sub_163F6
```

**已確認**：`ds:A9FDh` 以**角色編號**為索引（不是隊伍槽），
`ds:46DAh` 那個參數的**低 4 位**會被單獨取出來。
**未解**：`sub_17C69`、`sub_13C58` 各做什麼，以及那個 byte 剩下的 4 位是什麼。

## 5. Evade（`0x13223`）：結算階段只印一句

```
0x13223  al ← 0x52 ＝ 82；jmp sub_16CB2   ; 「\x0B evades.」
```

`docs/re/38` §2 讀出下令階段的處理程式是 `clc; retn`（空的），
效果全在命中門檻的基礎值 60。**結算階段也只有一句話**——兩邊都不做事是對的，
迴避真的只靠那個基礎值。

推論等級：**已確認**（兩張跳表的同一格都讀完了）。

## 9. 這一輪學到的（寫成規則）

- **「A 不做這件事，所以 B 一定做」是推論，不是讀出來的。** `docs/re/41` 的
  「動作在結算階段」方向完全正確，但**那句話標的是已確認**，
  而結算端一個位址都沒列。**推論出來的結論要標成推論，並且列出「下一個入口」**——
  這裡的入口只要一句 grep `ds:46D8h` 的讀取端就找得到。
- **一組跳表要問「有沒有第二張」。** 同一個索引在不同階段查不同的表是常見設計；
  `ds:A43Bh` 與 `ds:A568h` 只差 `0x12D`，兩張都是 10 筆。
  **讀完一張表之後，掃一次「還有誰用這個索引」。**
- **接線表擋不住這一類漏接。** `docs/re/41` 標「已接 → `internal/game/handlers.go`」
  是**對的**：那個檔案真的引用了它。漏的是「處理程式做完之後沒有人用結果」。
  接線表自己寫著「有引用只證明有人讀過，不證明實作是對的」——
  **這就是那句話的實例**。要抓這類漏接，得問「玩家按下去會發生什麼」。
