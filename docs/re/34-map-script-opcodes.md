## 1. 這是一台直譯器

踩到第 1 層 nibble ＝ 6 的格子，會走到 `sub_12C80`（`docs/re/29` §5.3）。
記錄 `+0x00` 的 bit7 沒設時，那個值經 section 型別 `0x10` 的指標陣列換成
一個小數字，拿去索引 `ds:A4EAh` 的 **44 筆跳表**（`0x1A470`–`0x1AD14`，
第 45 個 word 是 0）。

每個指令的形狀一樣：

```
讀 ds:46AEh 指到的那筆記錄（自己就是「指令」）
做一件事
CF ＝ 0 → 繼續；CF ＝ 1 → 停
```

`+0x01`／`+0x02` 是**下一步要跳到哪**——好幾個指令的工作就是依條件把
`+0x03/+0x04` 或 `+0x05/+0x06` 搬進 `+0x01/+0x02`（見 op 1、3、15）。
所以這台直譯器有自己的程式計數器，而**分支就是「換一個下一步」**。

## 3. 順便驗證到的三件事

- **標頭 `+0x2F`／`+0x31`／`+0x32` 的語意**（遭遇機率分母／種類數／槽上限，
  `docs/re/00-master-index.md` §4.2）——13 個指令在調整它們，而且各自帶合理的上下限，
  與遭遇生成那邊讀出來的用法完全一致。這是**第二個獨立來源**。
- **角色記錄 `+0x28` 是狀態旗標**，不只是「名片行要不要反白」：
  四個指令都在對它做 `|=`，值從 `ds:CF4Eh` 那張表查出來。
  `docs/re/15` 原本記的「非 0 → 反白」還是成立（狀態非零就反白），
  但**它的本體是旗標不是顯示開關**。
- **`ds:4653h` 與 `ds:4656h` 都是隊伍人數**：op 12 用前者、op 17 用後者做同一件事的迴圈上限。
  出廠存檔兩者都是 4，還分不出差別（`docs/re/32` §9）。

## 4. 對 remake 的意義

這台直譯器是**世界互動的資料驅動核心**：關卡設計者用這 44 個指令寫劇情腳本，
存在地圖區塊的記錄裡。remake 必須把它照實作出來，不能用「照劇情硬寫」代替——
否則每張地圖都要重寫一次邏輯。

指令的參數全部落在記錄的 `+0x03` 之後，`+0x01/+0x02` 是下一步。
**中文化不影響這一層**（它不含文字），但**存檔改寫要保留這些記錄的原始 bytes**。

## 6. 還沒解的

- op 2（`sub_10036` 那個 overlay 呼叫）、op 26（`sub_1142B`）。
- `ds:CF4Eh` 那張狀態旗標表有幾筆、每個 bit 是什麼。
- section 3 與 section 5 在這些指令裡的角色（誰是「腳本」、誰是「場上的東西」）。
- 44 個 opcode 在 42 張地圖的實際使用頻率——還沒統計。

## 7. 這一輪學到的（寫成規則）

- **一組位址連續、大小相近的小函式，先假設它是指令集。** 這 44 支擠在
  `0x1A470`–`0x1AD14`，最短 1 條指令、最長 55 條，全部以 `clc`／`stc` ＋ `retn` 收尾——
  形狀比任何一支的內容更早告訴你它是什麼。
- **指令集會反過來驗證資料格式。** 13 個指令在調整記錄區標頭的三個欄位，
  而那三個欄位的語意本來是從遭遇生成那邊推的。**兩邊獨立對上，才算釘死。**
