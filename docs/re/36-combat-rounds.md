## 1. 敵方是「三組 × 每組最多 10 個」

`0x1ADC6`–`0x1AE50` 是兩層迴圈：

```
外層  ds:CF80h 從 0 數到 2          ← **三組敵人**
內層  bl 從 0 每次 +2 數到 0x14     ← 每組 10 個（HP 陣列一個 2 bytes）
```

`ds:46C8h` 這時指在**某一組的 30-byte 區塊**（`docs/re/37` §2.2）：

| 位移 | 內容 |
|---|---|
| `+0x00`–`+0x13` | 10 個敵人的 16-bit HP |
| `+0x14`–`+0x1D` | **每個敵人一個 byte 的「這回合還沒行動」旗標** |

內層先測 HP 是不是 0（死了就跳過），再測 `+0x14 + n` 那個 byte；
非 0 才排進行動順序，**而且排完立刻清成 0**（`0x1AE06`）——
所以那個 byte 就是「這一輪還沒動過」。

## 2. 行動順序表：`ds:7931h`

```
0x1AE0A  sub_19BF8          ; 累加器 ← 0
0x1AE0D  sub_19C84          ; 2d6 逢同點續擲
0x1AE10  sub_19C2C          ; 累加
0x1AE13  sub_1B15F          ; → sub_12A40（攻擊資料定址）→ sub_12ABA 取 +0x02
0x1AE16  shl al,1 ×3        ; **× 8**
0x1AE1E  sub_19C2C          ; 累加
0x1AE21  sub_1B0E2          ; 寫進 ds:7931h ＋ 游標（16-bit）
0x1AE26  sub_1B0DA(2)       ; 游標 += 2
```

所以：

```
行動值 = 2d6（逢同點續擲）+ 攻擊資料 +0x02 × 8
```

`sub_12ABA` 就是「取 `ds:4665h` 指到那筆的 `+0x02`」（11 bytes），
而 `sub_1B15F ＝ sub_12A40(ds:CF80h) ＋ sub_12ABA`——`sub_12A40` 拿這一組的
型別去定址**敵人資料表**，所以行動值加的是敵人資料 `+0x02`（`docs/re/37` §3.1）。
⚠ **物品表的 `+0x02` 是「非 0 才進商店列表」**（`docs/re/22`）——
又是同一個位移在兩張表裡兩種意思（`docs/re/32` §1）。

游標是 `ds:CF83h`；跳過整組時一次前進 `0x14`（`0x1AE38`），
所以**表的版面是「三組 × 10 格 × 2 bytes」的固定格子**，不是壓縮過的清單。
`sub_1B0F9` 用另一個游標 `ds:CF82h` 把某一格清成 0（那一個單位出局）。

隊伍成員排進**同一張表**，但公式不同——`0x1AE7C` 走的是
「2d6 ＋ Speed（角色記錄 `+0x11`）＋ Brawling × 3」，**沒有 ×8**，
也不碰 `sub_1B15F`（[`90`](90-party-initiative.md) §1）。
`sub_1B15F` 的另外兩個呼叫端 `0x1B046`／`0x1B123` 在命中判定那條路上
（`docs/re/88`），不是行動順序。

而且**只有下攻擊令的人才排進表**（`0x1AE78` 的 `cmp al, 2`，[`90`](90-party-initiative.md) §2）。

推論等級：**已確認**（迴圈邊界、旗標的清除、寫入位址都讀到；
`sub_12ABA` 取的欄位已在 `docs/re/37` §3.1 對上）。

## 3. 誰先動：不是排序，是「每次挑最大的」

`0x1AEAE`–`0x1AEE0`：

```
累加器 B（ds:46C0h）← 0；游標 ds:CF83h ← 0
迴圈（游標每次 +2，繞完整張表）：
    A（ds:46BEh）← 行動表[游標] 的 16-bit 值
    sub_19C69 比較 A 與 B
    A ≥ B → B ← A，且 ds:CF82h ← 游標        ← 記住目前最大的那一格
最大值 ＝ 0 → 這一輪結束
否則 ds:CF82h 指到的那個單位行動，做完 sub_1B0F9 把它那一格清成 0
```

所以**沒有排序演算法**：每次線性掃一遍挑最大的，做完清零，再掃一遍。
效果等同排序，但有一個看得見的差別——

⚠ **同值時取後面的**：比較是 `A ≥ B` 不是 `A > B`，所以掃到相同值會覆蓋。
行動表的前 `0x3C` bytes 是三組敵人，隊伍排在後面，
**所以行動值相同時隊伍先動**。

回合收尾（`0x1AEEB`）：掃 `ds:46D8h` 的隊伍欄位，值為 2 的清成 0
（`ds:46DAh` 同步清）——那是只在這一回合成立的暫時狀態。

## 4. 旗標區的初始化

`0x13740`：對三組各寫一次，`bl` 從 `0x14` 跑到 `0x1E`——
**正好是 `+0x14`–`+0x1D` 那 10 個 byte**，值取自 `ds:0A5A0h`。
這獨立確認了 §1 從「讀了就清零」推出來的那個欄位。

## 7. 這一輪學到的（寫成規則）

- **「排進表就把旗標清掉」是回合制的指紋。** 看到「讀一個 byte、非 0 才做事、
  做完寫 0」，而且外面包著兩層固定邊界的迴圈，那就是回合初始化——
  比追資料流快得多。
- **固定格子的表比壓縮清單好認**：游標一次跳 `0x14` 而不是逐格前進，
  說明表的版面是預留好的，索引可以直接對回單位編號。
- **「排序」常常不是排序。** 這裡是「線性掃描挑最大 → 做完清零 → 再掃」，
  結果等同排序，但**同值的先後順序不一樣**——而那正是會影響玩法的部分。
  看到行動順序就假設是 sort，會把這個差別寫丟。
