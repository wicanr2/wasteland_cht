# 53：清單框架（`sub_16DB4` ／ `sub_16D34`）

輸入：`wl.merged.exe`，SHA-256
`cd5b07eaa55f1e1578caa1b05f0bd5331355cd119f387e61b1a8906738e78118`。

商店的買與賣、訓練師的技能表、醫生的疾病表**共用同一套清單**。
`docs/re/42` 把三個迴圈讀完了，但清單本身一直掛著。這一份補上。

## 1. 兩支的分工

| 函式 | 呼叫端數 | 做什麼 |
|---|---:|---|
| `sub_16DB4` | 11 | **畫一頁**：從 `ds:4699h` 起逐列呼叫回呼，記下每列對應的真實索引 |
| `sub_16D34` | 13 | **等選擇**：回傳選到的索引，或三個特別值 |

## 2. 介面（全域變數）

| 變數 | 意義 | 誰設 |
|---|---|---|
| `ds:4696h` | **每一列的繪製回呼**（`sub_19DC3(3)` 間接呼叫） | 呼叫端 |
| `ds:4699h` | 這一頁的**起始索引** | 呼叫端／翻頁 |
| `ds:469Ah` | 這一頁畫到的**最後一個索引** | `sub_16DB4` |
| `ds:469Ch` | **索引上限**（掃到這個值就停） | 呼叫端 |
| `ds:469Eh` | **每頁列數上限** | 只有一處：`0x1C600`（醫生的疾病表，值 **9**） |
| `ds:469Fh` | 這一頁**實際畫了幾列** | `sub_16DB4` |
| `ds:470Eh` | 呼叫端指定的「換人」鍵（商店與訓練師都是 `'P'`） | 呼叫端 |
| `ds:0B1D0h` 起 | **列 → 真實索引**的對應表 | `sub_16DB4` |
| `ds:4698h` | 選到的**真實索引** | `sub_16D34` |

⚠ **回呼可以說「這一列不要」**：回 CF ＝ 1 那一列就跳過、不佔位子
（賣的清單靠這個濾掉賣不掉的東西，`docs/re/42` §3.1）。
所以**列號與索引不是同一件事**，中間隔著 `ds:0B1D0h` 那張表。

⚠ **每頁列數只有醫生設**（9）。其餘清單沒設，等於「畫到索引上限為止」——
所以「一頁最多幾件」不是全域常數，是**逐個呼叫端決定**的。

## 3. `sub_16D34` 的回傳值

```
ESC (0x1B)              → 0xFF
ds:470Eh（如 'P'）       → 0xFE
Enter (0x0D) 或 Space   → 0xFD
'1'–'9'                 → (鍵 − 1) & 0x0F，且必須 < ds:469Fh（這一頁實畫列數）
                          → ds:4698h ← 對應表[列]，CF ＝ 0
0xCB/0xC8/'I'           → 上一頁
0xCD/0xD0/'K'           → 下一頁
其他                     → 繼續等
```

三個特別值是 `0xFF` > `0xFE` > `0xFD`，所以呼叫端用
`cmp al,0FFh` / `cmp al,0FEh` / `js`（bit7）分辨——
`docs/re/42` §3 那三行判斷現在看得懂了。

⚠ **選擇鍵只有 `'1'`–`'9'`**，而且比對的是「這一頁實際畫了幾列」不是總數。
所以超過 9 件一定要翻頁才選得到，沒有第 10 個鍵。

## 4. 翻頁

```
下一頁：dl ← ds:469Ah ＋ 1；dl ＝ ds:469Ch → 不動（已經到底）
        否則 ds:4699h ← dl，重畫
上一頁：ds:4699h ≤ ds:0B1DDh → 不動（已經在第一頁）
        否則 sub_16E43 往回
```

`ds:0B1DDh` 記的是**第一頁的起始索引**（`sub_16DB4` 開頭在 `ds:4699h` ＝ 1 時設）。

## 7. 這一輪學到的（寫成規則）

- **「列」與「索引」是兩件事。** 回呼可以跳過一列，所以清單上的第 3 列
  不一定是資料的第 3 筆。原版用一張 `ds:0B1D0h` 的對應表接起來——
  重製版若直接拿列號當索引，濾掉東西之後就會選錯。
- **看起來像全域常數的東西，可能只有一個呼叫端在設。** 「每頁 9 列」
  全檔只有醫生設過；把它當成清單框架的常數會讓其他清單無故被截斷。
  **要確認一個值是不是常數，掃寫入點比讀程式碼快。**
