## 1. 升級門檻：`(L² − L) × 512`

升級檢查在 `0x1B93D`（對 `ds:46B5h` 指到的角色）：

```
0x1B93D  lvl ← 記錄 +0x24 ＋ 1          ; 想升到的等級（ds:D435h）
0x1B94C  需求 ← 0                        ; 24-bit：ds:D447h–D449h
0x1B95B  重複 lvl 次：需求 += lvl        ; ＝ lvl²
0x1B97C  需求 <<= 9（9 次移位）           ; × 512
0x1B99E  另算 lvl << 9
0x1B9AE  需求 −= lvl << 9                 ; ＝ (lvl² − lvl) × 512
0x1B9CC  比較記錄 +0x21–+0x23（24-bit）與需求
0x1B9E8  夠 → 升級（0x1BA08）；不夠 → 印訊息離開
```

| 等級 | 需要的累計經驗值 |
|---:|---:|
| 2 | 1,024 |
| 3 | 3,072 |
| 4 | 6,144 |
| 5 | 10,240 |
| 6 | 15,360 |
| 10 | 46,080 |

**升級不扣經驗值**（整段只有比較沒有減），所以 `+0x21`–`+0x23` 是累計值——
與 `docs/re/19` §6 記的「只加不減的 24-bit 計數器」一致。**那個計數器就是經驗值**，
推論等級**已確認**。

24-bit 的上限是 16,777,215，對應等級 181 左右；實務上不會碰到。

## 2. 升級時發生什麼（`0x1BA08` 起）

```
ds:D434h++                       ; 這一輪升了幾級（可以連升）
sub_1B8A0                        ; 播音效 4
階級 ← ds:D522h[等級]            ; 等級 → 階級編號的表
  與前一級的階級編號相同 → 印訊息 0x39
  不同                     → 印訊息 0x38（升階）
記錄 +0x24 ← 新等級
ds:4687h ← 2                     ; 訊息用的數量選擇子（docs/re/28）
sub_1BA72                        ; 顯示角色卡
  └─ 0x1BB18：記錄 +0x20（技能點）＋= 1   ← **每升一級給 1 點**
回到 0x1B93D 再檢查一次           ; 經驗值夠就繼續升
```

### 2.1 階級階梯（`ds:D522h`，byte 表，索引 ＝ 等級）

階級名字走 `sub_1BB5D`（字串表 `ds:D622h`，`docs/re/17`）。
**等級與階級是兩件事**：等級每次 +1，階級到某些等級才換，而且換得越來越慢
——**前 11 級一級一階，之後每 2 級、每 3 級、最後每 4 級一階**：

| 等級 | 階級 | 等級 | 階級 |
|---:|---|---:|---|
| 1 | Private | 30–32 | Lieutenant |
| 2 | Private 1st class | 45–47 | Captain |
| 3 | Specialist | 60–62 | Major |
| 5 | Corporal | 75–78 | Lance Colonel |
| 8 | Grenadier | 95–98 | Lance Commander |
| 11 | Master Grenadier | 115–118 | Brigadier General |
| 12–13 | Sergeant | 127–130 | Technical General |
| 22–23 | Cadet | 131 | General Argent |

完整階梯 **50 階、對到等級 1–131**（字串表有 64 條，用到 50 條）。
第 131 級之後表裡幾乎全是 `0x32`（＝ General Argent），夾雜零星 `0x33`–`0x37`
——那段形狀不像階級表，可能是後面另一個結構的開頭；**經驗值 24-bit 的上限
對應等級 181，所以理論上走得到，但原版沒有為那一段準備資料**。

## 3. 技能學習（`0x1C8E0` 起）

技能資料一筆一個 byte，兩個欄位擠在一起：

```
sub_1CA98：技能資料 +0x00 >> 3   → **IQ 需求**
sub_1CA8D：技能資料 +0x00 & 7    → **基礎技能點費用（1–7）**
```

流程：

```
IQ（記錄 +0x0F）< IQ 需求        → 'YOU ARE NOT SMART ENOUGH!'（0x1C9A1）
技能點（記錄 +0x20）< 費用       → 'NOT ENOUGH SKILL POINTS!'（0x1C906）
掃技能陣列 +0x80 起（每筆 2 bytes）找這個技能編號：
  找到 → 費用 ＝ sub_1C68E(基礎費用, 目前等級＋1)
         技能點 −= 費用；該技能等級 ＋= 1
  沒找到（空槽）→ 寫入技能編號、等級 ← 1，技能點 −= 基礎費用
技能點還有剩就繼續，否則問 Y/N（0x1C9B9）
```

### 3.1 費用隨等級加倍（`sub_1C68E`）

```
al ← 1；重複（等級 − 1）次：al <<= 1      ; ＝ 2^(等級−1)
再把基礎費用累加（等級 − 1）次…           ; 實作是加法迴圈，溢位回 0xFF
```

也就是 **升到等級 L 的費用 ＝ 基礎費用 × 2^(L−1)**，超過 255 回 `0xFF`（買不起）。

| 等級 | 基礎費用 1 | 基礎費用 3 |
|---:|---:|---:|
| 1 | 1 | 3 |
| 2 | 2 | 6 |
| 3 | 4 | 12 |
| 5 | 16 | 48 |
| 8 | 128 | （溢位） |

## 4. 經驗值從哪來

記錄 `+0x21`–`+0x23` 的加法在 `sub_19BC0`（24-bit 帶進位加），
取值在 `sub_19B67`（把 `+0x21` 起三個 byte 搬進 `ds:466Bh`–`466Dh` 的通用 24-bit 暫存）。

兩條來源：

- **戰鬥**：命中之後累加（`docs/re/20`）。
- **地圖事件**：效果記錄（`+0x08`／`+0x09`）可以把目標欄位指成 `0x21`，
  分派時就走 `sub_19BC0`（`docs/re/19` §3）。也就是**踩格子本身就能給經驗值**，
  值可以是固定數或 Nd6——這是效果系統本來就有的兩種形式。

每次給多少（戰鬥那條的計算式）——**未解**。

## 7. 這一輪學到的（寫成規則）

- **一連串 `add` ＋ 移位就是乘法。** 這台機器沒有用 `mul`：`lvl²` 是「重複 lvl 次
  加 lvl」、`× 512` 是九次 `shl`／`rcl`。看到迴圈裡只有加法與移位，先假設它在算
  多項式，再把式子還原出來——比逐條追資料流快得多。
- **「降級過的斷言」要在新證據出現時回頭升級。** `+0x21`–`+0x23` 先前只敢寫
  「只加不減的 24-bit 計數器」（`docs/re/19` §6）。這次升級門檻直接拿它跟
  `(L² − L) × 512` 比大小，語意才定案。**降級不是結案，是待辦**——
  這是同一條規則第二次生效（第一次是金錢，`docs/re/22` §5）。
