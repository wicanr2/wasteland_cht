# 29：地圖事件處理函式 —— 八個 nibble 全解

`cd5b07eaa55f1e1578caa1b05f0bd5331355cd119f387e61b1a8906738e78118`。

## 1. 先解決工具問題：IDA 沒把它們建成程式碼

`ds:AA87h` 的事件分派表（`docs/re/26` §5）裡，nibble 5／8／9 指到
`0x15280`／`0x15160`／`0x14410`——這三個位址在資料庫裡是**未定義的位元組**，
因為只有間接跳表指到它們，沒有任何直接 `call`。

新增 `tools/ida/export_forced.py`：在資料庫的**暫存副本**上
`del_items` → `create_insn` → `add_func`，再逐指令倒出來。
canonical `.i64` 不受影響（`tools/ida.sh run` 本來就跑副本）。

```bash
WL_IDA_TARGET="$PWD/workplace/analysis/unpacked/wl.merged.exe" \
  tools/ida.sh run tools/ida/export_forced.py workplace/analysis/dumps/forced.json \
  0x15280 0x15160 0x14410 0x15441 0x15453 0x12750 0x12C70 0x16CD0
```

⚠ **函式邊界是推的**（線性反組譯到 `retn` 或跳出這段的無條件 `jmp`），
內容則是真的位元組。

## 2. nibble 9（`0x14410`）：印一段訊息

```
0x14410  mov  bl, 0
0x14412  call sub_16D1A        ; 記錄 +0x00 非 0 → sub_17920（印訊息那一族）
0x14415  mov  al, 1
0x14417  mov  ds:46EFh, al     ; 踩在輻射上的旗標
```

四條指令。**nibble 9 是輻射區**：六張有 nibble 9 的地圖，那些格子指到的訊息
全部與輻射有關，而疊圖 8（畫在這種格子上的那張）是輻射三葉標誌——
完整證據在 [`48`](48-map-icons.md) §5。

推論等級：nibble 9 ＝ 輻射區 **已確認**；`ds:46EFh` 的用途 **強證據**
（只有這支寫它，讀取端還沒追）。

## 3. nibble 8（`0x15160`）：問答

**不是選單，是問答**，而且有兩種模式，由記錄 `+0x00` 的 bit7 決定：
bit7 設 ＝ 按一個鍵，bit7 沒設 ＝ **打一行字**（上限 16 bytes）。
兩種模式收到的答案都放進 `ds:7931h`，接著逐一與記錄 `+0x03` 起那串
字串編號解出來的答案比對（`sub_18D8E`），命中第 N 個就走第 N 條後續。

**這就是 `BIRD`／`DIPSTICK`／`MUERTE` 那類密語的比對點。**
完整流程、輸入常式、大小寫處理與中文化的硬約束見
[`46`](46-typed-answers-and-text-input.md)。

記錄的形狀：`+0x00` ＝ 題目字串編號（bit7 ＝ 單鍵模式）、
`+0x03` 起是答案清單（最後一個的 bit7 是結束標記）、
清單之後每個答案兩個 byte 的後續動作。

推論等級：**已確認**（兩種模式與比對都讀完）。

## 4. nibble 5（`0x15280`）：「這裡有東西」——第一次踩到才擲出內容

主迴圈從記錄 `+0x02` 起，**每兩個 byte 一組**（`0x15344` 連兩個 `inc bl`）：

| 第一個 byte | 意思 |
|---|---|
| `0x00` | 清單結束 |
| `0xFF` | 結束並跳 `0x1534B`（`sub_1728C` → 隊伍名單畫面） |
| `< 0x80` | **物品類別**，還沒決定是哪一件 |
| `≥ 0x80` | 已經決定過了（bit7 ＝ 已決定），直接用 |
| `0x5E` | 特例：改寫成 `0xDE` 並把後面兩個 byte 各擲一次骰（`sub_15441` ×2） |

沒決定過的類別會在這裡**擲出具體物品並寫回記錄**：

```
0x152C9  call sub_15453      ; 數出這個類別有幾件物品；ZF ＝ 一件都沒有
0x152DC  call sub_18E41      ; roll(件數) → 要第幾件
0x152E7  迴圈：ds:0A667h++ → sub_17AE0（物品資料表定址）→ sub_199F1（取 +0x03）
0x152F4  與類別相同就算一件，數到擲出來的那一件為止
0x15307  or  al, 80h         ; **設 bit7 ＝ 已決定**
0x1530D  寫回記錄 [bl]
0x1530F  第二個 byte：bit7 設 → and al,7Fh → sub_18E41 → 寫回   ; 數量也擲一次
```

`sub_15453(類別)` 從物品編號 `0x5E`（94）往下數到 1，逐一比對物品資料 `+0x03`：

```
0x15464  al ← ds:0A662h（目前的物品編號）
0x15467  call sub_17AE0      ; 物品資料表定址（docs/re/22 §2）
0x1546A  call sub_199F1      ; 取物品資料 +0x03
0x1546D  與類別相同 → ds:0A663h++
0x15477  編號 −1，數到 0 為止
```

**所以物品資料的 `+0x03` 在這條路徑上是「類別」**，而 `0x5E` ＝ 94 正好是
物品表的掃描上限（商店列表也掃到這個值，`docs/re/22` §2）。

推論等級：**強證據**。形狀是典型的 lazy 生成：**第一次踩到才決定內容，
結果寫回地圖記錄**，所以同一個寶箱重看不會變。

**物品資料 `+0x03` 就是類別，沒有第二種語意。** 看起來像衝突的那個
「傷害骰數 N」在另一張表裡（攻擊資料表，記錄區標頭 `+0x04`）——
兩張表都是 8 bytes 一筆，共用同一支定址器，差別在基址（`docs/re/32` §1）。

## 5. 剩下的三個：nibble 1、4、6

`export_forced.py` 一起倒出來（同樣要強制建指令）。三支都很短，
而且都以 `sub_169B1` 收尾——那是共同出口（用 `ds:46A6h`／`ds:46A7h` 呼叫
`sub_17CFF` 回主流程）。

### 5.1 nibble 4（`0x12750`）：印一句就走

```
0x12750  bl ← 0；sub_16D1A      ; 記錄 +0x00 非 0 → 印訊息
0x12755  al ← 2；jmp sub_169B1
```

### 5.2 nibble 1（`0x16CD0`）：只有「還沒走到」才印

```
0x16CD0  sub_17DC7 → 這一格的地圖座標（視窗原點 ＋ ds:46A8h/46A9h）
0x16CD3  sub_17CD2 → 換算
0x16CD6  座標 ＝ ds:4716h/4717h（隊伍位置）→ bl ← 0，否則 bl ← 1
0x16CEC  迴圈：記錄 [bl] 起逐個字串，bit7 ＝ 續接
0x16CFF  bl ＝ 0（就站在這一格）→ **不印**
0x16D0F  al ← 印了幾條；jmp sub_169B1
```

所以 nibble 1 是**遠看才有的描述**：走到那一格上面反而不顯示。

### 5.3 nibble 6（`0x12C70`）：第二層分派

```
0x12C70  al ← 記錄 +0x00 → sub_12C80
0x12C7B  al ← 1；jmp sub_169B1
```

`sub_12C80` 才是重點——它**再分派一次**：

```
al bit7 ＝ 1 → 索引 ＝ al & 0x7F，跳 ds:A4E0h[索引]      ; 5 筆
al bit7 ＝ 0 → 用 section 型別 0x10 取記錄，跳 ds:A4EAh[…] ; 44 筆
兩條回來 CF ＝ 1 → sub_163C4
```

| 表 | 線性 | 筆數 | 目標範圍 |
|---|---|---:|---|
| `ds:A4E0h` | `0x27300` | **5**（到 `ds:A4EAh` 為止） | `0x1A2C0`–`0x1C260`，各自相距很遠 |
| `ds:A4EAh` | `0x2730A` | **44**（第 45 個 word 是 0） | `0x1A470`–`0x1AD14`，位址連續遞增 |

### 5.4 第一張表：五個設施畫面（記錄 `+0x00` 的 bit7 設起來時）

五支的開頭形狀一模一樣：

```
把地圖記錄的 13 bytes 複製到 ds:7201h        ; 起點各不同（+0x03／+0x04／+0x07）
al ← 0..3；sub_190A6
  └─ al |= 0x80 → ds:46FAh；sub_184E8 載入那張 ALLPICS 圖（docs/re/23 §4）
     再把 ds:4680h 指到 0x7201 印出來
```

**那 13 bytes 是地點名稱的明文**——存檔全域狀態 `+0xC8` 存的
`Ranger Ctr. `（`docs/re/30` §3）就是從這裡來的。

| 位址 | 名稱起點 | 圖 | 身分 | 等級 |
|---|---|---:|---|---|
| `0x1BE50` | `+0x07` | 1 | **商店**——全檔通往 `sub_1C073`（買賣迴圈）的唯一路徑，而且它把記錄 `+0x03`／`+0x05` 搬進 `ds:46C3h`／`ds:DBF4h`，正好是 `docs/re/22` 記的折價指數與開場訊息 | 已確認 |
| `0x1A2C0` | `+0x03` | 3 | 先 `sub_18801`（**寫存檔**）再進選單迴圈（`sub_17574` 比對字首字母）——形狀是 Ranger Center 那種「存檔／管理」設施 | 強證據 |
| `0x1C260` | `+0x07` | 0 | **醫生**——`sub_1C561` 印疾病表 `ds:DCEDh`（`Exam $`／`Healing`／`Curing`），治療會清 `+0x28` 的狀態位元（`docs/re/35` §4） | 已確認 |
| `0x1BBA0` | `+0x04` | 2 | **技能訓練師**——`sub_1BE31` 印的是技能學習字串表 `ds:DACCh`（`docs/re/35` §4） | 已確認 |
| `0x1B4F0` | — | — | 逐隊員把記錄 `+0x4B` 的 bit0 設起來（迴圈上限 `ds:4656h` ＝ 隊伍人數），再跑 `sub_1B7B7(1..4)` ＋ `sub_1B735` 定時的四階段 | 未定 |

剩下的 `0x1A2C0`（先寫存檔再進選單）與 `0x1B4F0` 還沒定名。

跳表 `ds:A4E0h` 的五個 word（線性 `0x27300`）：

```
0xC260  0xBE50  0xBBA0  0xA2C0  0xB4F0   ← 第六個 word 是 0xA470（opcode 0）
```

所以編號就是 **0 醫生／1 商店／2 訓練師／3 存檔／4 未定**，
而且**表長 5 由下一張表的位址決定**，不是數迴圈數出來的。

### 5.4.1 設施記錄在資料裡有幾筆

42 張地圖的 section 6 陣列裡共 **7 筆**設施記錄（`+0x00` 的 bit7 設起來）：

| 種類 | 筆數 | 在哪幾張地圖 |
|---|---:|---|
| 0 醫生 | 2 | 13、38 |
| 1 商店 | 1 | 9 |
| 2 訓練師 | 3 | 13、15、38 |
| 3 存檔 | 1 | 0 |

⚠ **只掃「目前有格子指到」的記錄會得到 2 筆**（訓練師與存檔），
看起來像「這遊戲沒有商店也沒有醫生」。差別在於設施記錄多半**不是**
一開始就被格子指到的——要答對密語或跑腳本把那一格改寫過去
（`sub_17CFF`，`docs/re/46` §4.1）之後才走得到。

> **「地圖上現在有什麼」不等於「這張地圖有什麼」。** 統計地圖內容時要掃
> section 陣列本身，不要只掃格子指到的——後者會把可以被改寫出來的東西全部漏掉。

### 5.5 第二張表：44 個腳本指令

第二條路徑（記錄 `+0x00` 的 bit7 沒設）先用 section 型別 `0x10` 取一筆，
**那個 section 的指標陣列裡存的不是位移而是小數字**，直接拿來索引 `ds:A4EAh`。
44 個目標各自讀 `ds:46AEh` 指到的那筆記錄、做一件事、用 CF 回報成敗——
**這是一台小型腳本直譯器，記錄 `+0x00` 是 opcode、`+0x01/+0x02` 是下一步**。

44 個指令的完整表在 [`34`](34-map-script-opcodes.md)。

## 7. 這一輪學到的（寫成規則）

- **「IDA 沒建成函式」不等於「那裡沒有程式碼」。** 只被間接跳表指到的位址
  在資料庫裡就是一堆未定義位元組，`export_listing.py` 也倒不出來——
  症狀是「查不到這個位址」，跟「這個位址不存在」長得一樣。
  解法是在**副本**上強制 `create_insn`，而不是繞去別的反組譯器。
- **看起來像「同一個欄位兩種語意」的，先確認是不是兩張表。** 原版只有一支
  資料表定址器，基址是全域變數（`docs/re/32` §1）——不同呼叫路徑讀的是不同的表，
  而取值那一段的程式碼長得一模一樣。
- **`add_func` 圈出來的邊界不能照單全收。** 對只被跳表指到的位址，它常常只圈住
  第一條指令，於是逐指令倒出來只有一行——**症狀跟「這裡真的只有一條指令」一樣**。
  `export_forced.py` 現在的做法是：函式小於 16 bytes 就丟掉 IDA 給的邊界，
  改線性反組譯到 `retn` 或跳出這段的無條件 `jmp`。
