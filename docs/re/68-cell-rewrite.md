## 1. 七個呼叫端，差別只在「拿記錄的哪個位移」

```
sub_17CFF(al ＝ 記錄裡的位移, dl ＝ x, bl ＝ y)
    al ← 地圖記錄[位移]
    ＝ 0FEh／0FDh → 用上一次算出來的（ds:46FCh／46FDh）
    ds:46B3h ← 那個 byte        ; 新的第 1 層
    ds:46B4h ← 下一個 byte      ; 新的第 2 層
    ds:46FCh／46FDh ← 這一格**目前**的 (nibble, 記錄)   ; 給下一次的 0FEh 用
    jmp sub_17D50
```

| 呼叫端 | 傳入的位移 | 時機 |
|---|---:|---|
| `sub_13EC9`（條件閘收尾） | **4** 或 **6** | 全部人都過 ＝ 4（`0x1406D`）、有人沒過 ＝ 6（`0x14045`） |
| `sub_15CE0`（第四道閘） | 1 或 2 | nibble 11 ＝ 1、nibble 4 ＝ 2 |
| `sub_169B1` | 1／2／4 | 由呼叫端給（nibble 4／9／12 的處理） |
| `sub_13762`／`sub_13C58` | 敵方記錄的前兩個 byte | 遭遇相關 |

**同一支被四類機制共用**：條件閘、地形閘、事件處理、遭遇。
原版沒有「旗標」這種東西——答對密語、開了鎖、踩過陷阱，
表現方式都是**把那一格改成別的東西**。

## 2. `sub_17D50`：真正寫下去

```
al ← ds:46B3h
bit7 設 → clc retn        ; **不改**
sub_17D7A                 ; 寫第 1 層（見下）
sub_17C72                 ; 算第 2 層的位址
[ds:46ACh + y×寬] ← ds:46B4h   ; 寫第 2 層
stc retn
```

第 1 層是 4-bit packed，所以 `sub_17D7A` 要挑 nibble：

```
偶數格：al ← byte & 0x0F；新值 << 4；or
奇數格：al ← byte & 0xF0；新值直接 or
```

**清掉目標 nibble 再 OR**，所以正常情況等同「設定」。
但奇數格那條路 `or al, ds:BA08h` 用的是**整個 byte**——
新值超過 `0x0F` 就會污染高 nibble（也就是隔壁那一格）。
出貨資料沒踩到，`ParseCellPatch` 也因此**只去掉 bit7、不遮成 4 bits**，
讓 `SetCell` 有機會出聲而不是靜靜吃掉。

## 3. 實跑：游不過河會被沖到下游

資源 0 的 section 2 記錄 **2**（河流，64 格；`+0x03` ＝
`You are caught by the river's current.`，條件是技能 7 難度 6）：

```
+0x04／+0x05 ＝ ff ff   ; 游過去了 → bit7 設 → 不改
+0x06／+0x07 ＝ 0a 22   ; 沒游過 → 改成 **nibble 10（傳送）記錄 0x22**
```

傳送記錄 `0x22`：

```
80 00 01 00 …
+0x00 ＝ 0x80  bit7 設 → +0x01／+0x02 是**相對目前座標**的位移
+0x01／+0x02 ＝ (0, +1)   ; 往下游沖一格
+0x03 ＝ 0                ; 同一張地圖
```

**所以「被水流帶走」就是往下沖一格**，而下游那一格（(31,60)）是記錄 6
＝ `As calm as the water is here…`——平靜的水。

```
tools/go.sh run ./cmd/wl-play -script "path=31:59,down,up,down,up" -trace
  27 path  (31,59)  The party gets hurt for 4 point of damage.   ← 條件失敗，全隊各 −1
  29 up    (31,60)  TELEPORT.                                     ← 那一格已經變成傳送格
```

### 3.1 實機對拍

同一串鍵送進 DOSBox（`-emit-keys` 的 timeline，每個按鍵後補一次 `Return`
清訊息視窗）：

| | 原版 | remake |
|---|---|---|
| 踩上 (31,59) | `You are caught by the river's current.` ＋ 四人各 `gets hurt for 1` | 同一組判定（訊息合成一行：`The party gets hurt for 4`） |
| 之後 | `As calm as the water is here…`（下游那一格） | 走到 (31,60) 的記錄 6，同一句 |

資料、程式碼、remake 實跑與實機四邊一致。

⚠ **工具限制**：訊息視窗填滿時 DOSBox 停在 `ENTER`，後續按鍵全部失效。
長路徑的 timeline 要在**每個**按鍵後補 `key:Return`——每 4 個補一次不夠。
補 `Return` 會順帶叫出訊息速度滑桿（`SLOW ─── FAST`），但不影響移動。

## 4. remake 的取捨

`0xFE`／`0xFD`（沿用上一次算出來的值）**一律當成不改**：
原版把上一次的 `(nibble, 記錄)` 存在 `ds:46FCh`／`46FDh`，
remake 沒有那個暫存。照抄要先決定「上一次」的生命週期跨不跨地圖、跨不跨存檔，
在那之前不改比亂改安全。

## 5. 這一輪學到的（寫成規則）

- **「已解的格式」不等於「接上的機制」。** `ParseCellPatch` 照 `docs/re/46`
  寫得好好的，但全 repo 沒有人呼叫——**解完格式要順手 grep 一次呼叫端**，
  死碼會安靜地待很久。
- **同一支被多類機制共用時，差別往往只是一個參數。** `sub_17CFF` 的七個呼叫端
  差別只在「拿記錄的哪個位移」；先找出那個參數，比逐個呼叫端讀快得多。
- **改寫地圖格就是這個遊戲的「狀態」。** 沒有旗標、沒有事件表——
  開過的鎖、踩壞的地、答對的密語都是把格子換掉。
  重製版若另外做一套旗標系統，存檔就對不回原版。
