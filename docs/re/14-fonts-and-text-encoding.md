## 1. 結論：原版有兩套字型、兩套索引空間

先前把 `ds:722Fh` 的 `+0x1C` 當成「字元碼重映射」，以為文字編碼另有一套。
實際上是兩套獨立的字型，各有自己的索引方式：

| | 主文字字型 | 彩色字型 |
|---|---|---|
| 來源 | **內嵌在 `wl.exe`**，`seg003:0xCA60` | `colorf.fnt`，載到 `seg003:0xB4E0` |
| 字模大小 | 8 bytes（8×8、1 bit／像素） | 32 bytes（8×8、EGA 4 平面、4-bit 顏色） |
| 字模數 | 128（`and ax, 7Fh`） | 172（5,504 ÷ 32） |
| 索引 | **ASCII − 0x20** | 自成一套，見 §3 |
| 繪製 | `sub_1060C`（overlay slot 5） | `sub_10CB6`（overlay slot 19） |
| 用途 | 遊戲所有一般文字 | **只用來畫選單詞** |

**中文化要動的是主文字字型那一套**，它是純 ASCII、可預測、而且不在獨立檔案裡。

## 2. 主文字字型（`seg003:0xCA60`）

`sub_1060C` 的關鍵五行：

```
0x10651  257f00      and     ax, 7Fh         ; 索引取低 7 位
0x10654  8bf0        mov     si, ax
0x10656  d1e6        shl     si, 1           ; ┐
0x10658  d1e6        shl     si, 1           ; │ × 8
0x1065A  d1e6        shl     si, 1           ; ┘
0x1065C  81c660ca    add     si, 0CA60h      ; ＋ 字型基址
```

來源段是 `ds:9165h` 存的段值（`seg003`），不是預設 DS——
`0x10672 mov cx, ds:9165h ／ mov ds, cx`。同一件事在 slot 19 也做一次
（`0x10D14`）。**把 `ds:` 位移直接當 seg002 位址會整組對不上**，
`0xCA60` 在 seg002 裡是一段執行期緩衝，看起來像雜訊。

畫法：`mov al, 0Fh` 寫進 sequencer map mask ＝ 四個平面同時寫，
所以主文字是**單色**的；8 次 `movsb`，每次 `di += 0x28`（EGA mode 0Dh 一列 40 bytes）。

`ds:4678h` 非 0 時走另一條路：`lodsb ／ not al ／ stosb` ——**反白**。

### 2.1 字模配置（已確認）

| 索引 | 對應 | 內容 |
|---|---|---|
| 0–95 | ASCII `0x20`–`0x7F` | 完整可見 ASCII，**含小寫**。`0x7F` 是一個臉狀圖示 |
| 96–99 | 字元碼 `0xA0`–`0xA3` | 上／下／右／左四個箭頭 |
| 100–124 | — | 全空白 |
| 125–127 | 字元碼 `0x12`–`0x1F` 會落進這裡 | 三塊網點圖樣 |

最後一列的推導：控制碼判斷是 `cmp al, 12h ／ jnb`，所以 `0x12`–`0x1F`
會通過判斷、接著做 `sub al, 20h` 變成 `0xF2`–`0xFF`，再被 `and 7Fh`
折成 `0x72`–`0x7F`（114–127）。

重製時可以直接照 `索引 ＝ ASCII − 0x20` 做，值域外的行為要照上表復現。

## 3. 彩色字型（`colorf.fnt`）與 `+0x1C` 的真正意義

`sub_10CB6` 裡那段一直沒解釋的程式碼：

```
0x10CD4  cmp  al, 18h
0x10CD6  jb   short loc_10CE5
0x10CD8  cmp  al, 33h
0x10CDA  ja   short loc_10CE5
0x10CDC  cmp  byte ptr ds:722Fh, 0
0x10CE1  jnz  short loc_10CE5
0x10CE3  add  al, 1Ch
```

把字模畫出來就清楚了（`tools/dump_font.py colour`）：
`colorf.fnt` 裡有**兩組形狀完全相同、只有顏色不同的 28 格字模**，
一組從 `0x18` 開始、一組從 `0x34` 開始，相距正好 `0x1C`。

| bank | 起點 | 顏色 |
|---|---|---|
| 暖色 | `0x18` | 外框 4（紅）、填色 E（黃） |
| 冷色 | `0x34` | 外框 1（藍）、填色 B（亮青） |

逐格比對可以驗證：`0x1E` 與 `0x3A` 的位元圖樣一模一樣，只有顏色平面不同。

所以 **`ds:722Fh` 不是字元碼重映射，是選色旗標**：
0 → 換成冷色那組，非 0 → 用暖色那組。預設是 0（冷色），
`sub_18B4C` 會把它暫時設成 1、畫完再設回 0。

### 3.1 索引：`(ch & 0xDF) − 0x29`

`sub_17451` 把 ASCII 換成彩色字型索引：

```
0x17490  3c20   cmp  al, 20h        ; 空白
0x17492  7418   jz   short loc_174AC ; → 直接印 0x31
0x17494  24df   and  al, 0DFh       ; 轉大寫
0x17496  04d7   add  al, 0D7h       ; ＝ − 0x29
```

`'A'`(0x41) → `0x18`、`'Z'`(0x5A) → `0x31`，也就是 **A–Z 線性落在 `0x18`–`0x31`**。
slot 19 的範圍檢查正好是 `0x18`–`0x33`，兩邊互相印證。

### 3.2 那六個不是字母的槽位

把 `0x18`–`0x33` 全部畫出來，A、B、C、D、E、F、I、L、M、N、O、P、R、S、T、U、V、W、X、Y
都在該在的位置，但 **G、H、J、K、Q、Z 六格放的是 UI 拼貼（箭頭、面板邊框）**，
不是字母。

這不是矛盾，因為彩色字型只拿來畫**選單詞**。全檔的選單字串是：

```
0x277EC  seg002+0xA9CC  'Use Enc Order Disband View Save Radio'
0x29C32  seg002+0xCE12  'CREATE DELETE PLAY'
```

用到的字母只有 `A B C D E I L N O P R S T U V W Y`——
**沒有任何一個是 G、H、J、K、Q、Z**。當年美術把用不到的字母格挪去放 UI 圖了。
（A–Z 裡沒用到的是 F、G、H、J、K、M、Q、X、Z 九個，被挪用的是其中六個。）

把兩個選單字串逐字餵進 `(ch & 0xDF) − 0x29` 再畫出來，每個詞都清楚可讀——
這是這條映射的端對端驗證。

推論等級：**已確認**（映射讀自程式碼、字模畫出來對過、用實際選單字串走完一遍）。

### 3.3 中文化的意義

- 選單詞是**用字母形狀畫的圖**，不是走文字管線。改成中文要嘛替換這 28 格字模，
  要嘛把選單改走主文字字型。這是版面決策，等規格階段定。
- **鍵盤選單靠字首字母比對**（`sub_17574` 拿按鍵碼比對每個詞的第一個字母），
  所以中文選單必須另外設計選擇鍵，不能只換字。

## 4. 文字管線

```
sub_1786E  印字串（28 個呼叫端）
  ├─ sub_1785E     設定每字元處理器 ds:B265h ← sub_19E53
  └─ 逐 byte → sub_1789C ── jmp word ptr ds:B265h ──┐
                                                     │
   sub_19E53（組行）── 字元寫進 ds:71CDh 的行緩衝 ───┤ 兩者擇一
   sub_19DC3（直繪）── sub_1000F ＝ overlay slot 5 ──┘
```

`sub_17857` 會把 `ds:B265h` 改指向 `sub_19DC3`，`sub_1785E` 改回 `sub_19E53`。
兩支的前半段一模一樣（同一組旗標檢查），差別只在字元最後是進緩衝還是直接畫。

### 4.1 控制碼表（18 個）

兩支處理器都在 `cmp al, 12h` 之後用 `碼 × 2` 查跳表：

| 處理器 | 跳表位址 | 線性 |
|---|---|---|
| `sub_19E53`（組行） | `ds:CD74h` | `0x29B94` |
| `sub_19DC3`（直繪） | `ds:CD50h` | `0x29B70` |

兩張表只有三格不同（`0x00`、`0x08`、`0x0D`）。

| 碼 | 處理器位址 | 作用 | 等級 |
|---|---|---|---|
| `0x00` | `0x19EAE`／`0x19E24` | 收尾（`sub_19004` ＋ `sub_1A26C`） | 強證據 |
| `0x01` | `0x19E2A` | `ds:4678h ← 0xFF`＝**反白開** | 已確認 |
| `0x02` | `0x19E30` | `ds:4678h ← 0`＝**反白關** | 已確認 |
| `0x03` | `0x19E36` | 反白關 ＋ 跳 overlay slot 6（**清到行尾**） | 強證據 |
| `0x04` | `0x1001B` | overlay slot 9 ＝**清除矩形** | 已確認 |
| `0x05` | `0x18EAD` | **等待按鍵**（分頁暫停） | 強證據 |
| `0x06` | `0x19EE1` | 同 `0x05` | 已確認 |
| `0x07` | `0x19727` | 未解 | 未解 |
| `0x08` | `0x19F12` | 往回找行首非空字元，寫 `ds:CDCCh` | 假說 |
| `0x09` | `0x19E3C` | **相對定位**：讀下一個 byte 當參數加進欄位計數 `ds:4672h`，再跳過它 | 已確認 |
| `0x0A` | `0x1A004` | `ds:4702h ← 1`（模式旗標，`sub_1A00A`） | 強證據 |
| `0x0B` | `0x19ECD` | 存回字串指標，`sub_171B9` 把 `ds:46B5h/46B6h` 換進 `ds:4680h/4681h`＝**插入角色記錄裡的字串（名字）** | 強證據 |
| `0x0C` | `0x1A03F` | `ds:470Ch ← 1`（模式旗標，`sub_1A045`） | 強證據 |
| `0x0D` | `0x19EFC`／`0x1A0C5` | 組行版走欄位推進；直繪版走計時器等待＝**延遲** | 強證據 |
| `0x0E` | `0x1A078` | `ds:471Bh ← 1`（模式旗標，`sub_1A07E`） | 強證據 |
| `0x0F` | `0x1A275` | 用 `ds:4687h` 呼叫 `sub_176A2` | 未解 |
| `0x10` | `0x19EB8` | `ds:4703h ← 1`＝**捕捉下一個字元**（寫進 `[bx−0x7224]`） | 已確認 |
| `0x11` | `0x19EBE` | 把 `ds:8DDCh` 起 25 bytes 清零＝**清一行緩衝** | 已確認 |

**`0x09` 帶一個 byte 參數**，這件事對中文化很重要：翻譯工具在切字串時
不能把控制碼後面那個 byte 當成文字。

## 5. 選單系統

彩色字型的唯一使用者。三支：

| 函式 | 作用 |
|---|---|
| `sub_17533` | 依 `ds:4688h`（目前選中的第幾個詞）走過字串，把該詞的位移放進 `ds:468Bh` |
| `sub_17451` | 把那個詞置中畫在第 `0x18` 列，用彩色字型 |
| `sub_17574` | 拿按鍵碼 `ds:4667h` 比對每個詞的**第一個字母**，比中就把 `ds:4688h` 換過去 |

按鍵碼由 `sub_18EFE` 在 `0x18FFC` 寫進 `ds:4667h`；同一支在
`0x18FF0`–`0x18FFA` 會把小寫字母減掉 `ds:C058h`（值為 `0x20`）轉成大寫。

## 6. 可重跑的完整指令

```bash
# 兩套字型畫成文字圖
python3 tools/dump_font.py colour workplace/orig/wastland/colorf.fnt   /tmp/font-colour.txt
python3 tools/dump_font.py mono   workplace/analysis/unpacked/wl.merged.exe /tmp/font-mono.txt

# 相關函式完整倒出
WL_IDA_TARGET="$PWD/workplace/analysis/unpacked/wl.merged.exe" \
  tools/ida.sh run tools/ida/export_function.py workplace/analysis/dumps/text-layer.json \
  0x1060C 0x10CB6 0x1786E 0x19E53 0x19DC3 0x17451 0x17533 0x17574 --callers
```

字型與跳表的位址換算：
`seg003` 起於線性 `0x2AE20`（主文字字型 `seg003+0xCA60` ＝ `0x37880`）；
`ds:` 位移在 seg002，起於線性 `0x1CE20`。**兩者不能混用**——§2 的坑就是這個。

## 7. 這一輪學到的（寫成規則）

- **`ds:` 位移不是永遠指向同一段。** 繪圖程式碼會先 `mov ds, ds:9165h` 換段，
  之後的 `ds:XXXX` 全部要用 `seg003` 當基底。判斷位址之前先往上找最近的
  `mov ds, ...`，不要一律套 seg002。症狀是「解出來像雜訊」，不會報錯。
- **看不懂的常數，先把資料畫出來再猜。** `+0x1C` 猜了很久都沒結論，
  把 172 個字模畫成文字圖之後，兩個 bank 的關係一眼就看出來了。
- **「這裡少了六個字母」不是矛盾，是線索。** 缺的字母正好是選單詞用不到的，
  反過來證明了這套字型的用途範圍。下結論之前先問「那它實際上要印什麼」。
