## 1. 結論

原版**有**遊戲時鐘，24 小時制，走一步推進的時間由**該地圖的記錄區標頭**決定：

```
ds:4658h   分的小數（低位累加器）
ds:4659h   分（滿 60 進位）
ds:465Ah   時（滿 24 歸零）
```

```
每走一步：ds:4658h/4659h ＋= word(標頭 +0x34)      ← 每步的分鐘數 × 256
          ds:4722h       ＋= byte(標頭 +0x36)      ← 週期任務的刻度
          ds:4650h–4652h ＋= byte(標頭 +0x36)      ← 32-bit 累計（不歸零）
```

時鐘顯示在畫面外框的上緣，晝夜（門檻 6 時與 18 時）會改變地圖上畫出來的圖形。

## 2. `sub_1676A`：走一步之後推進時間

移動流程在捲動之後呼叫它（`0x1655D`，`docs/re/26` §1）：

```
0x1676A  mov  al, ds:4658h
0x1676D  mov  bl, 34h
0x1676F  mov  di, ds:46B0h        ; 記錄區標頭
0x16773  add  al, [bx+di]         ; ＋ 標頭 +0x34
0x16775  mov  ds:4658h, al
0x16778  mov  al, ds:4659h
0x1677B  inc  bl                  ; 標頭 +0x35
0x1677D  adc  al, [bx+di]         ; 帶進位
0x1677F  mov  ds:4659h, al
0x16782  cmp  al, 3Ch / cmc / jnb ; ≥ 60 分？
0x16787  sub  al, 3Ch             ;   分 −= 60
0x1678C  mov  al, ds:465Ah
0x1678F  add  al, 1               ;   時 ＋= 1
0x16791  cmp  al, 18h / cmc / jnb ;   ≥ 24 時？
0x16796  mov  al, 0               ;     時 ← 0
```

接著推進第二個刻度：

```
0x1679B  mov  bl, 36h
0x1679D  ds:4722h  ＋= [標頭 +0x36]      ; 週期任務用，換地圖時歸零（sub_18350）
0x167A9  ds:4650h  ＋= [標頭 +0x36]      ; 32-bit 累計，進位疊到 4651h／4652h／722Eh
0x167C3  if (ds:4722h & 0x0F) == 0 → sub_12440
```

## 3. 每步多久：實測 42 張地圖

```bash
python3 tools/summarize_map_layers.py …   # 標頭欄位隨層結構一起倒出
```

| 標頭 `+0x34/+0x35` | 每步分鐘（÷256） | `+0x36` | 地圖數 |
|---|---:|---:|---:|
| `0x0400` | **4.0**（荒野大地圖 #0） | 16 | 1 |
| `0x0200` | 2.0 | 4 | 2 |
| `0x0080` | 0.5 | 2 或 4 | 11 |
| `0x0040` | **0.25**（15 秒，一般室內） | 1 | 28 |

`+0x36 × 64 ＝ word(+0x34)` 在 **39／42** 個地圖成立——也就是 `+0x36` 的一刻通常
是 **0.25 分鐘**，而 `sub_12440` 每 16 刻跑一次 ＝ **每 4 分鐘遊戲時間**一次。
三個例外（資源 #38、#39、#40）的 `+0x36` 偏小，那幾張地圖的週期任務跑得比較慢。

## 4. 時鐘顯示（`sub_17DF1`）

```
0x17DFB  ds:8DD0h ← 0x1C        ; 字元欄 28
0x17DFD  ds:8DD1h ← 0           ; 字元列 0 ← 就是外框的上緣（docs/re/25 §2.3）
0x17E05  畫字元 0x0A
0x17E0A  ds:465Ah（時）→ sub_176A8 → 十位、個位
0x17E21  畫字元 0x0C            ; 分隔
0x17E26  ds:4659h（分）→ 同上
0x17E3D  畫字元 0x0B
```

`sub_176A8` 把一個 byte 丟進 24-bit 轉十進位（`sub_18DCE`），結果的兩位數
在 `ds:466Eh`，印的時候取高 4 位與低 4 位——**兩位數、補零**。

## 5. 晝夜：門檻是 6 時與 18 時

兩處各自獨立，門檻一樣：

| 位置 | 作用 |
|---|---|
| `0x1805D`（`sub_18024`） | `時 < 6` 或 `時 ≥ 18` → 這一格改用圖形 `8`；否則走第 3 層的圖形編號 |
| `0x1A528` | 白天（`6 ≤ 時 < 18`）讀記錄 `+0x03`，夜間讀 `+0x05` |

所以**夜間的地圖畫面與白天不同**，而且同一筆記錄可以有「白天版」與「夜間版」。

## 6. 以時間為節拍的角色處理（`sub_12440`）

每 16 刻（多數地圖 ＝ 每 4 分鐘遊戲時間）跑一次，對隊伍每個成員
（迴圈上限 `ds:4656h`）處理角色記錄的 `+0x1B`–`+0x1E`（MAXCON／CON）與 `+0x27`／`+0x28`：

- `+0x1E` 的 bit7（CON 為負）→ 與 `0xF6` 比較後走另一條路（傷勢惡化那一族）
- `+0x28` 高 4 位非 0 → 每 `ds:4722h & 0x3F` 歸零時（＝ 64 刻）走 `sub_1254A`
- 其餘情形在 `ds:4722h & 0x3F`（隊伍成員 ＝ 目前操作者時是 `& 0x7F`）歸零時
  呼叫 `sub_12537`

`sub_12537`／`sub_1254A` 的內容還沒逐行讀，但位置與節拍已定：
**「隨時間恢復／惡化」這一族全部掛在這裡**（執行檔字串
`'\x0b must heal over time.'` 也指向同一個機制）。

## 7. 32-bit 累計與存檔

`ds:4650h`–`4652h` ＋ `ds:722Eh` 是**不歸零的累計計數**（單位同 `+0x36` 的刻）。
`sub_1CB30`（常駐段）拿它與 `ds:722Ah`–`722Dh` 的差值比 `0xF0`，超過就呼叫
`sub_183B1`——週期性的重載／檢查。

存檔會把 `ds:464Eh` 起的 **14 bytes** 原樣搬到 `[0x71A9]`（`sub_18801`），
讀檔反向（`0x187ED`）。這 14 bytes 涵蓋 `0x464E`–`0x465B`，
**包含視窗原點、32-bit 累計與時鐘**——所以時鐘是存檔狀態的一部分（盤點 C2 的一塊）。

## 8. 順便解出：標頭 `+0x33` ＝ 地圖外的填充圖形

`sub_18024` 畫一格時第一件事就是讀 `+0x33`：

```
0x1802C  call sub_18016          ; 座標在地圖範圍內嗎
0x1802F  mov  bl, 33h
0x18035  mov  al, [bx+di]        ; al ← 標頭 +0x33
0x18037  jb   loc_18098          ; 出界 → 直接拿這個 al 當圖形編號畫
```

實測 42 張地圖的 `+0x33` 落在 0–145，全在圖形編號的值域內（`docs/re/24` §2.3），
其中 13 張是 0（`IC0_9.WLF` 的第 0 號，空白）。

## 10. 還沒解的

- `sub_12537`／`sub_1254A` 的內容（恢復與惡化的實際公式）。
- 時鐘的初值：全檔沒有寫入點，只有存檔載入那條路，所以新遊戲的起始時間
  應該在存檔範本裡——要等 C2 解開。
- `ds:722Ah`–`722Dh` 的語意（`sub_1CB30` 拿來比 `0xF0`）。
- 夜間圖形 `8` 是 `IC0_9.WLF` 的第 8 號還是別的（§5 那一行只寫 `al ＝ 8`）。

## 11. 這一輪學到的（寫成規則）

- **「有沒有 X 機制」要先問資料，再問程式碼。** 這一輪先掃 4,935 條遊戲文字找
  `hour`／`o'clock`／`night`，41 條命中全是慣用語——**文字層沒有時間系統的痕跡**。
  這個負面結果不是結論，但它把搜尋方向從「找時間的文字」轉成「找每步被加的變數」，
  兩步就找到了。（掃描本身有正對照：同一份語料裡其他詞彙照樣命中。）
- **找週期性機制，就找「每個動作都會執行的那一段」裡的加法。** 從「走一步成功」
  的位址做可達性分析，只列對全域做 `inc`／`add` 的指令，42 個候選裡
  `ds:4658h`／`4659h`／`465Ah` 三個連號的一眼就看得出是時：分。
- **一個常數在兩個無關的地方出現同樣的門檻，就是語意。** `cmp al, 6` 與
  `cmp al, 12h` 同時出現在畫格子的 `sub_18024` 與記錄選擇的 `0x1A526`，
  兩處都以 `ds:465Ah` 當輸入——晝夜的判定不必再猜。
