`docs/re/105` §2 把「指令階段的肖像畫的是誰」列為未解：實機截圖裡沒有敵人，
出現的是遊俠的圖，所以只能說「至少在沒有敵人時畫的是隊伍這一邊」。

## 1. 肖像框 ＝ 一張圖 ＋ 一行 13 bytes 的說明（`sub_190A8`／`sub_190B8`）

```
0x190A8  ds:46FBh ← 0                 ; 畫面上「有圖」的旗標先關
0x190AD  ds:46FAh ← al                ; ← **目前這張圖的編號**（唯一的來源）
0x190B0  call sub_184E8               ; 載圖並畫上去（docs/re/23 §4）
0x190B3  ds:46FBh ← 1

0x190BE  ds:4672h ← 1                 ; 游標欄 1
0x190C3  ds:4673h ← 0x0B              ; 游標列 11
0x190C8  印空白直到欄 13              ; 把圖下面那一列清乾淨
0x190D4  push ds:4680h
0x190D8  ds:4680h ← 0x7201            ; ← **說明字串的緩衝區**
0x190DE  dl ← 1；bl ← 0x0C；sub_17868 ; 印在（欄 1，列 12）
0x190E5  pop  ds:4680h
```

兩件事對上了：

- `ds:46FAh` 是**目前這張圖的編號**，`sub_190F8` 重畫時就是讀它（`0x190FF`）。
  存檔／換地圖時連同 `ds:46FBh` 一起搬進 `ds:CE49h`／`ds:CE4Ah` 再搬回來
  （`0x1A2DD`、`0x1A3C0`）——所以它**跨畫面模式活著**，不是戰鬥專屬的變數。
- `ds:7201h` 是**13 bytes 的說明字串**，就是存檔 `+0xD0` 的那一格
  （`docs/re/30` §「地點名稱」，出廠是 `Ranger Ctr. `）。地圖進場時從地圖標頭
  `+3` 抄 13 bytes 進來（`0x1A2C0`–`0x1A2D8`）。

> **肖像框不是戰鬥的元件，是「目前這張圖 ＋ 它的說明」**。設施畫面、戰鬥畫面
> 用的是同一張圖與同一行字，差別只在誰最後寫了 `ds:46FAh` 與 `ds:7201h`。

推論等級：**已確認**（三處寫入點與 `sub_190B8` 的座標逐行讀出）。

## 2. 每一回合挑一次：最近的那一組（`sub_12636`）

`sub_12636` 只有一個呼叫端——`0x11FEF`，戰鬥回合入口 `sub_11F76` 走完
「還有沒有敵人」之後、開指令選單（`0x1200D` 的 `sub_19727`）之前：

```
0x11FC1  bl ← 0；al ← [ds:46C8h + 0]   ; 這一組還有沒有人（docs/re/105 §1）
0x11FC9  非 0 → loc_11FEF
   …都沒有 → 印字串 20 ＋ 76、問 Y/N（`sub_12619`）…
0x11FEF  call sub_12636                ; ← 肖像框
0x1200D  call sub_19727                ; 指令選單的區域
```

`sub_12636` 自己：

```
0x12640  al ← ds:4654h；sub_13A37
0x1264C  al ← 0x0C；call sub_126D7      ; 掃 12 筆
0x12651  找到 → loc_1266B
0x12653  dl ← 0；al ← 0x30；sub_126D7   ; 再掃 48 筆
0x1265A  找到 → loc_1266B
0x1265C  ds:46F0h−−
0x12660  al ← 0x60；call sub_16CB2      ; ← **印字串 96 ＝ `Ranger`**
0x12665  al ← 8                         ; ← **圖 8**
0x12669  jnz  loc_12692                 ; 直接去組說明那一段

0x1266B  （找到了）
0x12672  bl ← ds:0A420h；dec bl；sub_13A56 ; 選定那一組
0x12681  dl ← bl；call sub_129E9          ; 名字（§4）
0x12688  dl ← ds:0A420h；call sub_12A40   ; 定址到那一組的敵人資料
0x1268F  call sub_12A9D                   ; ＝ 資料 +0x07 ＝ **肖像編號**
0x12692  …把說明抄進 ds:7201h（§3）…
0x126D4  jmp  sub_190A8                   ; 載圖 ＋ 印說明
```

`sub_126D7` 是那個「挑」的迴圈：`ds:A422h` 起始 0xFF，逐組取
**`[ds:46C8h + 3]` ＝ 那一組與隊伍的距離**（`docs/re/101` §6），
`cmp al, ds:A422h ／ cmc ／ jb` 比下去——條件成立才更新，所以留下的是**最小值**：

| | 值 |
|---|---|
| `ds:A420h` | 選中的組號 |
| `ds:A422h` | 選中的那一組的距離 |

⚠ **同一個迴圈順便把敵人組列印在畫面上**：`sub_1271F` → `sub_12284` 一次處理一組，
印出組號、名字、`" at "`（字串 97）與距離，而且**目前這一組印成反白**
（`0x122B5` 比 `ds:4654h`，相等就 `sub_19E2A`，`docs/re/111`）。挑不到組時
畫面上那份清單也是空的——玩家看到的「敵人像沒出現」與「清單上沒有東西」
是同一件事的兩個表現。推論等級：**強證據**（`sub_12284` 的印字路徑逐行讀出，
`sub_122E9` 的失敗條件還沒讀完）。

> **肖像框畫的是「離隊伍最近的那一組敵人」**：圖 ＝ 那一組敵人資料的 `+0x07`，
> 說明 ＝ 那一組的名字。**一組都挑不到才畫遊俠**（圖 8、字串 96 `Ranger`）——
> `docs/re/105` 那張截圖是空地遭遇，沒有任何一組，走的正是這一支。

推論等級：**已確認**（兩條分支都讀到底，字串 96 在字串表裡就是 `Ranger`）。

## 3. 說明字串置中在 12 格裡（`0x12692`–`0x126D1`）

```
0x12693  0x7201–0x720C 填空白（12 格），ds:720Dh ← 0    ; 結尾
0x126A5  al ← ds:4672h − 1                ; ＝ 剛印出來那個名字的長度
0x126AA  ≥ 0x0C → 不置中（bl 維持 0）
0x126AF  al >>= 1；bl ← 6 − al             ; ← 置中的起點
0x126BC  從 ds:71CDh 逐 byte 抄，每個 +0x20，填到 bl == 0x0C
```

12 格、置中、每個 byte 加 `0x20`（文字緩衝區存的是 ASCII − 0x20）。
截圖上的 `Ranger` 六格，起點 ＝ 6 − 3 ＝ 3，正好對上。

## 4. 名字走的是 `+0x09` bit0 那條分岔（`sub_129E9`）

```
0x129E9  bl ← 9；di ← ds:46C6h；al ← [bx+di]   ; 遭遇記錄 +0x09
0x129F1  shr al, 1                             ; bit0 → CF
0x129FA  CF=1 → loc_12A04                      ; 地圖的明文名字表
0x129FC  否則 loc_12AA2；al += 0x52；印字串     ; 種類名（表 1 的 83–87）
```

與 `docs/re/114` §6 是同一個位元、同一條路：設著就用地圖的明文名字表
（`Juveniles`），沒設就印五個大分類之一（`Animal`／`Mutant`／`Humanoid`／
`Cyborg`／`Robot`）。**戰鬥訊息裡的稱呼與肖像框的說明是同一支函式產生的**，
所以兩處永遠一致。

## 7. 這一輪學到的（寫成規則）

- **「畫的是誰」要問「誰寫了那個變數」，不要問「這個畫面是什麼模式」。**
  肖像框看起來是戰鬥畫面的一塊，實際上畫的是一個**跨模式活著**的全域
  （`ds:46FAh` ＋ `ds:7201h`），戰鬥只是最後一個寫它的人。
- **截圖只證明它走過的那一條分支。** `24-encyes.png` 是空地遭遇，
  看到的是「一組都挑不到」的後備路徑；把它當成「戰鬥就是畫遊俠」會整條反過來。
- **`cmp ／ cmc ／ jb` 是取最小值的慣用法**（`cmc` 之後 `jb` ＝ 原本的 `jae`），
  照字面讀成「大於就跳」會把「最近的一組」讀成「最遠的一組」——
  而兩種讀法在只有一組敵人的畫面上長得一模一樣。
