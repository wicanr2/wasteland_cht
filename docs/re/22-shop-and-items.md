## 1. 商店是一筆地圖記錄

商店沒有硬編在程式裡，設定全部從**目前的地圖記錄**（`ds:46AEh`）讀出來：

```
0x1BEA5  b303      mov  bl, 3
0x1BEA7  8a01      mov  al, [bx+di]      ; di ＝ ds:46AEh
0x1BEA9  a2c346    mov  ds:46C3h, al     ; ← 折價指數（見 §3）
0x1BEAC  b304      mov  bl, 4
0x1BEB0  a2c246    mov  ds:46C2h, al     ; 未解
0x1BEB5  b305      mov  bl, 5
0x1BEB7  a2f4db    mov  ds:0DBF4h, al    ; 開場訊息編號（sub_178A0 印它）
0x1BE9A  b306      mov  bl, 6
0x1BEA2  a2c446    mov  ds:46C4h, al     ; 未解
```

這與 `docs/re/19` 的效果系統同一個路數：**行為在程式碼裡，參數在資料裡**。

主迴圈（`0x1BF2C`–`0x1BF5C`）用字母選單：

| 按鍵 | 動作 |
|---|---|
| `B` | 買（`sub_1C073`） |
| `S` | 賣（`sub_1BF5F`） |
| `P` | `sub_19B81`（隊伍相關） |
| `ESC` | 離開 |

## 2. 物品資料表：`ds:7A31h`，95 筆 × 8 bytes

定址在 `sub_17AE0`（12 個呼叫端）：

```
0x17AE0  b9397a    mov  cx, 7A39h        ; 基址
0x17AE3  890e9446  mov  ds:4694h, cx
0x17AE7  b208      mov  dl, 8            ; ← stride 8
0x17AE9  8816-9b46 mov  ds:469Bh, dl
0x17AED  e95cf4    jmp  sub_16F4C        ; ds:4665h ＝ 基址 ＋ 索引 × 8
```

表本身是**執行期載入**的（映像裡那段是零）。載入在 `0x186A9`：

```
0x186A9  b9f802    mov  cx, 2F8h         ; ← 760 bytes
0x186AC  ba317a    mov  dx, 7A31h
0x186AF  e85e93    call sub_11A10
```

**760 ÷ 8 ＝ 95 筆**，而執行檔的字串表裡物品名正好是 **95 條**
（編號 36–130，`docs/re/17` §4）。兩個獨立來源的數字完全吻合。

`sub_17AE0` 的基址是 `0x7A39` ＝ 表首 `0x7A31` ＋ 8，也就是**索引從 1 開始**。
商店列表（`sub_1C140`）從 1 掃到 93（`cmp al, 5Eh` 停）。

### 2.1 已知欄位

| 位移 | 內容 | 依據 |
|---|---|---|
| `+0x00`–`+0x01` | **基礎價**（16-bit） | `sub_17B5C` 把它搬進 24-bit 金額暫存 `ds:466Bh`– `466Dh` |
| `+0x02` | 非 0 才會出現在商店列表 | `sub_1C140` 的 `test al, al ／ jz 跳過` |
| `+0x03` | **傷害骰數 N** | `sub_12A76`（`docs/re/20` §4） |
| `+0x05` 高 4 位 | **傷害基底** | 同上 |
| `+0x07` | 與角色記錄的某欄位比較 | `sub_19202` 的 `bl=7 ／ cmp al,[bx+di]` |

`+0x04`、`+0x05` 低 4 位、`+0x06` 未解。

## 3. 價格公式

`sub_1C1CC`：

```
sub_17B5C                          ; 金額 ← 物品 +0x00/+0x01（16-bit 基礎價）
dl = ds:46C3h                      ; 折價指數（來自地圖記錄 +0x03）
if dl == 0: return                 ; 0 → 原價
loop dl 次:
    ds:466Dh/466Ch/466Bh >>= 1     ; 24-bit 右移一位
金額 ← 物品[+0x00/+0x01] − 剛才右移的結果
```

也就是：

```
價格 ＝ 基礎價 − (基礎價 >> n)     n ＝ 地圖記錄的 +0x03
```

| n | 實付比例 |
|---:|---|
| 0 | 100% |
| 1 | 50% |
| 2 | 75% |
| 3 | 87.5% |
| 4 | 93.75% |

**n 越大越接近原價**，所以 `n ＝ 1` 是最便宜的一檔。同一支被買與賣兩條路徑共用，
差別在地圖記錄給的 `n`。

推論等級：**已確認**（三支函式讀完，24-bit 右移與借位減逐條對過）。

## 4. 買的流程（`sub_1C073`）

```
sub_1968A                    ; 找角色的空物品槽；沒有就印 'Your inventory is full.'
印 'PRICE     ITEM' 表頭      ; 訊息 7
sub_1C140                    ; 列出有供貨（+0x02 非 0）的品項
選擇（sub_16D34）
sub_1C1CC                    ; ← 算價格
sub_17B3E                    ; ← 拿價格跟角色金錢（+0x15，24-bit）比大小
jnb → 'That costs too much!'
sub_1968A                    ; 再找一次空槽
rec[空槽]   ← 物品編號
rec[空槽+1] ← 附屬 byte
sub_17B15                    ; ← 扣款（24-bit 借位）
```

## 5. 金錢欄位確認

`docs/re/19` §6 曾把角色記錄 `+0x15`–`+0x17` 降級成「可花用的 24-bit 計數器」，
理由是「語意沒有由文字直接證實」。商店這條路徑把它補上了：

- 商店字串表有 `'You have $'`（訊息 4）與 `'That costs too much!'`（訊息 9）
- 買東西時拿**價格**跟 `+0x15` 比大小（`sub_17B3E`），不夠就印那句
- 成交後用 `sub_17B15` 從 `+0x15` 扣掉**同一個價格**
- 醫生的字串表（`ds:DCEDh`）也有 `'Healing costs $'`、`' per CON point.'`

**`+0x15`–`+0x17` 是金錢**，等級升回**已確認**。

至於 `+0x21`–`+0x23`（只加不減，戰鬥命中後累加），仍然**未解**——
不要因為「一個是錢，另一個大概是經驗值」就寫進規格。

## 6. 還沒解的

- 賣的價格用哪個 `n`（`sub_1BF5F` 那條路徑的 `ds:46C3h` 從哪來）。
- 物品資料 `+0x04`、`+0x05` 低 4 位、`+0x06` 是什麼。
- 地圖記錄的 `+0x04`（→ `ds:46C2h`）與 `+0x06`（→ `ds:46C4h`）在商店裡的作用。
- 物品資料表從資料檔哪個位移讀出來（`0x186A9` 那一段的 seek 計算還沒逐條讀）。
- 商店列表只掃到 93，但表有 95 筆——最後兩筆是什麼。

## 8. 這一輪學到的（寫成規則）

- **兩個獨立來源的數字對上，就是很強的佐證。** 物品資料表載入 `0x2F8` ＝ 760 bytes、
  stride 8 → 95 筆；字串表裡的物品名正好 95 條。這兩件事是從完全不同的路徑
  （載入器 vs 文字解碼器）得到的，吻合不太可能是巧合。
- **降級過的斷言要留著回頭補。** `+0x15` 先前因為「沒有文字證實」降成
  「可花用的計數器」，這次商店路徑補上了 `'You have $'`／`'That costs too much!'`
  與比價扣款的完整鏈，才升回已確認。**降級不是結案，是待辦**。
