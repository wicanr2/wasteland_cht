## 1. opcode 0 —— 有沒有別的隊伍站在這串座標上（`0x1A470`）

`docs/re/34` 記成「比對目前地圖／座標與記錄裡的一串條件」。逐指令讀完之後
它比的是**別支隊伍**：

```
al ← ds:4657h
loc_1A473:
  ds:CF30h ← al                    ; 迴圈計數（每一輪都存回去）
  cmp al, ds:4654h ; jz 下一組      ; **跳過自己這一組**
  sub_17208(al)                    ; ds:46B7h ← 那一組的槽表
  al ← [ds:46B7h + 0x0A]           ; 那一組在哪張地圖
  cmp al, ds:4655h ; jnz 下一組     ; 不同地圖就不算
  bl ← 7
loc_1A48F:
  al ← [記錄 + bl]；＝ 0FFh → 下一組  ; 座標清單，0xFF 結束
  x ← al；y ← [記錄 + bl + 1]
  [ds:46B7h + 8] ＝ x 且 [+9] ＝ y → bl ← 3，跳出
  bl += 2，回 loc_1A48F
loc_1A4CF:
  al ← ds:CF30h − 1；jns loc_1A473  ; 下一組
  bl ← 5                            ; 都沒命中
loc_1A4D8:
  記錄 +0x01/+0x02 ← [bl], [bl+1]
  sub_17208(ds:4654h)               ; **選回目前這一組**
```

`sub_17208(n)`：`ds:46B7h ← 0x7131 ＋ ds:B239h[n]`——那張表把組編號換成
槽表在角色記錄區裡的位移。`+0x08`／`+0x09`／`+0x0A` 是那一組的 X／Y／地圖
（`docs/re/60` §3）。

推論等級：**已確認**。

⚠ **「跳過自己這一組」那一行不能省。** 觸發腳本的就是站在那一格上的隊伍，
少了它會永遠走命中那一條，而症狀是「這個條件恆真」——看起來像資料的問題。

## 2. opcode 1 —— 第一個隊員站著嗎（`0x1A4F4`）

```
al ← 1；sub_172BB                  ; 選第 1 個角色，CF ＝ 1 ⇔ CON ≤ 0
bl ← 3；jnb 用 3；否則 bl ← 5
記錄 +0x01/+0x02 ← [bl], [bl+1]
```

`sub_172BB` ＝ `sub_19614`（選角色）＋ `loc_172BE`（倒下判定，`docs/re/99` §3）。
索引是 **1 起算**，所以那是隊伍的第一個人。

推論等級：**已確認**。

## 3. opcode 14 —— 自毀倒數的顯示（`0x1A7E8`）

它是 opcode 35（啟動倒數，`docs/re/100`）的另一半：**把還剩多久印出來**。

```
32-bit：經過 ← ds:4650h.. − ds:722Bh..
剩餘 ← 0xF0 − 經過                  ; 0xF0 ＝ 240 刻 ＝ SelfDestructTicks
ds:CF29h ← ds:CF4Ah[剩餘 & 3]       ; 表 ＝ 00 0F 1E 2D ＝ 0／15／30／45
剩餘 >>= 2                          ; → 秒
印字串 0x11
sub_18320(剩餘, bl ＝ 0x3C)          ; 除以 60 → 商 ＝ 分、餘 ＝ 秒
印 商 ':' 餘（補 0 兩位）'.' ds:CF29h
印字串 0x12
stc                                 ; ← **印完停住**
```

所以畫面上是 `mm:ss.ff`，滿刻數 240 顯示成 `1:00.00`——**倒數是一分鐘**。

推論等級：**已確認**（兩張表都從映像讀出，除法常數 `0x3C` 直接在指令裡）。

## 4. opcode 4 與 39 —— 寄放一個角色，過一段時間再領回

### 4.1 opcode 4（`0x1A54B`）：寄放

```
sub_19614(1)                        ; 第一個隊員
n ← 記錄 +0x03
ds:4661h ← 0x65C ＋ n×256           ; 目的地
逐 byte 抄 256 bytes（來源 ds:46B5h → 目的 ds:4661h）
[目的 +0xBD … +0xF8] ← 0            ; **物品陣列**（30 × 2，`docs/re/15`）
[目的 +0x1F] ← 0                    ; 裝備武器的槽
[目的 +0x1A] ← 0                    ; AC
[目的 +0x25] ← 0                    ; 裝備護甲的槽
[目的 +0x15/+0x16/+0x17] ← 0        ; 金錢（24-bit）
ds:0A5Ch ＋ n×4 ← 目前時間（32-bit）
```

⚠ **清除全部發生在副本上。** 寫入目標是 `ds:4661h` 不是 `ds:46B5h`——
原本那個隊員一個欄位都不動。讀反的話會變成「寄放會把身上的東西弄不見」。

⚠ **技能陣列（`+0x80`–`+0xBC`）不在清除範圍裡**，只有物品被清掉。

推論等級：**已確認**。

### 4.2 opcode 39（`0x1AC03`）：領回

```
n ← 記錄 +0x03
32-bit：經過 ← 目前時間 − ds:0A5Ch[n]
經過 < 0x2D00 → bl ← 6                          ; 時候未到
ds:4656h（人數）≥ 7 → bl ← 8                     ; 隊伍滿了
否則：
  ds:4661h ← 0x65C ＋ n×256
  loc_19624(人數 + 1)                            ; 下一個空的角色槽
  逐 byte 抄 256 bytes（副本 → 新槽）
  ds:4656h++；ds:4653h++
  [ds:46B7h + ds:4653h] ← ds:4656h               ; 寫進槽表
  …一段文字輸入迴圈（13 個字寫回記錄 +0x00）…
  bl ← 4
記錄 +0x01/+0x02 ← [bl], [bl+1]
```

⚠ **三個分支的目標不是常見的 `+0x03`／`+0x05`**，是 `+0x04`／`+0x06`／`+0x08`。
照別的 opcode 的習慣抄會走到錯的下一步。

推論等級：**已確認**（分支常數與 32-bit 借位比較逐指令讀過）。

## 9. 這一輪學到的（寫成規則）

- **「0 格」是「只能自己造記錄」，不是「不用做」。** 走不到的路徑照樣是
  直譯器的一部分；驗它的方法是**造輸入**，而造出來的輸入是測試的一部分，
  期望值必須來自組語不是實作。
- **同一段程式碼複製四份時，差別在常數。** op 8／9／34／37 是同一段的四份，
  差的只有「寫第幾筆」與「第二個參數是 `+0x04` 還是常數 0」。
  **逐支比對常數**，不要看到形狀一樣就共用一份實作。
- **分支目標不一定是 `+0x03`／`+0x05`。** op 39 用的是 `+0x04`／`+0x06`／`+0x08`。
  照習慣抄會走到錯的下一步，而那一步仍然是一個合法的記錄——不會崩，只會錯。
- **讀「抄一份再清掉某些欄位」時，先確認清的是哪一份。** op 4 清的是副本；
  來源與目的都在暫存器裡，看漏一個 `mov di, …` 就會把語意讀成相反的。
