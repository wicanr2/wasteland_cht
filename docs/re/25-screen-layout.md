## 1. 座標系統

畫面是 EGA mode 0Dh，**320 × 200、一列 40 bytes、四個平面**（`docs/re/04` §4）。
繪圖層用兩套單位，混用是讀錯位址的主因：

| 變數 | 單位 | 說明 |
|---|---|---|
| `ds:4674h`／`ds:4675h` | **byte 欄**（8 像素） | 矩形的左／右邊界 |
| `ds:4676h`／`ds:4677h` | **像素列** | 矩形的上／下邊界 |
| `ds:4672h` | byte 欄 | 文字游標的欄（清除矩形後 ＝ 左邊界） |
| `ds:4673h` | **字元列**（8 像素） | 文字游標的列（清除矩形後 ＝ 上邊界 ÷ 8） |
| `ds:8DD0h`／`ds:8DD1h` | 字元欄／字元列 | 畫字元用的游標（overlay slot 19） |
| `ds:4685h`／`ds:4686h` | byte 欄／像素列 | 畫一格地圖用（overlay slot 3／4） |

`sub_10762`（slot 9，清除矩形）同時證明了兩件事：`4676h`／`4677h` 是像素列
（拿去查 `ds:8DF9h` 的列位址表、逐列 `inc` 直到等於下界），而 `4673h` 是字元列
（`4676h` 右移三位才存進去）。

列位址表 `ds:8DF9h`：200 個 word，值 0、40、80…（slot 0 建表，另複製一份到
`seg003:0xDFE0`）。**畫面上任何位置的位址 ＝ 表[像素列] ＋ byte 欄。**

## 2. 五個視窗

```
        欄0                                   欄37 欄39
  列0   ┌──────────────────────────────────────┐        ← 外框（彩色字型的框線字元）
  列8   │ 地圖／圖片／隊伍名單                 │
        │            288 × 128                 │
  列135 │                                      │
  列136 └──────────────────────────────────────┘        ← 外框下緣（字元列 17）
  列144   訊息視窗：欄 1–38、字元列 18–23（6 行）
  列199
```

### 2.1 地圖視窗：19 × 9 格，288 × 128 像素，位置 (8, 8)

三處獨立證據：

| 來源 | 證據 |
|---|---|
| `sub_16619`（畫一整欄） | `mov al, 9` → **9 格高** |
| `sub_16646`（畫一整列） | `mov al, ds:46A3h` ＝ `0x13` → **19 格寬** |
| `sub_169CF`（在不在視窗內） | `(x − ds:464Eh) < 19` 且 `(y − ds:464Fh) < 9` |

`sub_16675` 重畫整個視窗時，`ds:0AA40h` 從 0 每次 ＋2 掃到 `19 × 2 ＝ 38`，
也就是 byte 欄 0、2、…、36。

**四邊各裁掉半格**：slot 3／4 對 `ds:4685h == 0`／`== 0x24`（第 19 欄）與
`ds:4686h == 0`／`== 0x80`（第 9 列）各有一條半格路徑。所以實際可見範圍是

```
橫：8 ＋ 17 × 16 ＋ 8 ＝ 288 像素（x ＝ 8…295）
縱：8 ＋  7 × 16 ＋ 8 ＝ 128 像素（y ＝ 8…135）
```

隊伍固定在視窗的第 (9, 4) 格：`sub_16149` 把原點算成
`ds:464Eh ＝ 隊伍 X − ds:46A8h`、`ds:464Fh ＝ 隊伍 Y − ds:46A9h`，
而 `sub_18350` 把這兩個常數設成 **9** 與 **4** ——正好是 19 與 9 的中央。

### 2.2 圖片視窗：同一個矩形

overlay slot 23（`sub_10F12`）把 `seg003:0x920` 的 **`0x24` bytes × `0x80` 列**
搬到螢幕位移 **`0x141`**：

```
0x141 ÷ 40 ＝ 列 8 …… 餘 1 ＝ byte 欄 1
0x24 ＝ 36 bytes ＝ 288 像素，0x80 ＝ 128 列
```

**與地圖視窗是同一個 288 × 128 @ (8, 8)。** `TITLE.PIC` 的尺寸（`docs/re/23`）
也正好是這個大小——標題、圖片、地圖共用同一塊畫面。

### 2.3 外框

`sub_197BB` 用彩色字型的框線字元（`0x0D`／`0x0E`／`0x0F`／`0x12`／`0x5E`／`0x5F`）
畫框，右下角傳 `dl ＝ 0x25`（欄 37）、`bl ＝ 0x11`（字元列 17）。

```
上緣 字元列 0  ＝ 像素 0–7      ← 地圖從 8 開始
下緣 字元列 17 ＝ 像素 136–143  ← 地圖到 135 結束
左緣 欄 0      ＝ 像素 0–7
右緣 欄 37     ＝ 像素 296–303  ← 地圖到 295 結束
```

框內側正好貼齊 §2.1 算出來的 288 × 128。

### 2.4 訊息視窗

`sub_17923`／`sub_17A6B` 設定：

```
ds:4674h ＝ 1     ds:4675h ＝ 0x26 (38)    欄 1–38  ＝ 像素 8–311
ds:4676h ＝ 0x90  ds:4677h ＝ 0xC0         像素列 144–192 ＝ 字元列 18–23
```

**6 行 × 38 欄**（8 × 8 字元）。`ds:4675h ＝ 0x26` 這個值在
`sub_17033`、`sub_17A6B`、`sub_1B875` 也各出現一次，是訊息區的固定行寬。

### 2.5 隊伍名單：把地圖視窗換掉

`ds:46B9h` 是**畫面模式旗標**：

| 值 | 畫面 | 誰設的 |
|---:|---|---|
| 0 | 地圖 | `sub_16675`（重畫整個地圖視窗時） |
| 1 | 隊伍名單 | `sub_1728C`、`sub_161C0` |

`sub_16C6F` 是切換鍵的處理：目前是名單就重畫地圖（`sub_163C4`），
目前是地圖就切成名單（`sub_1728C` → `sub_16F70`）。

名單畫在原本地圖視窗的位置：表頭在字元列 `0x0E`（14），
每個成員一行，列 ＝ 成員序號 ＋ `0x0F`（`sub_17033`），欄 1–38。
一行的欄位座標（NAME／AC／AMM／MAX／CON／WEAPON）見 `docs/re/15` §4。

同一支 `ds:46B9h` 也擋住地圖繪製：`sub_17FEE` 在旗標非 0 時，
只讓像素列 < 13 的格子通過，等於名單畫面下不再畫地圖格。

## 3. 中文化的直接影響

| 區域 | 原版容量 | 換成 16 × 15 點陣中文 |
|---|---|---|
| 訊息視窗 | 6 行 × 38 個 8×8 字元 | 每行 19 個全形字，**行高 15 > 8**，6 行放不下 |
| 隊伍名單 | 每行 38 欄，欄位在 `0x11`／`0x15`／`0x18`／`0x1C`／`0x20` | 欄位座標要重排 |
| 地圖視窗 | 288 × 128 固定 | 不受影響（圖磚不含文字） |

原版的文字控制碼（`docs/re/14` §4.1）有相對定位與清行，重排時要一起改。
**畫布尺寸與排版格的決策要等這一份與控制碼一起看**，不要只改字型。

## 6. 這一輪學到的（寫成規則）

- **同一組變數用兩種單位時，去找「換算的那一行」。** `ds:4676h` 是像素列、
  `ds:4673h` 是字元列，證據是 `sub_10762` 結尾的三個 `shr al, 1`——
  與其猜單位，不如找出把 A 寫成 B 的那一句。
- **視窗尺寸不要從清除矩形推。** 清除的範圍與實際繪製的範圍可以不一樣
  （§5 第三項就是一例）。尺寸要從**繪製迴圈的計數**與**邊界檢查**取，
  這兩個才是遊戲真正用的數字。
- **半格裁切會讓「格數 × 格寬」對不上視窗寬度。** 19 × 16 ＝ 304 ≠ 288；
  差的 16 像素是首尾各半格。看到差一格就先找繪製函式裡的邊界特例。
