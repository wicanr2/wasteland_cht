## 3. 賣（`sub_1BF5F`）

```
loc_1963F → dl ＝ 身上「賣得掉」的物品數（過濾版的計數，docs/re/41 §2.1）
dl ＝ 0 → 印字串 5「You don't have anything they want!」，回主迴圈
印字串 7 當表頭
迴圈：
    ds:469Dh ← 數量＋1；ds:469Ch ← 0x1F；ds:470Eh ← 'P'
    ds:4696h ← 0xC01B              ; ← 每一列的繪製回呼（§3.1）
    sub_16DB4 畫清單 → sub_16D34 等選擇
    0xFF → 結束；0xFE → 換人；負值 → 重畫
    選到第 n 件：
        bl ← n × 2 + 0xBB          ; 物品陣列的位移（docs/re/15）
        取出那件物品，**把那兩個 byte 清成 0**（從身上移除）
        sub_17AE0 定址物品表 → sub_1C1C2 算價 → sub_19895 加錢
        物品表 +0x02 ＝ 0xFF 就不動，否則 **+1**
        重新數，只剩 1 件就結束
```

### 3.1 每一列怎麼畫（`0x1C01B`）

```
ds:0DBF3h ← 槽編號
bl ← 槽 × 2 + 0xBB；al ← [角色記錄 + bl]
al ＝ 0 → stc（這一列跳過）
sub_17AE0 ＋ sub_17AF5 過濾不掉 → stc（賣不掉的不列）
sub_16EE8 ／ ds:467Fh ← 5 ／ sub_1C1C2 算價 ／ sub_17690 ／ sub_17852 印出來
⚠ 槽編號等於記錄 +0x25 或 +0x1F（**裝備中的**）→ sub_19E2A 標記那一列
clc
```

所以清單會**把裝備中的東西標出來**，但不會擋著不讓賣。

## 4. `+0x02` 是庫存量，不是旗標

`0x1BFE7` 賣東西時對物品表 `+0x02` 做 `add al, 1` 並寫回，
而 `0xFF` 那一格跳過不動。配上 `sub_1C140` 的「`+0x02` 為 0 就不列出」
（`docs/re/22` §2）與字串 `exe:7:1`「We are temporarily out of stock.」：

> **物品表 `+0x02` 是這家店的庫存量**：0 ＝ 缺貨（不列出）、
> `0xFF` ＝ 無限（賣給它也不會增加）、其餘是實際數量，賣一件就 +1。

`docs/re/22` §2 原本記的「非 0 才會出現在商店列表」是同一件事的表現，
不是另一個欄位語意。

推論等級：**已確認**（寫入點、0xFF 例外、列出條件與缺貨字串四方吻合）。

## 5. 醫生的逐點治療（`0x1C375` 起的迴圈）

```
al:dl ← MAXCON − CON            ; 16-bit：[+0x1B] − [+0x1D]，[+0x1C] sbb [+0x1E]
sub_176D0 印那個數字
印字串 16「 points. You can:  Heal 1 point / Continue」
sub_1C22F 印餘額
等按鍵：
    ESC 或 'C' → 結束
    'P' → 換下一個人
    'H' → 治一點：
        sub_1C548(bl ＝ 4)      ; 扣「每點價格」＝ 地圖記錄 +0x04（docs/re/35 §4.1）
        sub_17B15 錢不夠 → 跳出去（字串 18「You don't have enough money.」）
        sub_19CFE                ; CON +1
        sub_172AE 判斷之後可能再 sub_19CFE 一次
        sub_17033 重畫那一列
        回到迴圈開頭重算 MAXCON − CON
```

⚠ **一次按鍵只治一點、只扣一次錢**，而且**每一輪都重新算差額**——
所以錢不夠時停在中途是正常結果，不是錯誤分支。

## 9. 這一輪學到的（寫成規則）

- **「旗標」與「計數」長得一樣，差別在有沒有人加它。** `+0x02` 只看讀取端
  （「非 0 才列出」）會以為是旗標；找到 `add al, 1` 的寫入端才知道是庫存量。
  **要判斷一個欄位是不是旗標，先找它的加減法。**
- **`0xFF` 被跳過通常代表「無限／不適用」**，不是邊界保護。這裡賣東西給
  庫存 `0xFF` 的店不會讓它變 0x00，就是為了讓「無限供貨」成立。
- **逐點付費的迴圈要每一輪重算差額。** 原版把「還差幾點」放在迴圈開頭算，
  所以中途沒錢就停在那裡——把差額算在迴圈外會變成「錢不夠就一點都不治」。
