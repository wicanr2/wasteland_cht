## 1. 結論

`0x0A`／`0x0C`／`0x0E` 是**同一種東西的三個實例**：把一段文字切成幾段，
依一個選擇子只輸出其中一段。`0x0F` 則是插入一個數字。

| 碼 | 段數 | 選擇子 | 來源 | 例子 |
|---:|---:|---|---|---|
| `0x0A` | 2 | `ds:4687h` ＝ 1 → 第 0 段 | 數量（1 ＝ 單數） | `hammer\ns\n\n` → `hammers`／`hammer` |
| `0x0C` | 2 | `ds:470Bh` ＝ 0 → 第 0 段 | 角色記錄 `+0x18`（性別） | `\x0chis\x0cher\x0c` |
| `0x0E` | 3 | `ds:471Ah` ＝ 0／1／2 | 目標的類別（`sub_12A4C` 查表） | `\x0ehim\x0eher\x0eit\x0e` |
| `0x0F` | — | — | 印出 `ds:4687h` 的十進位值 | `hits \x0f ` → `hits 3 ` |

所以一句戰鬥訊息長這樣：

```
 sending \n\x0ehim\x0eher\x0eit\x0e\n\x0f of them\n to meet \n\x0ehis\x0eher\x0eits\x0e\ntheir\n maker
```

單數時 → `sending him to meet his maker`；
複數時 → `sending 3 of them to meet their maker`。

## 2. 過濾器的形狀（三支長得一樣）

以 `0x0A` 為例（`sub_1A00A`）。跳表那一格（`0x1A004`）先把模式旗標
`ds:4702h` 設成 1，之後**每一個字元**都會經過這支過濾器，回傳 `al = 0` 表示吃掉：

```
0x1A00A  mov  dl, ds:0CDCBh      ; 目前在第幾段
0x1A00E  test dl, dl / jnz 1A028
         ; ── 第 0 段 ──
0x1A012  cmp  al, 0Ah / jz 1A022 ;   遇到分隔碼 → 進下一段
0x1A016  mov  dl, ds:4687h
0x1A01A  cmp  dl, 1 / jz 1A021   ;   選擇子 ＝ 1 → 原樣輸出
0x1A01F  mov  al, 0              ;   否則吃掉
         ; ── 第 1 段（1A028）──
0x1A028  cmp  al, 0Ah / jz 1A036 ;   再遇到分隔碼 → 結束
0x1A02C  mov  dl, ds:4687h
0x1A030  cmp  dl, 1 / jz 1A01F   ;   選擇子 ＝ 1 → 吃掉（這一段是複數）
0x1A036  mov  al, 0              ; 結束：清模式旗標與段計數
0x1A038  mov  ds:4702h, al
0x1A03B  mov  ds:0CDCBh, al
```

`0x0C`（`sub_1A045`，段計數 `ds:0CDCAh`）與 `0x0E`（`sub_1A07E`，段計數
`ds:0CDC9h`）是同一個骨架，差別只有段數與選擇子：

```
0x0E 第 0 段：cmp ds:471Ah, 0 → 輸出
     第 1 段：dec dl / jnz 吃掉      （＝ 1 才輸出）
     第 2 段：cmp dl, 2 / jnz 吃掉
```

**一段文字要用幾個分隔碼**：段數 ＋ 1（最後一個是結束）。
`hammer\ns\n\n` ＝ 字根 `hammer` ＋ 第 0 段 `s` ＋ 第 1 段（空）＋ 結束。

## 3. 選擇子從哪來

| 選擇子 | 寫入點 | 語意 |
|---|---|---|
| `ds:4687h` | `sub_15A84`：`bl ＝ 2`，若 `dl == 0 && al == 1` 則 `bl ＝ 1` | **數量**：1 ＝ 單數、≥2 ＝ 複數。其他呼叫端（`0x17181`、`0x1BA72` 等）寫入實際數目 |
| `ds:470Bh` | `sub_19614` 尾段：角色記錄 `+0x18` | **性別**（0 ＝ Male、1 ＝ Female，`docs/re/15`） |
| `ds:471Ah` | `sub_12A4C`：查 `ds:0A920h` 那張表，索引來自敵人資料 | **目標類別**（0／1／2 → him／her／it） |

`0x0F` 走 `0x1A275`：取 `ds:4687h`（為 0 時當 1）交給 `sub_176A2` →
`sub_176A8` → `sub_18DCE` 轉十進位印出。**與 `0x0A` 共用同一個選擇子**，
所以「單複數」與「印出幾個」在原版是同一件事的兩面。

## 4. 這對中文化的意義

中文沒有單複數變化、也不區分 he／she 的字形，但**這套機制不能直接拆掉**：

- `0x0F` 要保留（「3 個」的數字還是要印）
- `0x0A`／`0x0E`／`0x0C` 的分段在中文常常變成「同一段」——
  例如 `him／her／it` 三段中文都是「他」，但**翻譯資料仍要保留三段**，
  否則遇到原版用它來切「他的／她的／它的」以外的用法時會少字
- 段數與分隔碼的數量要與原版一致，**否則整句會錯位**（過濾器是逐字元跑的）

建議翻譯格式保留原本的分隔碼，中文各段可以相同：

```
原版： sending \n\x0ehim\x0eher\x0eit\x0e\n\x0f of them\n to meet …
中文： 把\n\x0e他\x0e她\x0e它\x0e\n\x0f 個\n 送去見…
```

## 5. 順帶：`0x07` 與剩下的 `0x08`

- **`0x07`**（`0x19727`）：設定文字視窗（欄 `0x0E`–`0x27`、下界 `0x70`）並用彩色
  字型的框線字元畫框，游標移到 (0x0E, 0)。語料裡 59 次，多半在
  `'\x07Welcome to the Quartz Emporium.'` 這種開場白前面——**開一個新的文字框**。
  推論等級：**強證據**（程式碼讀完，但還沒與畫面對拍）。
- **`0x08`**（`0x19F12`）：**沖出目前這一行但不捲動**。整支讀完在
  [`docs/re/58`](58-line-flush-and-scrollback.md)：斷字 → 送畫面 → 寫 scrollback →
  把斷字點之後的搬回行首。與 `0x0D` 的差別是**不經過 `sub_19EFC`**，
  所以不捲動、不延遲、也不看批次旗標。
  語料裡 7 次當中**真正的用例只有 3 條**，另外 3 次在字母表本身、
  1 次在未用槽的解碼雜訊裡。推論等級：**強證據**。

## 7. 這一輪學到的（寫成規則）

- **「未解」的清單要定期回頭對照別的文件。** `0x0A` 在 `docs/re/14` 的控制碼表裡
  掛著「未解」，但 `docs/re/17` §4.1 早就從字串形狀認出它是單複數分隔——
  **同一個 byte，兩份文件兩種狀態**。這次是把兩邊接起來才發現三個碼是同一套機制。
- **形狀一樣的三支函式，解一支就解三支。** `sub_1A00A`／`sub_1A045`／`sub_1A07E`
  的骨架完全相同，差別只有段數與選擇子；先認出骨架，剩下的只要找選擇子的寫入點。
- **逐字元過濾器要配「模式旗標」一起看。** 單看 `sub_1A00A` 會以為它對所有文字
  都生效（那說不通）；跳表那一格先設 `ds:4702h ＝ 1`，過濾器只在旗標開著時被叫。
