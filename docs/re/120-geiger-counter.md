# 120：蓋氏計數器是輻射計量表 ＋ 逼近時的滴答聲

`docs/re/48` §2.1（nibble 9 ＝ 輻射區）

## 1. 誰在讀物品 48

全檔只有一處：`sub_17E42` 的 `0x17E5B`。

```
0x17E42  cmp  byte ptr ds:8DD9h, 0     ; 非 0 ＝ 局部重畫，直接跳過清旗標
0x17E47  jnz  0x17E4E
0x17E49  ds:4707h ← 0
0x17E4E  ds:BA07h ← 7Eh                ; 字模編號：預設「有計數器」那一組
0x17E53  ds:BA06h ← 1                  ; 隊員編號，從 1 起
0x17E58  call sub_19614                ; 依編號設 ds:46B5h（角色記錄位址）
0x17E5B  al ← 30h                      ; **物品 48 ＝ Geiger counter**
0x17E5D  call sub_1968C                ; 找這個人身上有沒有這件物品
0x17E60  jnb  0x17E7A                  ; CF ＝ 0（找到）→ 保持 7Eh，跳出迴圈
0x17E62  隊員編號 ＋1；< ds:4653h 就回 0x17E55
0x17E70  ds:46EEh ← 0FFh               ; **全隊都沒有 → 讀數作廢**
0x17E75  ds:BA07h ← 7Ah                ; 換成「沒有計數器」那一組字模
```

`sub_1968C(al ＝ 物品編號)` 是既有的物品搜尋（`docs/re/32` §6）：掃角色記錄
`+0xBD` 起、每 2 bytes 一筆到 `+0xF9`，找到 `CF ＝ 0` 並回傳位移，
找不到 `CF ＝ 1`、`bl ＝ 0FFh`。

⚠ 這裡的迴圈出口是 `jnb`，也就是**找到就跳出**——只要隊上有一個人帶著就算數，
不必是特定的人。攻略寫「Christina 身上的蓋氏計數器」，機制上與誰帶著無關。

正對照（`tools/scan_item_refs.py`，兩個表的走法檢查都是 0 例外）：
物品 48 在**寶箱 0 次、腳本攜帶檢查 0 次**——它只在商店買得到
（`docs/re/118` 的第 4 組庫存有一支，300 元）。全檔的立即數 `30h` 有 10 處，
逐處看過，其餘九處是 ASCII `'0'`、記錄位移 `+0x30` 與螢幕欄號，都不是物品編號。

## 2. 讀數 `ds:46EEh` ＝ 視野內最近的輻射格有多遠

寫入端在畫格子那一支 `sub_18024`（`docs/re/48` §2.1）：

```
0x1803C  call sub_17C20               ; 這一格第 1 層的 nibble
0x18047  cmp  al, 9                   ; **9 ＝ 輻射區**
0x18049  jnz  0x18088
0x1804B  call sub_180CF；sub_180DE     ; 疊圖
0x18051  call sub_19D4D               ; 距離 ＝ ds:CD0Dh[10·|Δy| ＋ |Δx|]
0x18054  cmp  al, ds:46EEh
0x18058  jnb  0x1805D
0x1805A  ds:46EEh ← al                ; **逐格取最小**
```

視窗重畫那一支 `sub_167CE`（`docs/re/26` §5）在開頭把它設回 `0FFh`，
所以每次重畫都是重算一次「視野內最近的輻射格離隊伍多遠」。
`sub_19D4D` 查的是既有的距離表 `ds:CD0Dh`（10 × 歐氏距離，`docs/re/37` §4，
remake 這一側是 `game.Distance`）。

`0FFh` 是保留值 ＝ **沒有讀數**：視野裡沒有輻射格會留著它，
全隊沒帶計數器則由 §1 直接蓋成它。兩個消費端都拿 `0FFh` 當「不要顯示／不要響」。

## 3. 提示一：畫面右緣的計量表

`sub_17E42` 接著用彩色字型（`sub_10039`，`docs/re/04` §5）在**字元欄 38–39**
畫一根直立的管子，游標列 `ds:8DD1h` 由下往上跑。外框只到欄 37
（`docs/re/25` §2.3），所以這一整條在框外。

| 字元列 | 內容 | 字模 |
|---:|---|---|
| 16、15 | 底座（機器本體） | 有計數器 `7E 7F` ／ `80 81`；沒有 `7A 7B` ／ `7C 7D` |
| 14–11 | 條，最多 4 格 | 列 > 12 用 `8A 8B`，列 ≤ 12 用 `86 87`（兩段不同色） |
| 同上 | 半格 | 列 > 12 用 `88 89`，列 ≤ 12 用 `84 85` |
| 剩下的到列 11 | 空管 | `82 83` |
| 10、9 | 頂蓋 | 條頂到頂時 `76 77` ／ `78 79`，否則 `72 73` ／ `74 75` |

長度的算法（`0x17EC3`）：

```
al ← ds:46EEh >> 3
al ≥ 9 → 整條空的                      ; 讀數 ≥ 72 或 0FFh
否則 n ← 9 − al；半格 ＝ n & 1；滿格數 ＝ n >> 1（0–4）
```

也就是**距離每 8 個表值退一階，共 9 階、畫成 4 格半**；越近條越長。

`ds:8DD9h` 非 0（局部重畫）時畫完條就 `retn`，不補空管也不畫頂蓋——
那一路是「只把變長的部分補上去」。

⚠ 字模編號是**彩色字型 `colorf.fnt` 的索引**，不是 ASCII。
`colorf.fnt` 有 172 個字模，`0x72`–`0x8B` 這 26 個就是這根管子的零件，
拿 `tools/dump_font.py colour` 印出來一眼可辨（`docs/re/14` §3）。

## 4. 提示二：滴答聲（攻略說的「叫了起來」）

主迴圈 `0x16B31` 每一輪都會看一次讀數：

```
0x16B49  dl ← ds:46EEh
0x16B4D  cmp dl, 0FFh
0x16B50  jz  0x16B85                  ; 沒有讀數 → 整段跳過
0x16B52  al ← ds:0AAE5h               ; 倒數還在跑就不重設
0x16B57  jnz 0x16B65
0x16B59  dl ＋1；al ← sub_18E41(dl)    ; **1dN**，N ＝ 距離 ＋ 1
0x16B60  al ＋3 → ds:0AAE5h            ; 倒數 ＝ 亂數 ＋ 3
0x16B65  bx ← ds:0D150h               ; BIOS 計時器
0x16B69  與 ds:0AAE1h 相同 → 跳過      ; **一個 tick 只減一次**
0x16B73  dec ds:0AAE5h
0x16B77  jnz 0x16B85
0x16B79  ax ← 2；call sub_1CBD3        ; **播音效 2**
```

音效 2 在 `docs/re/44` §6 的表裡是「短促、音高較高」的那一顆，
呼叫端只有這一處。間隔 ＝ `1d(距離＋1) ＋ 3` 個 BIOS tick（約 55 ms 一個），
所以**距離越近，取樣上界越小、平均間隔越短，滴答越密**；
沒帶計數器或視野裡沒有輻射格時一聲都不響。

remake 這一側是 `Scene.TickGeiger`，分頻交給呈現層（`internal/ui/ui.go`：
60 TPS ÷ 3 ＝ 20 Hz，整數分頻裡最接近 18.2 Hz 的一檔，與設施動畫同一個計數）。

推論等級：§1–§4 全部**已確認**（讀到程式碼並解釋得通）。
`0x16234` 在畫面初始化時把 `ds:46EEh` 設成 0（不是 `0FFh`）——**未解**，
它之後緊接著就會被視窗重畫那一支重算，實際影響看不出來。

## 5. 對攻略 M-09 的結論

> 蓋氏計數器在接近輻射區時會發出提示

**相符**，而且兩種提示都在：畫面右緣的計量表逐階變長，主迴圈的滴答聲逐漸變密。
機制上與「誰帶著」無關，也**不影響傷害**——擋輻射的是 `Rad suit`（`docs/re/55` §3）。

## 7. 這一輪學到的（寫成規則）

- **「某個道具有什麼用」要從「誰讀它的編號」問起，不是從它出現在哪個系統問起。**
  輻射這條路讀了兩次都沒有計數器的影子，因為它根本不在傷害結算裡；
  改成掃全檔的立即數 `30h`，第一輪就掃到了。
- **保留值要當成介面的一部分讀。** `ds:46EEh ＝ 0FFh` 同時表示「視野裡沒有輻射格」
  與「隊上沒有計數器」，兩個來源、一個語意，兩個消費端各自照它分支。
  只看寫入端會覺得那是兩件事。
- **字模編號不要當 ASCII 讀。** `7E 7F 80 81` 看起來像文字，其實是彩色字型裡
  一根管子的四塊零件。看到連號的字模編號先把字模印出來。
