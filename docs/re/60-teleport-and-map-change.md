# 60：傳送與換地圖（nibble 10）

日期：2026-08-15 ｜ 起因是 `docs/re/59` 的玩家路徑驗收：**玩家出不了起始地圖**

輸入：`wl.merged.exe`，SHA-256
`cd5b07eaa55f1e1578caa1b05f0bd5331355cd119f387e61b1a8906738e78118`。

`docs/re/26` §5 把 nibble 10 記成「讀隊伍槽表 `+0x0B`／`+0x0C` 並改寫隊伍座標」，
`docs/re/30` 把 `+0x0B`／`+0x0C` 記成「傳送目的地」。
兩處都不完整——**那組欄位是回程來源，而且傳送會換地圖**。

---

## 1. 為什麼要讀這一支

玩家路徑驗收發現：起始地圖（資源 0）**沒有任何設施格走得進去**，
23 筆設施記錄裡只有 2 筆被格子指到，44 個腳本 opcode 沒有一個開設施。
商店 `Q. Emporium` 在資源 1、`AG. store` 在資源 9——**都在別的地圖**。

資源 0 有 **28 格 nibble 10**，那就是城鎮入口。

## 2. `0x16A10` 全文

```
0x16A10  ds:AAD4h ≠ 0 → 直接 clc retn        ; 某個抑制旗標
0x16A1A  ds:AAD3h ＝ 0 → sub_16B17
0x16A24  ds:AAD3h ← 0；sub_169B1(4)

; ── 把「現在在哪」存進槽表當回程 ──
0x16A2E  bl ← 0Bh；di ← ds:46B7h（隊伍槽表）
0x16A34  ds:AAD1h ← 槽表[+0x0B]              ; 舊值先留著
0x16A39  槽表[+0x0B] ← ds:46A6h              ; ← 目前 x
0x16A40  ds:AAD0h ← 槽表[+0x0C]
0x16A45  槽表[+0x0C] ← ds:46A7h              ; ← 目前 y
0x16A4C  ds:AAD2h ← 槽表[+0x0D]
0x16A51  槽表[+0x0D] ← ds:4655h              ; ← **目前地圖編號**

; ── 決定要去哪 ──
0x16A56  al ← 地圖記錄 +0x03
0x16A5E  al ＝ 0FFh → 回程（loc_16A75）
0x16A62  記錄 +0x00 的 bit7 沒設 → loc_16A90（相對位移）
0x16A6A  bit7 設 → 基準 ＝ 目前座標

loc_16A75（回程）：
  dl ← ds:AAD1h、bl ← ds:AAD0h               ; 存起來的舊座標
  sub_17DE0；ds:464Eh ← dl；ds:464Fh ← bl
  al ← ds:AAD2h；sub_16AC7                   ; ← **換回舊地圖**
  clc; retn

loc_16A90（去程）：
  dl ← 記錄 +0x01 ＋ 基準 x
  bl ← 記錄 +0x02 ＋ 基準 y
  sub_17DE0；ds:464Eh ← dl；ds:464Fh ← bl
  ds:4655h ← 記錄 +0x03                      ; ← **目標地圖編號**
  sub_18350                                  ; 載入那張地圖
  loc_163CA；sub_15DAF
  stc; retn
```

## 3. 欄位

| 位置 | 意義 |
|---|---|
| 地圖記錄 `+0x00` bit7 | 1 ＝ `+0x01`／`+0x02` 是**相對目前座標**的位移；0 ＝ 相對原點 |
| 地圖記錄 `+0x01`／`+0x02` | 目標 x／y |
| 地圖記錄 `+0x03` | **目標地圖編號**；`0xFF` ＝ 回程 |
| 隊伍槽表 `+0x0B`／`+0x0C`／`+0x0D` | **回程**的 x／y／地圖編號 |

⚠ **`+0x0B`／`+0x0C` 不是「傳送目的地」。** 踩上傳送格的第一件事就是
把**目前**的座標與地圖寫進去，所以那是**回來的路**。
`docs/re/30` §3.1 原本記反了。

⚠ **`+0x0D` 之前沒有語意。** 隊伍槽表 14 bytes 的最後一個 byte
就是回程的地圖編號。

⚠ **去程 `stc`、回程 `clc`。** 去程回 CF ＝ 1 表示「這一步不要再往下做」
（地圖已經換掉，後面的捲動與遭遇掃描都不該跑）。

## 4. 對 remake 的意思

**這是「玩得通」的關鍵缺口**：沒有它，玩家永遠困在資源 0，
所有商店、醫生、訓練師（除了 `Chopper Sim.`）都到不了。

規格 07 §6 的 nibble 10 只寫「隊伍槽表 `+0x0B`／`+0x0C`」，
實作也只改座標——踩上去會傳到**同一張地圖**的別處。

## 5. 還沒讀的

- `ds:AAD4h`（抑制旗標）與 `ds:AAD3h`、`sub_16B17`。
- `sub_16AC7`（回程的換地圖）與 `sub_18350`（去程的載入）的差別；
  兩者都會換 `ds:4655h` 指的地圖，但走的路不同。
- `sub_17DE0`：座標寫進 `ds:464Eh`／`464Fh` 之前的那一步。

## 7. 這一輪學到的（寫成規則）

- **「玩不下去」會指到沒讀完的那一支。** 這一份的起點不是「該讀傳送了」，
  而是玩家路徑驗收發現商店進不去——**倒推回來才發現 nibble 10 只讀了一半**。
- **記成「目的地」的欄位，先看誰寫它。** `+0x0B`／`+0x0C` 在這一支裡
  **第一個動作就是被覆蓋成目前座標**。只看讀取點會把來源當成目的地。
- **一個結構的最後一個 byte 沒語意時，八成是被漏掉的。** 隊伍槽表 14 bytes
  裡 `+0x0D` 一直空著，而它就是回程那組的第三個欄位——
  **成對的欄位要一起找完**。
