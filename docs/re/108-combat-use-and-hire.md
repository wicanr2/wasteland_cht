## 1. `Use` 的指令參數 ＝ `(選項 << 4) | 方向`

下令階段 `0x1240B`（指令碼 7）：

```
0x1240B  ds:A426h ← al              ; 隊員編號
0x1240E  sub_13AE4                  ; 挑要用什麼（docs/re/92 §2）
           → al ＝ 選項（0 Skill／1 Item／2 Attribute）
           → bl ＝ 技能／物品／屬性的編號
           → dl ＝ **方向**（§2）
0x12411  jb → 取消
0x12413  ds:A425h ← dl
0x12417  sub_12738                  ; al <<= 4        ← 選項移到**高** 4 位
0x1241A  al |= ds:A425h             ; 方向填**低** 4 位
0x1241E  push ax                    ; ← 這就是回傳值 ＝ 指令參數
0x1241F  dl ← bl                    ; 編號
0x12427  di ← ds:46B7h；al ← [bx+di] ; 隊伍槽 → **角色編號**
0x12431  [bx − 5603h] ← al          ; ds:A9FDh[角色編號] ← 編號
0x12438  pop ax；clc；retn
```

結算階段 `0x13265`（`docs/re/107` §4）把它拆回來：

```
0x1328F  al ← [ds:46DAh + 成員]
0x13292  dl ← al & 0x0F             ; 低 4 位 ＝ 方向
0x13297  sub_17C69                  ; al >>= 4        ← 高 4 位 ＝ 選項
0x1329A  bl ← ds:A557h              ; ＝ ds:A9FDh[角色編號] ＝ 編號
0x1329E  sub_13C58(al, dl, bl)      ; 施用（docs/re/92 §4 已解）
```

兩支一行的輔助函式：**`sub_12738` ＝ `al << 4`**（`0x12738`–`0x12742`，
末尾 `test al, al` 只是順手設旗標）、**`sub_17C69` ＝ `al >> 4`**
（`0x17C69`–`0x17C71`，四個 `shr`）。

> ⚠ **`ds:A9FDh` 沒有欄位配置**（`docs/re/41` §7 掛著的問題）：
> 整個 byte 就是編號，寫進去與讀出來都不做位元運算。
> 分成兩半的是**指令參數 `ds:46DAh`**，不是這一格。
> 兩個 byte 一個存編號、一個存「選項 ＋ 方向」，是因為
> `ds:46DAh` 只有一個 byte 而要塞的東西有三樣。

推論等級：**已確認**（寫入端與讀取端逐指令對上）。

## 2. 方向是九向裡的一格，而且方向鍵與 `IJKL` 折在一起

`sub_13AE4` 收尾（`0x13C45`）回三個值，其中 `dl ← ds:A5E2h`，
來源是 `sub_125BD`：

```
0x125CF  ds:4674h ← 0x0F                ; 文字區左邊界 15（戰鬥面板）
0x125D8  ds:4680h ← 0xA469；sub_17868   ; 印 `Which way?`
0x125E4  ds:4680h ← 0xA45C              ; ↓ 那張字母表
0x125F6  sub_173B0 → al                 ; 等按鍵，回字母表索引
0x12606  al 為負 → stc（取消）
0x1260A  al ≤ 4 → 直接用
0x1260E  al > 4 → al −= 5               ; ← **方向鍵折進字母鍵那五格**
```

```
ds:A469h  "Which way?\r\r  "
ds:A45Ch  49 4B 4A 4C 20 | C8 D0 CB CD | 00
          I  K  J  L  ␣  | ↑  ↓  ←  →  |
```

前五格是 `I K J L` 與空白，後四格是方向鍵的擴充掃描碼。
`al −= 5` 把 `↑↓←→` 對到 `IKJL`——**兩套鍵是同一件事**，
不是八個方向。

`sub_164E0(al)` 拿它走一步：

```
0x164E0  dl ← ds:464Eh；bl ← ds:464Fh   ; 視窗原點
0x164F1  al <<= 1；ax ← [bx − 554Fh]    ; ← ds:AAB1h[al]，九筆的位移跳表
0x164F9  ds:4661h ← ax；sub_19EB4       ; 間接呼叫
0x16503  jmp sub_18016
```

`ds:AAB1h`（`--code` 倒出來，每一格是「(dl, bl) ＝ (x, y) 的增量」）：

| 索引 | 位址 | 指令 | 增量 |
|---:|---|---|---|
| 0 | `0x16508` | `dec bl` | (0, −1) 上 |
| 1 | `0x1650D` | `inc bl` | (0, +1) 下 |
| 2 | `0x16512` | `dec dl` | (−1, 0) 左 |
| 3 | `0x16517` | `inc dl` | (+1, 0) 右 |
| 4 | `0x18016` | — | 不動 |
| 5 | `0x16510` | `dec bl; dec dl` | (−1, −1) 左上 |
| 6 | `0x16506` | `inc dl; dec bl` | (+1, −1) 右上 |
| 7 | `0x1650B` | `dec dl; inc bl` | (−1, +1) 左下 |
| 8 | `0x16515` | `inc bl; inc dl` | (+1, +1) 右下 |

> **`docs/re/26` 的「斜走的四個入口誰在用」有答案了：它們是這張表的第 5–8 格，
> 四個對角增量。而它們選不到**——`ds:AAB1h` 全檔只有一個讀取點（`0x164F5`），
> `sub_164E0` 全檔只有一個呼叫端（`0x13C40`），而那條路的索引在
> `0x1260E` 就被折成 0–4。

全檔掃描佐證（把四個位址當成 16-bit little-endian 字面值掃整份映像）：
`0x650B`／`0x6510`／`0x6515` 各命中 **1 處**，分別是
`ds:AABFh`／`ds:AABBh`／`ds:AAC1h`——**就是這張表自己的第 7、5、8 格**；
`0x6506` 在資料段內也只有 `ds:AABDh` 一處（其餘命中落在資料段外，是巧合的位元組對）。

推論等級：**已確認**（表的內容、唯一消費端、以及折疊那三行都直讀；
「選不到」有全檔掃描佐證）。

## 3. `Hire` 挑的是遭遇佇列裡的一組

結算 `0x132AC`（`docs/re/107` §6）第一步是 `sub_13440`，它是三支的串接：

```
sub_13440:  sub_13449 → sub_13A56 → sub_157AD

sub_13449(bl ＝ 成員):  al ← [ds:46DAh + bl] & 0x3F     ; 參數的低 6 位
sub_13A56(al):          bl ← al mod 3                    ; **子組**（0–2）
                        dl ← (al div 3) & 3              ; **隊伍組**（0–3）
                        al ← (al div 3) >> 2
sub_157AD:              掃 ds:46C8h 的 10 個 16-bit 血量，
                        數出還活著幾個 → ds:A688h
```

`mod 3` ／ `div 3` 正是敵方記錄「3 組 × 10」的拆法（`docs/re/37` §2），
而 `& 3` 是遭遇佇列的「4 個隊伍組」（`docs/re/39` §4）。
所以 **`Hire` 的參數是「佇列裡的第幾組」**，與下令階段印字串 63
`Which group?` 對得起來（`docs/re/41` §3）。

`sub_1340C` 是同一條路少掉 `sub_157AD` 那一支，
`sub_1341C` ＝ 取記錄 `+0x14`。

推論等級：**強證據**（三支都逐指令讀完，拆法與兩份既有筆記的結構吻合；
`0x132BF` 之後那三支 `sub_1341C`／`sub_1340C`／`sub_13787` 怎麼把那一組
併進隊伍還沒讀）。

## 6. 這一輪學到的（寫成規則）

- **一個 byte 塞不下三樣東西時，找第二個 byte。** `Use` 要傳「選項、編號、方向」
  三樣，而指令參數只有一個 byte——原版把選項與方向壓成兩個 nibble，
  編號另外存在以**角色編號**為索引的一格。
  問「這個欄位的位元怎麼分」之前，先確認**要傳的東西有幾樣**。
- **「這幾格沒有人用」要掃全檔的字面值，不能只看 xref。** 跳表裡的位址是
  資料不是呼叫，xref 圖上什麼都看不到。把位址當成 16-bit 字面值掃整份映像，
  才數得出「只出現在這張表自己裡面」。
- **同一份筆記的「還沒解」清單會比正文舊。** `docs/re/92` §5 列著
  `sub_140DD`／`sub_14090`／`sub_14126` 未解，而同一份的 §6 把三支都解完了。
  **解完一項就回頭刪掉那一列**——留著會讓下一輪重讀一次。
