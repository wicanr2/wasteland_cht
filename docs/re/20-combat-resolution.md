## 1. 兩條路徑，一段共用的判定

戰鬥有兩條攻擊路徑，都在 IDA 未建成函式的區塊裡：

| 路徑 | 位址 | 基礎值 | 判定 |
|---|---|---|---|
| **隊伍攻擊敵方** | `0x1AF52`–`0x1AFF4` | 60／50（依 `[0x711D + 索引]` 是不是 `0xFF`） | `roll < 累加值` 才命中 |
| **敵方攻擊隊伍** | `0x1B04C`–`0x1B0D1` | 60／50／40（依 `[ds:46D8h + 目標]`） | `roll ≥ 累加值` 才命中 |

兩條都呼叫 `sub_1B108` 累加到 `ds:46C0h`，判定前綴的機器碼**一模一樣**，
只差最後一個 opcode：

```
隊伍→敵方  b0 64  e8 be de  3a 06 c0 46  f5  73 08     ; jnb
敵方→隊伍  b0 64  e8 b1 dd  3a 06 c0 46  f5  72 12     ; jb
```

這不是筆誤，是**同一個量在兩個方向的用法**——見 §2。

## 1.1 敵方攻擊隊伍（`0x1B04C`–`0x1B0D1`）

```
loc_1B04C:
  sub_19D0E                       ; 還有沒有可打的目標
  al = ds:4653h                   ; 隊伍人數
  sub_18E41                       ; ← roll(1..人數)：隨機挑一個目標
  ds:CF84h = al
  sub_172BB                       ; 這個目標能不能打；不能就重抽
  sub_19BF8                       ; 累加器 ds:46C0h ← 0
  bl = ds:CF84h
  al = [ds:46D8h + bl]            ; 目標的一個欄位
  al ＝ 5 → 0x3C(60) ／ ＝ 2 → 0x32(50) ／ 其餘 → 0x28(40)
  sub_1B108(al)                   ; ← 累加出「要擲贏的值」
  al = 100
  sub_18E41                       ; ← roll(1..100)
  cmp al, ds:46C0h
  cmc
  jb  loc_1B0A9                   ; 擲出值 ≥ 門檻 → 命中
  ; 未命中：印訊息 0x1F
loc_1B0A9:                        ; 命中
  印訊息 0x55
  sub_12A76                       ; ← 算傷害
  bl = ds:CF84h
  sub_157D6                       ; ← 套用傷害（護甲、扣 CON，docs/re/19 §4）
```

## 2. `ds:46C0h` 累加的是「隊伍成員的本事」

兩條路徑判定方向相反，一開始看起來像矛盾，其實是同一件事：

> **`sub_1B108` 累加的永遠是隊伍成員的能力值**（`ds:46B5h` 指到的那筆角色記錄），
> 而它對隊伍有利的方向，在攻擊時是「更容易打中」，在防守時是「更難被打中」。

| 路徑 | `ds:46B5h` 是誰 | 累加值的語意 | 判定 | 值越大 |
|---|---|---|---|---|
| 隊伍攻擊 | 攻擊者（隊伍成員） | **命中率** | `roll < 值` | 越容易命中 |
| 敵方攻擊 | 被攻擊者（隊伍成員） | **被命中門檻** | `roll ≥ 值` | 越難被命中 |

兩邊都是「隊伍成員的技能越高越好」，所以 `sub_1B108` 裡
「技能等級 × 3 是**加**進去的」在兩條路徑上都說得通。

方向逐條核對過，原始 bytes 也對過：

```
3a 06 c0 46    cmp  al, ds:46C0h   ; CF ＝ 1 當 al <  累加值
f5             cmc                 ; CF ＝ 1 當 al >= 累加值
72 ..          jb   …              ; 敵方攻擊：跳走 ＝ 命中（al >= 值）
73 ..          jnb  …              ; 隊伍攻擊：跳走 ＝ 命中（al <  值）
```

推論等級：**強證據**（兩條路徑的指令序列與原始 bytes 都對過；
「誰的技能」這一層是從 `ds:46B5h` 在各路徑的設定推的，還沒實機對拍）。

## 3. 累加值怎麼來：`sub_1B108`

累加器是 `ds:46C0h`（16-bit），加減都走 `sub_19C2C`（24 個呼叫端）——
一支**飽和加法**：`dl` 為負就減、借位夾在 0；為正就加、進位夾在 `0xFFFF`。

```
sub_1B108(al ＝ 基礎值):
  sub_19C2C                 ; 累加值 += 基礎值（依路徑是 40／50／60 或 50／60）
  sub_1B0F1                 ; ┐ al=1 **寫死** → sub_198CD 找 Brawling（技能 1）的等級
  sub_19C2C                 ; ┘ → sub_19CCC（×3）→ 累加值 += Brawling × 3
  loc_1570F                 ; ┐ bl=0x12 ＝ Agility（docs/re/21）
  sub_19C2C                 ; ┘ 累加值 += Agility
  al = ds:CF81h
  sub_13A56                 ; 全域組編號 → (a, b, 組)（docs/re/37 §5）
  sub_137F4 / sub_13787     ; 定址到那筆敵方記錄，並選中它所在的地圖記錄
  sub_1B15F                 ; ＝ 敵人資料表 +0x02（行動值欄位，docs/re/37 §3.1）
  push ax
  sub_12A8D                 ; ＝ 同一筆的 +0x05 & 0x0F（武器類別）
  if al == 1:  al <<= 2     ; 近戰類別 → **8-bit** ×4，高位丟掉
  else:        累加值 += 5
  al = −ax; dl = 0FFh
  sub_19C2C                 ; 累加值 −= 那個值
  ds:46BEh = 100
  sub_19C72                 ; 累加值 > 100 → 夾在 100
```

`sub_19CCC` 是乾淨的 ×3（`x + x×2`，含進位）：

```
0x19CCC  ds:0CD48h = al ; ds:0CD47h = al
0x19CD4  shl  byte ptr ds:0CD47h, 1 ; rcl al, 1    ; ×2，進位進高位
0x19CE0  adc  al, ds:0CD47h                        ; ＋原值 → ×3
```

**技能等級 ×3 永遠是加進累加值的**，而累加值對隊伍成員永遠是好事
（攻擊時＝命中率、防守時＝被命中門檻），所以兩條路徑不需要不同的公式，
只需要不同的比較方向。§2 那張表就是這件事。

## 4. 攻擊傷害：`sub_12A76`

```
0x12A76  e8c7ff    call sub_12A40        ; → ds:4665h ＝ **攻擊資料表**的一筆
                                         ;   （記錄區標頭 +0x04，8 bytes 一筆，docs/re/32 §8.1）
0x12A79  b303      mov  bl, 3
0x12A7B  8b3e6546  mov  di, ds:4665h
0x12A7F  8a01      mov  al, [bx+di]      ; +0x03 ＝ 骰子數 N
0x12A81  8ad0      mov  dl, al
0x12A83  b305      mov  bl, 5
0x12A85  8a01      mov  al, [bx+di]      ; +0x05
0x12A87  e8dfd1    call sub_17C69        ; al >>= 4（取高 nibble）
0x12A8A  e9f9d2    jmp  sub_19D86        ; ＝ 基礎 ＋ N 顆 d6
```

**傷害 ＝（資料 `+0x05` 的高 4 位）＋（資料 `+0x03`）顆 d6。**

`sub_19D86` 的介面是 `al ＝ 基底、dl ＝ 顆數`（`docs/re/13` §3.3），
這裡 `dl` 先被設成 `+0x03`，`al` 最後才被設成高 nibble，順序沒有搞反。

⚠ **這裡的「資料」是攻擊資料表，不是物品表。** `sub_12A40` 會把定址器的基址
換成記錄區標頭 `+0x04` 那張表（`docs/re/32` §1）。`sub_12A76` 的兩個呼叫端
（`0x1295D` 範圍傷害、`0x1B0BF` 敵方攻擊）都在敵方路徑上；
隊伍打敵方走的是另一條路（§4.1）。

推論等級：**已確認**（兩支函式讀完；`sub_19D86` 的語意已在 `docs/re/13` 驗過）。

### 4.1 隊伍打敵方：五項相加

命中之後（`0x1AF92`）把累加器 `ds:46C0h` 歸零，再用 `sub_19C2C`（16-bit 飽和加）
疊五個來源，結果直接當傷害交給 `sub_15A9D`：

| 呼叫 | 加的是什麼 |
|---|---|
| `sub_15755` | **武器的傷害骰**：`0 ＋（物品表 +0x06）顆 d6`；反戰車武器（類別 8／9）顆數加倍（[`45`](45-item-data-and-weapon-damage.md) §4） |
| `sub_182FA` | **裝備武器的技能等級 × 3**（`sub_196C9` 取裝備 → `sub_1830E` → `sub_198CD` → `sub_19CCC`） |
| `loc_1570A` | **Dexterity 修正**（記錄 `+0x13`） |
| `loc_15714` | **Strength 修正**（記錄 `+0x0E`） |
| `sub_15705` | **Luck 修正**（記錄 `+0x10`） |

那三個修正共用 `0x15716` 的尾巴，形狀正是 `docs/re/21` 的**屬性 → 修正值階梯**：

```
屬性 > 13 → (屬性 − 0x0C) >> 1        ; 正修正
屬性 < 9  → 帶符號的負修正
9–13      → 0                          ; 死區
```

**兩邊的傷害算法不一樣**：敵方打隊伍是**一次**「基底 ＋ Nd6」（§4，資料取自
攻擊資料表）；隊伍打敵方是**五項相加**，其中第一項是武器的傷害骰、
另外四項是不擲骰的加值。

⚠ `ds:46C0h` 在這條路徑上被用了兩次：先當命中門檻，命中之後歸零重算成傷害。
看到同一個全域在同一支函式裡有兩種語意時，要以「在哪一段」為準。

推論等級：**已確認**（五個來源都讀完；`sub_15755` 見 [`45`](45-item-data-and-weapon-damage.md)）。

## 5. 完整的一次攻擊

**敵方攻擊隊伍**（把 §1.1、§3、§4 與 `docs/re/19` 接起來）：

```
挑目標    roll(1..隊伍人數)，不合格就重抽
累加值    基礎(40/50/60) ＋ 被攻擊者技能×3 ＋ 欄位 − 敵人資料 +0x02 項，夾在 100
命中      roll(1..100) ≥ 累加值
傷害      (攻擊資料+0x05 的高 4 位) ＋ (攻擊資料+0x03) 顆 d6
護甲      吸收 ＝ 被攻擊者 AC 顆 d6 的和
結算      CON −= (傷害 − 吸收)，≤0 就印「沒造成傷害」
傷勢      CON 為負時查門檻 −11/−20/−30/−40 → UNC/SER/CRT/MRT/COM
```

**隊伍攻擊敵方**（§1.2）：

```
累加值    基礎(50/60) ＋ 攻擊者技能×3 ＋ 欄位 − 敵人資料 +0x02 項，夾在 100
命中      roll(1..100) < 累加值
傷害      射程項 ＋ 武器技能×3 ＋ Dexterity／Strength／Luck 修正（§4.1，沒有骰）
護甲      敵方吸收 ＝ N 顆 d6 的和
結算      HP 減到 ≤0 就夾成 0；擊殺後 sub_159C7 算經驗值、sub_19BC0 加給角色
```

**每次擲骰**（挑目標、命中、傷害 N 顆、護甲 N 顆）全部走
`docs/re/13` 那一支加法型 RNG，所以只要 RNG 狀態一致，整場戰鬥可以逐次對拍。

## 5.1 敵方的血量與扣血

`ds:46C8h` 是**指標**，指向敵方記錄裡某一組的 30-byte 區塊（`docs/re/37` §1）；
血量是那個區塊 `+0x00` 起、每個敵人 2 bytes 的 16-bit 陣列，
索引就是目標編號 × 2（`sub_15B9C`）：

```
0x15B9C  8a1e71a6  mov  bl, ds:0A671h    ; ＝ 目標編號 × 2
0x15BA0  8b3ec846  mov  di, ds:46C8h
0x15BA4  8a01      mov  al, [bx+di]
0x15BA6  fec3      inc  bl
0x15BA8  0a01      or   al, [bx+di]      ; 16-bit 測零 ＝ 是否已死
```

扣血在 `sub_15A9D`：

```
al/dl = ds:46C0h/46C1h          ; 累加出來的傷害
sub_1597E                        ; 減掉敵方護甲：
    護甲 ＝ sub_15672 ＝ 0 ＋ N 顆 d6
    實際傷害 ＝ 傷害 − 護甲，算成負的就夾在 0
[ds:46C8h + n×2] −= 實際傷害      ; 16-bit 借位
if 結果 ≤ 0:
    擊殺計數 ds:0A674h ++
    原 HP 存進 ds:0A678h/0A677h
    HP 兩個 byte 都寫 0            ; ← 歸零，不像角色的 CON 會變負
印訊息 0x21 ＋ sub_15A84（N 點傷害，含單複數）
```

`sub_15672` 是敵方護甲：

```
0x15672  e84616    call sub_15CC0
0x15675  e81ad4    call loc_12A92
0x15678  8ad0      mov  dl, al          ; 骰子數 N
0x1567A  b000      mov  al, 0
0x1567C  e907c7    jmp  sub_19D86       ; ＝ 0 ＋ N 顆 d6
```

**兩邊的護甲機制一模一樣**（都是「N 顆 d6 的和」當吸收），差別只在
角色的骰數來自記錄 `+0x1A`（AC），敵方的來自 `loc_12A92`。

血量的處理則**不對稱**：

| | 位置 | 死亡條件 | 可否為負 |
|---|---|---|---|
| 角色 | 角色記錄 `+0x1D`–`+0x1E` | CON ＝ 0（負值分傷勢等級） | **可以**，負到 −40 以下有五級傷勢 |
| 敵方 | 該組區塊 `+ 編號×2` | 減到 ≤ 0 就寫 0 | **不會**，直接夾成 0 |

推論等級：**已確認**（程式碼讀完；血量陣列的位置由 `docs/re/37` §1 的
指標寫入點與 §3 的填值迴圈兩邊獨立確認）。

## 8. 這一輪學到的（寫成規則）

- **`cmc` 會把比較方向反過來，而且很容易看漏。** 把 `cmp`／`cmc`／`jcc`
  三條抄出來逐條推，不要憑印象。
- **兩處長得一樣的判定，差一個 opcode 就是相反的語意。** 這裡兩條路徑的
  判定前綴機器碼完全相同（`b0 64 … 3a 06 c0 46 f5`），只差 `72` 與 `73`。
  只讀其中一條會得到「累加值 ＝ 命中率」或「＝ 門檻」兩種互斥結論，
  **兩條都讀才看得出來它其實是「隊伍成員的本事」，方向隨攻守翻轉**。
  一度只讀到敵方那條時，合理性檢查與指令對不上，當時的處理是以指令為準
  並標明存疑——現在兩條合起來就解釋通了。
- **累加器被 clamp 在 100，不等於它是百分比。** 形狀像百分比的東西
  可以是門檻、難度或機率，差別只有比較方向看得出來。
