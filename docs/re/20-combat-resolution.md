## 1. 一次攻擊的流程

程式在 `0x1B04C`–`0x1B0D1`（IDA 未建成函式的區塊）：

```
loc_1B04C:
  sub_19D0E                       ; 還有沒有可打的目標
  al = ds:4653h                   ; 隊伍人數
  sub_18E41                       ; ← roll(1..人數)：隨機挑一個目標
  ds:CF84h = al
  sub_172BB                       ; 這個目標能不能打；不能就重抽
  sub_19BF8                       ; 累加器 ds:46C0h ← 0
  bl = ds:CF84h
  al = [ds:46D8h + bl]            ; 目標的一個欄位
  al ＝ 5 → 0x3C(60) ／ ＝ 2 → 0x32(50) ／ 其餘 → 0x28(40)
  sub_1B108(al)                   ; ← 累加出「要擲贏的門檻」
  al = 100
  sub_18E41                       ; ← roll(1..100)
  cmp al, ds:46C0h
  cmc
  jb  loc_1B0A9                   ; 擲出值 ≥ 門檻 → 命中
  ; 未命中：印訊息 0x1F
loc_1B0A9:                        ; 命中
  印訊息 0x55
  sub_12A76                       ; ← 算傷害
  bl = ds:CF84h
  sub_157D6                       ; ← 套用傷害（護甲、扣 CON，docs/re/19 §4）
```

## 2. 命中判定：d100 對「門檻」

**擲出 1–100，要 ≥ 門檻才命中。** 方向逐條核對過（原始 bytes 也對過）：

```
b0 64          mov  al, 64h        ; 100
e8 b1 dd       call sub_18E41      ; al ＝ roll(1..100)
3a 06 c0 46    cmp  al, ds:46C0h   ; CF ＝ 1 當 al <  門檻
f5             cmc                 ; CF ＝ 1 當 al >= 門檻
72 12          jb   loc_1B0A9      ; 跳走 ＝ 命中（該分支呼叫 sub_157D6）
```

**所以 `ds:46C0h` 累加出來的是「要擲贏的門檻」，值越大越難命中**——
它不是命中率，雖然被 clamp 在 100 這件事看起來像百分比。
下結論前請照上面五條指令重驗一次，`cmc` 很容易看反。

推論等級：**強證據**（指令序列與原始 bytes 都對過；「門檻」這個語意是從
比較方向推出來的，還沒有實機對拍佐證）。

## 3. 門檻怎麼累加：`sub_1B108`

累加器是 `ds:46C0h`（16-bit），加減都走 `sub_19C2C`（24 個呼叫端）——
一支**飽和加法**：`dl` 為負就減、借位夾在 0；為正就加、進位夾在 `0xFFFF`。

```
sub_1B108(al ＝ 基礎值):
  sub_19C2C                 ; 門檻 += 基礎值（40／50／60，依目標欄位）
  sub_1B0F1                 ; ┐ al=1 → sub_198CD 找技能編號 1 的等級
  sub_19C2C                 ; ┘ → sub_19CCC（×3）→ 門檻 += 技能等級 × 3
  loc_1570F                 ; ┐ bl=0x12 的欄位
  sub_19C2C                 ; ┘ 門檻 += 該欄位
  al = ds:CF81h
  sub_13A56 / sub_137F4 / sub_13787 / sub_1B15F   ; 算出一個「距離」類的值
  push ax
  sub_12A8D
  if al == 1:  ax *= 4      ; 近距離：× 4
  else:        門檻 += 5
  al = −ax; dl = 0FFh
  sub_19C2C                 ; 門檻 −= 那個值（近距離時是 ×4 之後的）
  ds:46BEh = 100
  sub_19C72                 ; 門檻 > 100 → 夾在 100
```

`sub_19CCC` 是乾淨的 ×3（`x + x×2`，含進位）：

```
0x19CCC  ds:0CD48h = al ; ds:0CD47h = al
0x19CD4  shl  byte ptr ds:0CD47h, 1 ; rcl al, 1    ; ×2，進位進高位
0x19CE0  adc  al, ds:0CD47h                        ; ＋原值 → ×3
```

**技能等級 ×3 是加進門檻的**，所以在這條路徑上技能等級越高越難被命中——
`sub_198CD` 讀的是 `ds:46B5h` 指到的那筆角色記錄，而這一段的目標是隨機挑出來的
隊伍成員，所以讀的是**被攻擊者**的技能。方向一致。

## 4. 武器傷害：`sub_12A76`

```
0x12A76  e8c7ff    call sub_12A40        ; → ds:4665h ＝ 武器／攻擊者的資料
0x12A79  b303      mov  bl, 3
0x12A7B  8b3e6546  mov  di, ds:4665h
0x12A7F  8a01      mov  al, [bx+di]      ; +0x03 ＝ 骰子數 N
0x12A81  8ad0      mov  dl, al
0x12A83  b305      mov  bl, 5
0x12A85  8a01      mov  al, [bx+di]      ; +0x05
0x12A87  e8dfd1    call sub_17C69        ; al >>= 4（取高 nibble）
0x12A8A  e9f9d2    jmp  sub_19D86        ; ＝ 基礎 ＋ N 顆 d6
```

**傷害 ＝（資料 `+0x05` 的高 4 位）＋（資料 `+0x03`）顆 d6。**

`sub_19D86` 的介面是 `al ＝ 基底、dl ＝ 顆數`（`docs/re/13` §3.3），
這裡 `dl` 先被設成 `+0x03`，`al` 最後才被設成高 nibble，順序沒有搞反。

推論等級：**已確認**（兩支函式讀完；`sub_19D86` 的語意已在 `docs/re/13` 驗過）。

## 5. 完整的一次攻擊

把 §1–§4 與 `docs/re/19` 接起來：

```
挑目標    roll(1..隊伍人數)，不合格就重抽
門檻      基礎(40/50/60) ＋ 被攻擊者技能×3 ＋ 欄位 ±距離修正，夾在 100
命中      roll(1..100) ≥ 門檻
傷害      (武器資料+0x05 的高 4 位) ＋ (武器資料+0x03) 顆 d6
護甲      吸收 ＝ 被攻擊者 AC 顆 d6 的和
結算      CON −= (傷害 − 吸收)，≤0 就印「沒造成傷害」
傷勢      CON 為負時查門檻 −11/−20/−30/−40 → UNC/SER/CRT/MRT/COM
```

**六次擲骰**（挑目標、命中、傷害 N 顆、護甲 AC 顆）全部走
`docs/re/13` 那一支加法型 RNG，所以只要 RNG 狀態一致，整場戰鬥可以逐次對拍。

## 8. 這一輪學到的（寫成規則）

- **`cmc` 會把比較方向反過來，而且很容易看漏。** 這裡是
  `cmp` → `cmc` → `jb`，實際語意是「大於等於才跳」。
  下「命中率」這種結論之前，把 `cmp`／`cmc`／`jcc` 三條抄出來逐條推一次；
  推完再問「這個方向合不合理」——這次合理性檢查一度指向相反答案，
  最後是**以指令為準**，把語意從「命中率」改成「門檻」。
- **累加器被 clamp 在 100，不等於它是百分比。** 形狀像百分比的東西
  可以是門檻、難度或機率，差別只有比較方向看得出來。
