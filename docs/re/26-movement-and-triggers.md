## 1. 走一步的完整流程

```
sub_1651A(方向)                  ; 方向：0 上、1 下、2 左、3 右
├─ ds:916Bh ← 方向 − 4
├─ sub_1649E                    ; 能不能走（§3）→ CF=1 就整個放棄
├─ ds:0AA47h ← 方向
├─ call word ptr ds:0AA45h      ; ← ds:0AAA7h[方向]：捲動 ＋ 補畫（§4）
└─ 回到 loc_16572
   ├─ ax ＝ 1 / call sub_1CBD3  ; 音效 1（腳步）
   ├─ sub_16890                 ; 擲遭遇（docs/re/00-master-index §4.2）
   └─ loc_163A0                 ; 重畫 ＋ 跑觸發（§5）
```

四支方向處理（`0x16565`／`0x165A4`／`0x165CA`／`0x165F0`）只差傳給
`sub_1651A` 的方向編號，成功之後全部跳到 `loc_16572`。

## 2. 三張跳表

```bash
python3 tools/dump_word_table.py workplace/analysis/unpacked/wl.merged.exe 0xAA87 16 --code
python3 tools/dump_word_table.py workplace/analysis/unpacked/wl.merged.exe 0xAAA7  4 --code
python3 tools/dump_word_table.py workplace/analysis/unpacked/wl.merged.exe 0xAAB1  4 --code
```

| 表 | `ds:` | 筆數 | 索引 | 內容 |
|---|---|---:|---|---|
| 事件處理 | `AA87h` | **16** | 地圖第 1 層的 nibble | 踩上去要跑哪一支（§5） |
| 捲動 | `AAA7h` | 4 | 方向 | `0x16584`／`0x165FB`／`0x165AC`／`0x165D2` |
| 座標增減 | `AAB1h` | 4 | 方向 | `0x16508`／`0x1650D`／`0x16512`／`0x16517` |

**事件處理表剛好 16 筆**，而第 1 層一格只有 4 bits——表的長度就是「一格能有幾種東西」
的上界。（記錄區標頭的 section 位移表有 24 種型別，`docs/re/16` §3；
兩者不同：地圖 nibble 只能點到前 16 種。）

座標增減那四筆指到成對指令的**中間**，同一段程式碼因此提供兩種走法：

```
0x16506  inc dl        ← 從這裡進去是斜走（x+1, y−1）
0x16508  dec bl        ← 表指這裡：往上（y−1）
0x1650A  retn
```

四對都是這個寫法，所以斜走的四個入口也已經在程式裡，只是這張表沒用到。

## 3. 能不能走：`sub_1649E` 的四道閘

```
sub_164E8         ; 方向 → 目標座標（查 ds:AAB1h）→ sub_18016 邊界檢查
                  ;   0 ≤ x < ds:46A4h、0 ≤ y < ds:46A5h（＝ 邊長 D）
sub_17C20         ; 取目標格第 1 層的 nibble
  nibble == 3 或 15 → 擋住
sub_13E9B → CF    ; 擋住（內含 sub_14085：nibble == 2 也擋）
sub_16AD5 → CF    ; 擋住（nibble == 10 且記錄 +0x00 的 bit7 ＝ 1 時走詢問流程）
sub_15CE0
```

目前確認會擋住移動的 nibble：**2、3、10（條件式）、15**。
其餘 nibble 的通行與否還沒逐一讀完，所以這份清單是**下界不是全集**。

## 4. 捲動：只重畫新進來的兩排

四支捲動函式的形狀一樣，以「往左」為例：

```
0x165AC  dec byte ptr ds:464Eh   ; 視窗原點 X −1
0x165B0  cmp ds:4724h, 0 / jnz   ; 這個旗標非 0 就不重畫
0x165B7  call sub_10024          ; overlay slot 12：畫面整塊往右推一格
0x165BA  ds:4685h ← 2  / sub_16619   ; 重畫 byte 欄 2
0x165C4  ds:4685h ← 0  / sub_16619   ; 重畫 byte 欄 0
```

| 方向 | 原點 | overlay slot | 補畫的兩排 |
|---|---|---:|---|
| 上 | `ds:464Fh` −1 | 14（`sub_1002A`） | 像素列 `0x10`、`0x00` |
| 下 | `ds:464Fh` +1 | 13（`sub_10027`） | 像素列 `0x70`、`0x80` |
| 左 | `ds:464Eh` −1 | 12（`sub_10024`） | byte 欄 `0x02`、`0x00` |
| 右 | `ds:464Eh` +1 | 11（`sub_10021`） | byte 欄 `0x22`、`0x24` |

補畫的座標**正好是視窗的兩端**（欄 0–`0x24`、列 0–`0x80`），
這是地圖視窗 19 × 9 的第四個獨立證據（`docs/re/25` §2.1）。
每次補兩排而不是一排，是因為首尾各是半格。

overlay slot 11–14 因此解出來是**四個方向的畫面捲動**
（`docs/re/04` §3 原本只標「四支大小相近，疑似同族」）。

## 5. 踩上去之後：nibble → 處理函式

`loc_163A0` 先重畫（`sub_167CE` 掃整個視窗，把 nibble 為 **4／5／9** 的格子重畫——
那三種是會動的），再由 `sub_163F6` → `sub_16410` 做分派：

```
0x16410  call sub_17DC7
0x16413  call sub_169EB          ; al ← 這一格的 nibble，並把 ds:46AEh 指到該筆記錄
0x16416  shl al, 1
0x1641A  mov ax, [bx-5579h]      ; ← ds:0AA87h[nibble]
0x1641E  mov ds:4661h, ax
0x16424  jmp sub_19EB4           ; 間接呼叫
```

| nibble | 處理函式 | 目前讀到的 |
|---:|---|---|
| 0、3、7、11、13、14、15 | `0x16563` | `clc; retn`——**什麼都不做** |
| 1 | `0x16CD0` | 比對 `ds:4716h`／`4717h`（上一次的位置），避免重複觸發 |
| 2 | `0x13EC9` | 讀記錄 `+0x0A`（`0xFF` 是哨兵）→ `sub_172BB`／`sub_1417F`。同時也是擋住移動的那一種 |
| 4 | `0x12750` | `sub_16D1A(bl=0)` → `sub_169B1(al=2)` |
| 5 | `0x15280` | **寶箱／掉落物**：第一次踩到才把類別擲成具體物品與數量並寫回記錄（`docs/re/29` §4） |
| 6 | `0x12C70` | 讀記錄 `+0x00`，bit7 決定走哪條 → `sub_169B1(al=1)` |
| 8 | `0x15160` | **多選一選單**：記錄 `+0x03` 起是選項，收 `'1'`–`'9'`（`docs/re/29` §3） |
| 9 | `0x14410` | 印一段訊息並設 `ds:46EFh`（`docs/re/29` §2） |
| 10 | `0x16A10` | 讀隊伍槽表 `+0x0B`／`+0x0C` 並改寫隊伍座標 `ds:46A6h`／`46A7h`——**傳送** |
| 12 | `0x12BD0` | 讀記錄 `+0x00` → `sub_17920`（印訊息那一族） |

實測 42 張地圖的第 1 層只用到 **0–4、6、8–12**，而表裡有專屬處理函式的正好是
**1、2、4、6、8、9、10、12**，其餘指到那支空的 `0x16563`。
**資料用到的值與程式碼有實作的值互相吻合**，兩邊是獨立來源。

推論等級：分派機制**已確認**；5／8／9／10／12 五支已讀完（**強證據**，`docs/re/29`），
1／2／4／6 還只到「入口與前幾行」，是**假說**。

## 6. 每走一步還做了兩件事

- `sub_16890`：擲遭遇（機率分母在記錄區標頭 `+0x2F`）。
- `sub_1676A`（在捲動之後、`0x1655D`）：**推進遊戲時鐘**，每步加的量寫在該地圖的
  標頭 `+0x34`／`+0x35`。時鐘是 24 小時制，晝夜會換畫面與記錄欄位——見
  **[`docs/re/27`](27-game-clock.md)**。

## 9. 這一輪學到的（寫成規則）

- **跳表的長度會告訴你欄位有幾個 bit。** 事件處理表剛好 16 筆，而地圖第 1 層是
  4 bits——先量表長，比從資料反推值域快，而且不會被「這份資料剛好沒用到」騙。
- **「補畫幾排」會洩漏視窗尺寸。** 捲動後補的是欄 0／2 與 `0x22`／`0x24`、
  列 0／`0x10` 與 `0x70`／`0x80`，四個端點直接把視窗框出來。
  找視窗大小時，除了繪製迴圈，**捲動的補畫座標是另一個獨立來源**。
- **跳表指到指令中間不是反組譯錯誤。** `0x16508` 落在 `inc dl` 之後、`dec bl` 之前，
  是刻意讓同一段程式碼提供「斜走」與「直走」兩個入口。
  看到表指向非指令邊界，先確認是不是這種共用尾巴的寫法。
