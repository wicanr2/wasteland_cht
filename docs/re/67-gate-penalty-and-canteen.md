## 1. `sub_14193`：條件跑完之後改一個欄位

```
0x14193  ds:A5C7h ← al             ; 要改誰（角色編號）
0x14196  sub_19614                 ; 設那個人的記錄位址
0x1419C  al ← 地圖記錄 +0x08
0x141A4  ＝ 0 → retn               ; 沒設欄位就什麼都不做
0x141A9  ds:A5C6h ← al & 7Fh       ; **欄位位移**（角色記錄裡的位移）
0x141AF  al 的 bit7：
           設   → 量 ＝ 記錄 +0x09 & 7Fh          （**固定值**）
           沒設 → 量 ＝ sub_19D86(0, +0x09 & 7Fh) （**N 顆 d6**）
0x141D3  sub_19BF0                 ; 量 → ds:46BEh/46BFh
0x141DD  bl ← 記錄 +0x09           ; **原始 byte，含 bit7**
0x141E7  al ← 角色編號；dl ← 欄位位移
0x141EE  call sub_141FA            ; bl 有號負 ＝ 減、正 ＝ 加（docs/re/55 §3）
```

| 欄位 | 意義 |
|---|---|
| 記錄 `+0x08` 低 7 位 | **角色記錄的欄位位移**（`0x1D` ＝ CON、`0x15` ＝ 金錢） |
| 記錄 `+0x08` 的 bit7 | 1 ＝ 量是固定值；0 ＝ 量是 `+0x09 & 0x7F` 顆 d6 |
| 記錄 `+0x09` 低 7 位 | 量（或骰數） |
| 記錄 `+0x09` 的 bit7 | 1 ＝ **減**、0 ＝ 加（傳給 `sub_141FA` 當有號數） |

`sub_142D7` 只是「讀 `+0x08` 並 `& 0x7F`」，收尾那幾條拿它跟 `0x1D`／`0x15` 比，
所以那兩個欄位有專屬的後續處理（`sub_142ED` 會寫 `ds:465Bh` ＝ 時鐘的時）。

## 3. `sub_13EC9` 的迴圈形狀（remake 目前是近似）

收尾那一段（`0x13FB1`–`0x1406A`）顯示 `ds:A5D3h` 是**角色編號**，
從 1 數到 `ds:4653h`，而 `0x13FDC` 的 `sub_14193(A5D3h)` 就在迴圈裡——
所以原版是**逐個角色各自判定、失敗的各自受罰**。

remake 目前的 `EvalParty` 是「任一人過就算過」，**形狀不同**：

| | 原版 | remake |
|---|---|---|
| 判定 | 每個能行動的人各跑一次整串條件 | 逐個試，第一個過就停 |
| 懲罰 | 沒過的那個人各自受罰 | 沒有懲罰 |

對「開門」這種用途兩者結果相同（有人過就開），
但**對高溫這種每個人都要扣血的用途完全不同**。
接懲罰之前要先把迴圈改成原版的形狀。

## 6. 這一輪學到的（寫成規則）

- **一筆記錄裡「條件」與「後果」是分開的欄位。** 條件串列在 `+0x0A` 起，
  而後果（改哪個欄位、加還是減、固定還是擲骰）在 `+0x08`／`+0x09`——
  只讀條件會以為判完就沒事了。
- **兩個 bit7 管兩件不同的事。** `+0x08` 的 bit7 決定「固定值還是擲骰」、
  `+0x09` 的 bit7 決定「加還是減」。同一筆記錄裡相鄰的兩個 byte，
  各自的最高位語意不同——**逐條讀比推類比可靠**。
- **形狀對了才談接線。** `EvalParty` 的「任一人過就算過」對開門是對的，
  對「每個人都要扣血」是錯的。**先確認迴圈的形狀，再決定要不要接**。
