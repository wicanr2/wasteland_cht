## 1. 先講清楚一件事：`ds:4665h` 是共用的「當前資料筆」指標

原版只有**一支**資料表定址器：

```
sub_16F4C(al ＝ 索引)：ds:4665h ← ds:4694h ＋ 索引 × ds:469Bh
```

`ds:4694h`（基址）與 `ds:469Bh`（stride）**是可換的**，由呼叫前的設定函式決定：

| 設定函式 | 基址 | stride | 這是哪張表 |
|---|---|---:|---|
| `sub_17AE0` | `0x7A39`（執行檔內） | 8 | **物品資料表**（95 筆，`docs/re/22`） |
| `sub_18134` | `ds:BA20h`（執行檔內） | 2 | **技能資料表**（§2） |
| `sub_12A40` → `0x12A4C` | 記錄區標頭 `+0x04`／`+0x05`（區塊內） | 8 | **攻擊資料表**（§8） |

所以**「`ds:4665h` 的 `+0x03` 是什麼」這個問題沒有唯一答案**——要先回頭看誰設的基址。
這一點是 `docs/re/20` §4 與 `docs/re/22` §2.1 之前把攻擊資料寫成物品欄位的原因
（推翻紀錄在 `CONTEXT.md`）。

## 2. 技能資料表：`ds:BA20h`，36 筆 × 2 bytes

`sub_1C5B0`（技能學習選單）從索引 1 掃到 `0x24` ＝ 36，每筆兩個 byte：

| byte | 內容 |
|---|---|
| `+0x00` | `>> 3` ＝ **最低 IQ**；`& 7` ＝ **基礎技能點費用**（`docs/re/31` §3） |

### 2.1 用手冊做獨立對照

官方英文手冊的技能表有 **27 條**，每條帶「最低 IQ」與「首級點數」
（`docs/manual/02-character-profile.md`）。**27 條全部與執行檔逐值吻合，零例外。**
執行檔多出來的 8 條手冊完全沒列：

> Combat shooting、Helicopter pilot、Electronics、Toaster repair、
> Doctor、Clone tech、Cyborg tech、Energy weapon

`+0x01`（檢定屬性）手冊沒有寫，是這一輪才從程式碼讀出來的。

## 3. 技能檢定：`sub_180F0(al ＝ 技能編號, dl ＝ 難度)`

```
累加器 B ← 0                                  ; sub_19BF8 → ds:46C0h
B += 難度 × 5 ＋ 15                            ; sub_19CAC 回 16-bit，再 sub_19C2C
sub_18146(技能) ─┬─ 2d6 逢同點續擲（sub_19C84）
                 │  骰值 < 5 → 直接失敗（不看任何加成）
                 ├─ 累加器 A ← 0，A += 骰值      ; ds:46BEh
                 ├─ A += 該技能的檢定屬性值      ; 技能資料 +0x01 當記錄位移
                 └─ A += 技能等級 × 3            ; sub_198CD 取等級、sub_19CCC ×3
ds:916Bh ≠ 0 → 經驗值 += 骰值                   ; sub_19BC0（§7）
成功 ⟺ A ≥ B                                    ; sub_19C69
成功 → sub_1818E：這個技能有機會自己升一級（§5）
```

**門檻 ＝ 難度 × 5 ＋ 15**，難度來自地圖記錄（§6），值域 0–31 → 門檻 15–170。
技能等級 ×3 與戰鬥命中用的是同一支換算（`docs/re/20` §3），這不是巧合：
兩邊都在算「這個人有多行」。

推論等級：**已確認**（五支函式逐條讀完）。

## 4. 屬性檢定：`sub_1820C(al ＝ 難度, bl ＝ 角色記錄位移)`

同一個骨架，少了技能那一項，另外有兩個特例：

```
bl ＝ 0x18（性別）→ 直接比相等，不擲骰
bl ＝ 0x24（等級）→ 直接比大小，不擲骰
其餘：
  2d6 續擲，< 5 → 失敗
  ds:916Bh ≠ 0 → 經驗值 += 骰值
  A ＝ 骰值 ＋ 記錄[bl]
  成功 ⟺ A ≥ 難度 × 5 ＋ 15
```

所以**「性別是女」「等級要 ≥ N」和「敏捷檢定」在資料上是同一種條件**，
只差 `bl` 那個位移。推論等級：**已確認**。

## 5. 技能會自己變強：`sub_1818E(al ＝ 技能, dl ＝ 難度)`

檢定成功之後才跑：

```
沒學過這個技能              → 不升
技能等級 ≥ 角色等級（+0x24）→ 不升        ← 技能等級的上限就是角色等級
技能等級 ≥ 難度             → 不升        ← 太簡單的事練不出東西
門檻 ＝ (難度 − 技能等級) ÷ 2 ＋ 1
roll(1..10) < 門檻          → 技能等級 ＋1（飽和 255），印訊息
```

難度越高、目前等級越低，練起來越快。推論等級：**已確認**。

## 6. 地圖記錄的條件串列（E5 的觸發條件）

`sub_13EC9` 從地圖記錄 `+0x0A` 起**每 2 bytes 一個條件**，逐個試到成功或 `0xFF`：

| byte | 內容 |
|---|---|
| `+0` | 高 3 位 ＝ **條件型別**（`sub_1417F` ＝ `>> 5`）；低 5 位 ＝ **難度**（`sub_1418A` ＝ `& 0x1F`） |
| `+1` | 型別相關的參數 |

| 型別 | 參數是什麼 | 怎麼判 |
|---:|---|---|
| 0 | 技能編號 | 有這個技能才試 → `sub_180F0(技能, 難度)`（§3） |
| 2 | **角色記錄位移** | `sub_1820C(難度, 位移)`（§4） |
| 3 | 一個數 | 與 `ds:4653h`（隊伍人數）相等 |
| 4 | 金額 | `sub_17B3E`：金錢 `+0x15`–`+0x17` 夠不夠（**只比不扣**） |
| 其他 | 物品編號 | `sub_1968C`：掃記錄 `+0xBD`–`+0xF7` 找這件物品；找到 → `sub_19A58` **消耗一次** |

`sub_19A58` 值得單獨記一筆：物品的附屬 byte **低 6 位是次數**，減到 1 再用就把
那個槽整個移除（`sub_194E8`），高 2 位原樣保留。這就是「鑰匙用完會消失」的機制。

推論等級：**強證據**（分派與五種型別的判定都讀完；型別 1／5／6／7 走同一條物品路徑，
但為什麼要分四個編號還沒對上）。

## 7. 經驗值的三個來源

| 來源 | 給多少 | 位置 |
|---|---|---|
| **檢定**（技能／屬性） | 2d6 續擲的骰值 | §3、§4，由 `ds:916Bh` 開關（§7.1） |
| **擊殺敵人** | §8 的公式 | `sub_159C7` → `sub_19BC0` |
| **地圖事件效果** | 固定值或 Nd6 | 效果記錄把目標欄位指成 `0x21`（`docs/re/19` §3） |

三條都經過同一支加法：`sub_19BC0` 把 `ds:466Bh`–`466Dh` 這個 24-bit 暫存
加進記錄 `+0x21`–`+0x23`，**溢位就把三個 byte 全填 `0xFF`（飽和，不繞回）**。

### 7.1 `ds:916Bh` ＝ 這一步是不是玩家自己走的（防刷）

全檔掃描 `ds:916Bh` 只有三筆引用：**一個寫、兩個讀**。

```
0x1651D  mov  ds:916Bh, al           ; sub_1651A：al ＝ 方向碼 − 4
0x1810C  cmp  byte ptr ds:916Bh, 0   ; sub_180F0（屬性檢定）
0x18241  cmp  byte ptr ds:916Bh, 0   ; sub_1820C（技能檢定）
```

唯一的寫入點是走一步的入口 `sub_1651A`，它把**方向碼減 4** 存進去
（`docs/re/26` §1）。方向碼 0–3 是四個方向，所以玩家自己走出來的一步
會留下 `0xFC`–`0xFF`；**只有「方向碼 4」會留下 0**，而 4 只有兩個來源：

| 呼叫端 | 什麼時候 |
|---|---|
| `0x16B9F` | `ds:4704h` 每次外部時鐘變動 ＋1，**滿 1024 就自動走一步**（推時間、擲遭遇） |
| `0x16B46` → `sub_1656D` | `ds:46E1h` 非 0 時每一輪自動走一步 |

兩個讀者都在檢定成功之後：**`916B == 0` 就跳過給經驗值那一段**。
接起來就是一條防刷規則：

> **站著讓時間流逝所觸發的檢定不給經驗值；玩家自己走出來的那一步才給。**

⚠ `916B` **不是每次檢定各自設的**，它記的是「最後一次移動」——
檢定讀到的是殘留值。所以玩家走一步之後，接下來所有檢定都給經驗值，
直到下一次自動步把它清成 0。重製版要照這個形狀做，不要改成 per-check。

另外兩個呼叫端（`0x13D33` 的腳本移動、`0x15FD9`）傳的是變數不是常數，
到底會不會是 4 **未解**——但它們不影響上面這條規則的形狀。

## 8. 擊殺經驗值：`sub_159C7`

```
敵人編號 n ─ sub_13A56 ─→ 拆成 (a ＝ n÷12, b ＝ (n÷3) & 3, 槽 ＝ n mod 3)
sub_137F4(a, b)          ; ds:46C8h ＝ 0x6B31 ＋ 0x178×a ＋ 0x5E×b（docs/re/20）
sub_12A40(槽)            ; ds:4665h ← 攻擊資料表的第 k 筆（§1）
loc_12A92                ; 倍數 ← 資料 +0x04 的低 4 位
sub_15A18                ; 基值 ← 資料 +0x00/+0x01（16-bit）
466B/466C/466D ← 0
重複（倍數 ＋ 1）次：24-bit 累計 += 基值
```

**擊殺經驗值 ＝ 資料 `+0x00`–`+0x01`（16-bit） × ((資料 `+0x04` 低 4 位) ＋ 1)**。
又是加法迴圈當乘法（`docs/re/31` §7 的同一條規則）。

### 8.1 敵人資料表：記錄區標頭 `+0x04`，8 bytes 一筆

`0x12A4C` 把基址設成 `[ds:46B0h + 4]`／`[+5]`，而 `ds:46B0h` 就是記錄區標頭的基址
（`sub_1393E` 用同一個指標讀標頭任一 byte）；stride 寫死 8。
這與 `docs/re/00-master-index.md` §4.1 記的「標頭 `+0x04` ＝ 一張 8 bytes 一筆的
記錄表位址」互相對上。

| 位移 | 內容 | 依據 |
|---|---|---|
| `+0x00`–`+0x01` | **基礎血量，同時也是經驗值基值**（16-bit） | `sub_12AAB`（生怪）／`sub_15A18`（擊殺）讀同一組 byte |
| `+0x02` | **行動值欄位** | `sub_12ABA`（`docs/re/36` §2、`docs/re/37` §3.1） |
| `+0x03` | **傷害骰數 N** | `sub_12A76`（`docs/re/20` §4） |
| `+0x04` 低 4 位 | **經驗值倍數 −1** | `loc_12A92` |
| `+0x05` 高 4 位 | **傷害基底** | `sub_12A76` |
| `+0x05` 低 4 位 | 未解 | `sub_12A8D`（10 個呼叫端） |
| `+0x06`、`+0x07` | 未解 | |

**這張表不是物品表。** 兩張都是 8 bytes 一筆，位址與內容完全不同（§1）。

## 11. 這一輪學到的（寫成規則）

- **看到「某某資料 `+0x03`」的結論，先問基址是誰設的。** 原版只有一支定址器，
  基址與 stride 都是全域變數；同一段程式碼在不同呼叫路徑上讀的是不同的表。
  **只讀取值那一段，就會把 A 表的欄位寫進 B 表的規格**，而且完全自洽、看不出錯。
- **手冊是好用的獨立對照，但只能對它寫了的部分。** 27 條技能逐值吻合，
  給了執行檔那張表很強的信心；而執行檔多出來的 8 條，手冊一個字都沒有——
  **「手冊沒寫」不等於「遊戲沒有」**。
- **檢定、命中、經驗值都共用同一組累加器與換算。** 找到一組
  「歸零 → 逐項累加 → 比大小」的函式之後，其餘機制多半是同一組的另一種填法，
  照著呼叫端往外走比從頭讀每支函式快得多。
