## 1. 42 張地圖都畫得出來

`TestEveryMapRenders`：對每張地圖從中央開始 `LoadMap` 再 `Frame()`，檢查

- 畫面尺寸是 `ScreenWidth × ScreenHeight`
- **每個像素都在 EGA 16 色內**（值 > 15 直接 fatal）
- 不是全黑

```
資源  0：36839／64000 個像素非零（57.6%）
資源  1：23131／64000（36.1%）
資源  2：35310／64000（55.2%）
42 張地圖：畫得出來 42 張、全黑 0 張
```

## 2. 23 家設施都畫得出來

`TestEveryFacilityRenders`：每一家 `EnterFacility` → `Frame()` → `TickAnim()`。
設施畫面有圖片與局部動畫（規格 26），缺圖或動畫解析錯會在這裡炸。

## 3. 戰鬥畫面

`TestCombatRenders`：走到打起來再 `Frame()`。

```
戰鬥畫面：2292／64000 個像素非零（3.6%）
```

3.6% 比地圖的 36–58% 少一個數量級，第一眼像缺口——
但 `docs/re/40` 開頭就寫明：**「戰鬥沒有專屬畫面。原版把地圖視窗換成隊伍名單」**，
訊息與選單都印在原本的訊息視窗裡。所以戰鬥畫面**本來就只有文字**，
稀疏是對的。

**分布看起來不對時，先查文件再查程式碼**。

## 6. 這一輪學到的（寫成規則）

- **值域檢查比「不是全黑」有用。** 「每個像素都在 0–15」抓得到調色盤算錯、
  索引溢位這類問題，而那些通常還是畫得出「不全黑」的東西。
- **全部跑一遍才叫覆蓋。** 42 張地圖裡有大有小、有室內有室外、
  有 `0x600` 也有 `0x1800` 的標頭——只跑地圖 0 等於沒測。
- **分布異常要先找文件。** 戰鬥畫面稀疏一個數量級，查 `docs/re/40`
  第一段就有答案；`docs/re/81` 的傷害爆表則是文件裡沒有的，才要往程式碼追。
