## 2. 表在哪裡

映像裡 `ds:7A31h` 那段是零，表是開檔時讀進來的：

```
0x18654  ...
0x1866D  mov  dx, 53C5h          ; game1 的存檔資源
0x18670  mov  cx, 2              ;   32-bit ＝ 0x000253C5
0x18673  cmp  byte ptr ds:46C5h, 4
0x1867A  mov  dx, 8BC7h          ; game2 ＝ 0x00028BC7
0x18680  add  dx, 1206h          ; ← 存檔資源 ＋ 0x1206 ＝ 物品表資源
0x18684  adc  cx, 0
0x18687  mov  bl, ds:46C5h
0x1868B  cmp  bl, 4
0x18690  shl  bx, 1
0x18692  add  dx, [bx-41E0h]     ; ds:BE20h[槽] ＝ 0 / 0x2FE / 0x5FC
0x18699  call sub_11534          ; seek
0x186A4  call sub_119DB
0x186A9  mov  cx, 2F8h           ; 760 ＝ 95 × 8
0x186AC  mov  dx, 7A31h
0x186AF  call sub_11A10          ; 讀 ＋ 解密
```

`game1` 裡這三個區塊（`0x265CB`／`0x268C9`／`0x26BC7`）都是 `msq0`，
用 `docs/re/08` 的演算法解出來，三份都通過原版自己的 checksum 條件。

**表跟著存檔走**，這解釋了 `docs/re/22` 的一個懸案：賣東西時 `0x1BFE7`
會把 `+0x02` 加一，改的就是這份存檔內的表，不是唯讀資料。

索引：`sub_17AE0` 的基址是 `0x7A39` ＝ 表首 ＋ 8，位址 ＝ `0x7A39 + 8 × 索引`，
所以**索引 0 落在表的第 1 筆**。物品名是執行檔字串表 2 的第 `36 + 索引` 條。

⚠ 760 bytes ＝ 95 筆，但第 0 筆沒有人定址得到，**可定址的是索引 0–93，94 件**。
字串表那邊有 95 條物品名（第 36–130 條），最後一條 `Cash` 沒有對應的表列——
它應該是金錢的顯示名，不是庫存物品。

## 3. 八個欄位

| 位移 | 內容 | 依據 |
|---|---|---|
| `+0x00`–`+0x01` | 基礎價（16-bit） | `sub_17B5C`（`docs/re/22`） |
| `+0x02` | 這家店的庫存量 | `sub_1C140`／`0x1BFE7`（`docs/re/42`） |
| `+0x03` | `>> 3` ＝ **類別**；低 3 位未解 | `sub_199F1`（§3.1） |
| `+0x04` | **彈匣容量** | §3.2 |
| `+0x05` | **使用技能的編號** | §3.3 |
| `+0x06` | **骰數**：武器＝傷害 Nd6、護甲＝AC | §3.4 |
| `+0x07` | **要用的彈藥物品編號**，0 ＝ 不用 | §3.5 |

完整的 95 筆在 [`generated/ida94/items.md`](generated/ida94/items.md)（工具輸出）。

### 3.1 類別 ＝ `+0x03 >> 3`

`sub_199F1` 取 `+0x03` 之後跳進 `sub_17C69` 的**第二條指令**（`0x17C6B`），
那支是四個連續的 `shr al, 1`——**從第二條進去只右移三次**，不是四次。

```
0x199F1  mov  bl, 3
0x199F3  mov  di, ds:4665h
0x199F7  mov  al, [bx+di]
0x199F9  jmp  loc_17C6B          ; ＝ al >>= 3
```

18 個類別，按表的內容分得很乾淨：

| 類別 | 內容 |
|---:|---|
| 1 | 近戰／徒手（Fists、Ax、Club、Chainsaw、Knife、Proton ax） |
| 2 | 手槍與投擲（M1911A1、Spear、Throwing knife、VP91Z） |
| 3 | Flamethrower、M17 carbine |
| 4 | M19 rifle、Red Ryder |
| 6 | 衝鋒槍 |
| 7 | 突擊步槍 |
| 8／9 | 反戰車（Mangler、Sabot rocket／LAW rocket、RPG-7） |
| 10–12 | 能量武器 |
| 13 | 爆裂物（Grenade、Plastic explosive、TNT） |
| 14 | 彈藥 |
| 15 | 護甲 |
| 16 | 一般物品 |
| 17 | 可賣雜物（Clay pot、Fruit、Jewelry） |
| 18 | 劇情物品 |

**`ds:CD00h` 那張清單就是「有射程的武器類別」**（`sub_19D2F` 逐 byte 比對，
遇到負值收工）：

```
0D 0A 0B 0C 02 03 04 05 06 07 08 09 FF
```

＝ 類別 2–13。**類別 1（近戰／徒手）不在裡面**，14 以上也不在。

### 3.2 `+0x04` ＝ 彈匣容量

M1911A1 45 pistol 是 **7**、VP91Z 9mm 是 18、Uzi 是 40、Mac 17 SMG 是 30、
M19 rifle 是 8、Flamethrower 是 60。`.45` 手槍七發是史實，
整欄的數字也只有「一次能打幾發」講得通。讀取端在 `sub_19A0F` 的另一個入口
（`0x19A14`，`bl = 4`）。

### 3.3 `+0x05` ＝ 技能編號

值直接對到技能字串表（`docs/re/32` §2 的 36 條）：

| `+0x05` | 技能 | 用它的武器 |
|---:|---|---|
| 1 | Brawling | Ax、Club、Chainsaw、Proton ax、Spear |
| 3 | Clip pistol | M1911A1、VP91Z |
| 4 | Knife fight | Knife |
| 5 | Pugilism | Fists |
| 6 | Rifle | M17 carbine、M19 rifle、Red Ryder |
| 8 | Knife throw | Throwing knife |
| 10 | Assault rifle | AK 97、M1989A1 |
| 11 | AT weapon | Mangler、Sabot rocket、LAW rocket、RPG-7 |
| 12 | SMG | Mac 17、Uzi |
| 20 | Demolitions | Grenade、Plastic explosive、TNT |
| 34 | Energy weapon | 五把雷射／離子／介子武器 |

**十一個群組沒有一個例外**——這是「欄位語意」等級的證據，不是巧合。
`docs/re/20` §4.1 的第二項（`sub_182FA` ＝ 裝備武器的技能等級 × 3）
要知道「是哪個技能」，答案就是這個欄位。

### 3.4 `+0x06` ＝ 骰數

同一個欄位，兩種讀者，同一個意思——**這件裝備值幾顆 d6**：

- **武器**：`sub_15755` 拿它當 `sub_19D86` 的顆數（§4）。
  Fists 1、Knife 3、Chainsaw 6、Proton ax 14、RPG-7 13、Meson cannon 19。
- **護甲**：`sub_1949E`（裝備）在類別 ＝ 15 時把它寫進角色記錄 `+0x1A`：

```
0x194C5  call sub_199F1          ; 類別
0x194C8  cmp  al, 0Fh            ; 15 ＝ 護甲
0x194CA  jnz  short loc_194DC
0x194CC  call sub_19A0F          ; ＝ 物品 +0x06
0x194CF  mov  bl, 1Ah
0x194D5  mov  [bx+di], al        ; 角色記錄 +0x1A ← AC
```

而 `docs/re/19` §4 早就讀出「護甲吸收 ＝ 記錄 `+0x1A` 顆 d6」。
兩邊接起來：Leather jacket 1、Kevlar vest 4、Kevlar suit 6、
Pseudo-chitin armor 10、Power armor 14。

同一段還解掉兩個角色記錄欄位：**`+0x1F` ＝ 裝備武器的物品槽、
`+0x25` ＝ 裝備護甲的物品槽**（`sub_1949E` 用它們判斷「再按一次就是卸下」）。

### 3.5 `+0x07` ＝ 彈藥物品編號

表自己指回自己：M1911A1 45 pistol 的 `+0x07` ＝ 30 ＝ **45 clip**、
M17 carbine ＝ 31 ＝ 7.62mm clip、VP91Z ＝ 32 ＝ 9mm clip、
五把能量武器 ＝ 34 ＝ Power pack。索引基準與物品名完全一致。

`sub_19202` 拿它跟角色記錄的一個欄位比（`docs/re/22` 只讀到這一步），
現在看得出來那是**檢查身上有沒有對應的彈藥**。

## 4. `sub_15755`：隊伍傷害的第一項

`0x15755`，`seg000+0x5755`，88 bytes，3 個呼叫端。
**入口：`al` ＝ 角色編號、`dl` ＝ X（見 §4.2）。**

```
0x15755  mov  ds:0A689h, dl      ; 存 X
0x15759  call sub_13878          ; 算接戰值；順便把裝備武器設成當前定址的物品
0x1575C  mov  al, ds:46CDh       ; 武器類別
0x1575F  call sub_19D2F          ; 在 ds:CD00h 清單裡嗎
0x15762  jb   short loc_1577F    ; 不在 → 走這條
0x15764  mov  al, ds:46CCh
0x15767  cmp  al, 10h
0x15769  cmc
0x1576A  jb   short loc_1577F    ; 接戰值 ≥ 0x10（＝ 0xFE）→ 也走這條

; ── 近戰分支（§4.3：正常戰鬥踏不到）──
0x1576C  mov  dl, 1
0x1576E  mov  al, 0
0x15770  mov  al, ds:46CDh       ; ⚠ 把上一行的 0 蓋掉
0x15773  cmp  al, 2
0x15775  jz   short loc_157AA
0x15777  cmp  al, 0Ah
0x15779  jz   short loc_157AA
0x1577B  inc  dl
0x1577D  jnz  short loc_157AA

loc_1577F:
0x1577F  call sub_19A0F          ; ＝ 物品 +0x06
0x15782  mov  dl, al             ; 顆數
0x15784  mov  al, ds:46CDh
0x15787  call sub_15C8C          ; 類別 ∈ {8, 9}？
0x1578A  jb   short loc_157A8    ; 不是 → 顆數就用原值
0x1578C  cmp  dl, ds:0A689h
0x15790  cmc
0x15791  jnb  short loc_157A8    ; 顆數 < X → 也用原值
0x15793  mov  ds:0A68Ah, dl
0x15797  mov  al, dl
0x15799  sub  al, ds:0A689h
0x1579D  clc
0x1579E  adc  al, ds:0A68Ah      ; dl ← 2 × 顆數 − X
0x157A2  mov  dl, al
0x157A4  jnb  short loc_157A8
0x157A6  mov  dl, 0FFh           ; 溢位就飽和

loc_157A8:
0x157A8  mov  al, 0              ; 基底 0
loc_157AA:
0x157AA  jmp  sub_19D86          ; ＝ 基底 ＋ dl 顆 d6
```

`sub_19D86` 是 `docs/re/13` §3.3 早就驗過的「基底 ＋ N 顆 d6」，
介面是 `al ＝ 基底、dl ＝ 顆數`。所以：

> **第一項 ＝ 0 ＋（武器 `+0x06`）顆 d6。**

### 4.1 接戰值只有兩種結局

`sub_13878` 決定 `ds:46CCh`／`ds:46CDh`：

| 情況 | `46CC` | `46CD` |
|---|---|---|
| 角色不能行動（`sub_172BB`，CON ≤ 0） | `0x00` | **不動**（留上一次的值） |
| 裝備的類別 ∈ 2–13 | `0xFE` | 類別 |
| 其他（空手、近戰、非武器） | `0x0F` | 強制成 `1` |

回到 `sub_15755`：`46CD ＝ 1` 不在 `ds:CD00h` 清單裡 → 跳 `loc_1577F`；
`46CD ∈ 2–13` 在清單裡 → 但這時 `46CC` 必然是 `0xFE ≥ 0x10` → 也跳 `loc_1577F`。
**兩條都走同一邊。**

### 4.2 反戰車武器：`2N − X`

`sub_15C8C` 只認類別 8 與 9 ——表裡正好是 Mangler、Sabot rocket、
LAW rocket、RPG-7 四把（技能欄一致是 AT weapon）。它們的骰數在 `N ≥ X` 時
變成 `2N − X`，飽和在 255。

`X` 的兩個取值：

| 呼叫端 | `X` |
|---|---|
| `0x1AFA3`（`0x1AF52` 的隊伍攻擊） | **0**——前一條 `call sub_19BF8` 就是 `al ← 0; dl ← 0` |
| `0x15566` → `sub_15738` | `loc_12A92` 的回傳 ＝ 敵人資料表 `+0x04` 低 4 位 |
| `0x12E40`（`46CD == 0x0D`，投擲爆裂物） | 未定——這一段沒有明顯的設定點 |

X ＝ 0 時 `2N − 0 ＝ 2N`：RPG-7 在主攻擊路徑上是 **26 顆 d6**。
敵人資料表 `+0x04` 低 4 位在 `docs/re/31` 是「經驗值倍數 −1」，
用在這裡等於「越硬的敵人，火箭的加成越少」——講得通，但**只有單一來源**，
所以標強證據。

### 4.3 近戰分支踏不到

`0x1576C` 那一段要同時成立兩件事：`46CC < 0x10`（即 `0x00` 或 `0x0F`）
**而且** `46CD ∈ 2–13`。但 `46CC ＝ 0x0F` 時 `46CD` 一定被強制成 `1`，
所以只剩 `46CC ＝ 0x00`——角色不能行動，而 `46CD` 還留著上一個角色的類別。

那條路上還有一個原版的疏漏：`0x1576E` 的 `mov al, 0`（基底）
被下一條 `mov al, ds:46CDh` 蓋掉，於是基底變成武器類別。
**照抄**——它在正常流程裡跑不到，重製版沒有理由去「修好」它，
但也不該把它整段刪掉（`docs/re/44` §5 的走音 E 同一個道理）。

## 5. 對重製版的意義

- 物品表**從玩家自備的存檔區讀**，不散布（與音效資料、字型一致）。
- 傷害要照抄「顆數 × d6」的形狀，不要換成期望值或平均傷害——
  26 顆 d6 的分布和 91 點固定傷害是兩回事。
- 技能欄（`+0x05`）讓 `docs/re/20` §4.1 的第二項可以實作了。
- 三個沒有名字的物品（編號 70／71／72，價 500／4500／4000）：
  執行檔字串表的第 106–108 條是空的。名字可能在區塊字串表裡，未查。
- `Cash` 沒有表列，商店與清單要另外處理它。

## 6. 還沒解的

- `+0x03` 的低 3 位。整張表只有 bit0 會是 1，而且**只出現在類別 8／9／13**
  （反戰車與爆裂物，也正是 `+0x04` ＝ 1、用一次就沒了的那些）。
  「bit0 ＝ 消耗型」是**假說**，沒有讀到任何程式碼碰它。
- `X` 在 `0x12E40`（投擲爆裂物）那條路上是什麼。
- 物品 70／71／72 的名字。
- `sub_15C8C` 為什麼只認 8 與 9，而不是整個反戰車家族用同一個類別。

## 8. 這一輪學到的（寫成規則）

- **「某某項未定」掛久了要回頭問一次「真的難嗎」。** 這一項在
  `docs/re/20`／`21`／`22`／`38` 四份文件裡掛了「未定」，實際上函式只有 88 bytes，
  讀完只花一輪。擋住的不是難度，是沒人回去看。
- **跳進函式中間就是另一支函式。** `sub_199F1` 跳的是 `loc_17C6B`
  ——`sub_17C69` 的第二條指令。當成「呼叫 `sub_17C69`」就會把 `>> 3` 讀成 `>> 4`，
  類別全部差一倍，而且每一條都還「看起來像有意義的分類」。
- **表的欄位語意要用「整欄一起講得通」來驗，不是單筆。** `+0x05` 是靠
  十一個群組零例外才敢寫成「技能編號」；只看 Fists ＝ 5 什麼也證明不了。
- **表自己指回自己是最好的佐證。** `+0x07` 的值就是同一張表的索引
  （手槍 → 45 clip），而且索引基準和物品名一致——這種自洽比任何外部說法都硬。
- **執行期載入的表要找到它的來源檔，不要停在「映像裡是零」。** 物品表在存檔區，
  所以它是**可變的遊戲狀態**，不是唯讀資料——這一點會直接影響存檔的改寫策略。
