## 1. 佇列：`ds:A96Fh`，4 組 × 4 槽

64 bytes ＝ 16 筆 × 4 bytes。分組位移表 `ds:A622h` 是 `00 10 20 30`，
所以**第 g 個隊伍組的四個槽從 `16 × g` 開始**——與敵方記錄陣列的
4 × 4 版面（`docs/re/37` §1）一一對應。

| 位移 | 內容 |
|---|---|
| `+0x00` | 遭遇所在格的 **x** |
| `+0x01` | **y** |
| `+0x02` | 資源（地圖）編號 |
| `+0x03` | **與最近那一組隊伍的距離**（§4） |

| 函式 | 作用 |
|---|---|
| `sub_14A88(bl)` | 寫一筆（x／y 取自 `ds:0A60Dh`／`ds:0A60Ch`，地圖取 `ds:4655h`，距離取 `ds:0A60Bh`） |
| `sub_14AEA(al, dl, bl)` | 依 (地圖, x, y) 線性找；找到回 CF ＝ 1，`bl` 停在該筆的位移 |
| `sub_14AAA` | 找到之後把那 4 bytes 清成 0 |
| `sub_14B93(al)` | 組編號 → 該組四個槽的起始位移（查 `ds:A622h`） |

⚠ **`sub_14664` 一進來就把整個 64 bytes 清成 0**（`0x14669`–`0x14673`）。
佇列不是持久的待辦清單，是**「目前視野裡有哪些遭遇」的快照**，每次掃描重建。

## 2. 掃描範圍就是看得見的那塊

```
ds:0A621h ← 9                     ; 掃 9 列
y ← ds:464Fh                      ; 視窗原點 Y
每一列：
    y < 0 → 跳過；y ≥ ds:46A4h → 這張地圖掃完
    sub_17C72(y)                  ; 第 2 層的列基址 → ds:46ACh
    ds:0A61Fh ← ds:46A3h          ; 這一列掃幾行（＝ 0x13 ＝ 19）
    x ← ds:464Eh                  ; 視窗原點 X
    每一行：
        x < 0 → 跳過；x ≥ ds:46A5h → 換下一列
        sub_17C20(x, y) → ds:46B3h ; 第 1 層的 nibble
        nibble ＝ 3 或 15 → 這一格有遭遇
```

**9 × 19 正好是地圖視窗**（`docs/re/25`），也正好是距離表涵蓋的範圍
（`docs/re/37` §4 的 5 × 10 ＝ 半徑 ±4 × ±9）。三處獨立對上。

> **遭遇 ＝ 第 1 層 nibble 3 或 15 的格子。** 這兩個值同時也是
> `ds:AA87h` 那張 16 筆踩踏跳表裡的兩個項目（`docs/re/26` §5）——
> 同一個 nibble，走過去會觸發，看得見時就會被掃到。

推論等級：**已確認**（迴圈邊界、兩個 nibble 值、視窗原點與地圖邊界都讀到）。

## 3. 每一格要過的關

命中的格子先用 `sub_1379E`（第 1／2 層的值 → 記錄）取出它的地圖記錄（`ds:46C6h`），
再用 `sub_19D4D(x, y)` 算與隊伍的距離（`docs/re/37` §4）。

| 記錄位移 | 用途 |
|---|---|
| `+0x00` | **察覺距離上限**——距離大於它就整格略過 |
| `+0x01` | **主動距離**——距離不大於它就一定進佇列 |
| `+0x03`／`+0x05`／`+0x07` | 三組敵人的型別（`docs/re/37` §3） |
| `+0x04`／`+0x06`／`+0x08` | 三組敵人的數量 |
| `+0x09` | `sub_12AC5` 取 `>> 2` |

判斷順序：

```
距離 > 記錄+0x00                → 略過這一格
是玩家自己那一組                 → 順便把敵人圖示畫到地圖上（0x147BA–0x14819）
sub_19D0E：這格沒有敵人          → 略過
距離 ≤ 記錄+0x01                → 進佇列
否則 距離 ≤ 該組的接戰值         → 進佇列
否則                            → 略過
```

## 4. 接戰值，與「哪一組最靠近」

進 `sub_14664` 的第一段先對**四個隊伍組**各算一次：

```
[0x7212 + 組] ← max over 該組成員 of sub_13878(成員)
```

`sub_13878` 回傳的是 `ds:46CCh`，只有三種值：

| 值 | 條件 |
|---|---|
| `0x00` | 這個成員不能行動（`sub_172BB`，CON ≤ 0） |
| `0x0F` | 能行動 |
| `0xFE` | 能行動，而且 `sub_199F1` ＋ `sub_19D2F` 那條路成立（裝備／射程相關，未逐行讀） |

距離最大 98（`docs/re/37` §4），所以 `0x0F` ＝ 只在很近的距離算數、
`0xFE` ＝ 任何距離都算數。取最大值等於「**這組裡最能接戰的那個人**」。

命中的格子接著用 `sub_149F7` 對四組各評一次，把結果寫進 `[0x7111 + 組]`：

```
該組不在這張地圖／這一格不在該組的視窗內／該組沒有敵人可打 → 0xFF
否則 距離 ≤ 記錄+0x01 或 距離 < [0x7212 + 組] → 存「距離」
否則                                          → 0xFF
```

⚠ **存進去的是距離，不是接戰值。** `sub_14A65` 接著掃這四個 byte，
從 `al ＝ 0xFF` 開始、**只在比目前小的時候更新**——所以它挑的是
**距離最近的那一組**（全部 0xFF ＝ 沒有任何一組適用，整格略過）。

那個距離就是佇列的 `+0x03`，那一組決定這筆放進哪四個槽。
槽內以 `+0x03` **由近到遠**排（`0x148A8` 的比較迴圈是「插在第一個比它遠的前面」），
四槽滿了就把最遠的擠掉（寫 `0xFF` 到 `[0x7111 + 組]` 之後重挑下一近的組）。

如果這筆本來就在佇列裡（`sub_14AEA` 找得到，回傳值 `al ＝ 佇列索引 >> 2` ＝ 原本那一組），
而且原本那一組就是最近的那一組，就什麼都不做。

推論等級：**已確認**（`sub_149F7`／`sub_14A65` 逐指令讀完，
比較方向與 `0xFF` 初值都對過；只有決定 `0xFE` 的 `sub_199F1`／`sub_19D2F` 未讀）。

## 5. 收尾：敵方記錄跟著佇列走

`0x14965`–`0x149F6` 掃 4 × 4 筆敵方記錄，對每一筆：

```
記錄 +0x02 ≠ 目前地圖 → 清掉
用記錄的 (+0x00, +0x01, 地圖) 去 sub_14AEA 找佇列 → 找不到就 sub_138B0 整筆清成 0
```

所以**走出視野的遭遇，它的敵方記錄會被丟掉**——這也解釋了為什麼
`sub_14480`（`docs/re/37` §3）要分兩趟：先把還在的搬到該在的槽，再替新的建記錄。

回傳值：`ds:0A60Ah`（這次有東西進佇列）**AND** `ds:0A610h`
（有記錄通過 `sub_12AC5`）非 0 → CF ＝ 0。

## 8. 這一輪學到的（寫成規則）

- **「這張表是誰填的」要問寫入點，而寫入點常常只有一支函式。**
  `ds:A96Fh` 在映像裡全零、直接定址掃描零命中，看起來像沒人碰——
  它其實全部經 `[bx + 位移]` 存取，而三支存取函式的呼叫端全在同一支 `sub_14664` 裡。
- **同一個尺寸出現三次就不是巧合。** 9 × 19 的掃描範圍、19 × 9 的地圖視窗、
  5 × 10 的距離表半徑——三處獨立對上，等於同時確認了三件事的邊界。
- **清空發生在進入點，不是離開點。** 看到一張表「不知道誰清的」時，
  先看使用它的那支函式開頭——快照型的資料結構都是進來就重建。
- **「挑最大」與「挑最小」差在初值，不在比較方向。** `sub_14A65` 從 `0xFF` 起跳，
  所以它挑的是最小值；`sub_1AEAE`（`docs/re/36` §3）從 0 起跳，挑的是最大值。
  兩支的比較序列長得幾乎一樣——只看比較不看初值會把語意讀反。
