## 1. 佈局

```
+0x0000              地圖（P bytes）
+P                   記錄區標頭（0x5C ＝ 92 bytes）
+P+0x5C              第一個 section
…                    其餘 section 依標頭裡的位移排列
```

**P 不是固定的 0x800**（`docs/re/09` §2 曾經以 `+0x800` 為起點找記錄表，
那是把地圖當成固定 2048 bytes 推出來的）。P 由執行檔內的選擇表決定：

| 條件 | P |
|---|---|
| `ds:BF1Ch[資源編號] == 0x40` | `0x1800`（6,144） |
| 其餘 | `0x600`（1,536） |

程式碼在 `sub_1841F`（`0x1841F`–`0x18436`）：

```
0x1841F  ba0018      mov  dx, 1800h
0x18422  a05546      mov  al, ds:4655h
0x18425  84c0        test al, al
0x18427  780a        js   short loc_18433
0x18429  8ad8        mov  bl, al
0x1842B  8a871cbf    mov  al, [bx-40E4h]     ; ds:BF1Ch
0x1842F  3c40        cmp  al, 40h
0x18431  7403        jz   short loc_18436
0x18433  ba0006      mov  dx, 600h
0x18436  8916b046    mov  ds:46B0h, dx       ; ← P
```

`ds:BF1Ch` 那張 50 byte 的表只有四個 `0x40`（資源 0、12、22、26），
其餘都是 `0x20`——**42 個區塊裡只有 4 個是大地圖**。

推論等級：**已確認**（程式碼讀完、表值從映像讀出）。

### 1.1 地圖尺寸

區塊被讀進 DS:0000（`sub_1841F` 的 `mov dx, 0` ＋ `sub_115E5`），
所以地圖從 body 位移 0 開始，佔滿 P bytes，一個 byte 兩格（4 bits 一格）：

| P | 格數 | 最佳列寬（垂直自相關） | 尺寸 |
|---|---:|---:|---|
| `0x600` | 3,072 | 64 nibble（32 個區塊） | **64 × 48** |
| `0x1800` | 12,288 | 128 nibble（4 個區塊） | **128 × 96** |

大地圖正好是小地圖的兩倍寬、兩倍高。剩下 6 個小區塊的自相關在 32 列寬最高，
可能是地形單純造成的假峰，**未定案**。

推論等級：**強證據**（P 來自程式碼，尺寸來自自相關的極值，未由繪圖程式碼直接證實）。

## 2. 記錄區標頭（P 起算 0x5C bytes）

已對上的欄位：

| 位移 | 內容 | 依據 |
|---|---|---|
| `+0x00` | word → `ds:4692h/4693h` | `sub_1790B`（3 個呼叫端） |
| `+0x02` | word → `ds:4680h/4681h`＝**字串指標** | `sub_129E9`（`0x12A04`–`0x12A13`） |
| `+0x04` | word → `ds:4694h/4695h` | `sub_12A4C`（3 個呼叫端） |
| `+0x06`…`+0x28` | **section 位移表**（見 §3） | `sub_17CB1` |
| `+0x33` | byte，`sub_18024` 讀 | `0x18031` |

`+0x02` 是字串指標這件事很有用：`docs/re/09` §3 看到的那批明文怪物名，
入口就在這裡，不必再靠掃描找。

任意標頭 byte 的通用讀取器是 `sub_1393E`（9 bytes、7 個呼叫端）：

```
0x1393E  mov  di, ds:46B0h
0x13942  mov  al, [bx+di]     ; bl ＝ 標頭位移
0x13944  jmp  sub_178A0
```

## 3. Section 位移表與兩層索引

標頭裡的位移**不是連續存放的**，要透過執行檔內 `ds:B9E0h`（線性 `0x28800`）
那張「section 型別 → 標頭位移」的表去查：

| 型別 | 標頭位移 | | 型別 | 標頭位移 |
|---:|---|---|---:|---|
| 0–12 | `+0x06`、`+0x08`…`+0x1E` | | 13、14 | 0（不存在） |
| 15 | `+0x24` | | 16 | `+0x26` |
| 17 | `+0x28` | | 18–23 | 0（不存在） |

取一筆記錄要走兩層，全部在 `sub_17CB1`（33 bytes、18 個呼叫端）裡：

```
0x17CB1  50          push ax                 ; al ＝ 記錄編號
0x17CB2  d0e3        shl  bl, 1              ; bl ＝ section 型別
0x17CB4  8b87e0b9    mov  ax, [bx-4620h]     ; 查 ds:B9E0h → 標頭位移
0x17CB8  0306b046    add  ax, ds:46B0h       ; ＋ P
0x17CBC  8bf8        mov  di, ax
0x17CBE  8b05        mov  ax, [di]           ; 讀出 section 起點
0x17CC0  a36146      mov  ds:4661h, ax
0x17CC3  58          pop  ax
0x17CC4  d0e0        shl  al, 1
0x17CC6  8ad8        mov  bl, al
0x17CC8  8b3e6146    mov  di, ds:4661h
0x17CCC  8b01        mov  ax, [bx+di]        ; section 起點 ＋ 編號×2
0x17CCE  a3ae46      mov  ds:46AEh, ax       ; ← 這筆記錄的位址
0x17CD1  c3          retn
```

`ds:46AEh` 之後被當基址暫存器用（全檔 150 處以上的 `mov di, ds:46AEh`），
**它就是「目前這筆地圖記錄」**。這解釋了為什麼固定位移掃描完全找不到記錄欄位。

推論等級：**已確認**（程式碼讀完）。

### 3.1 型別是從哪裡來的

**取一格的記錄時，section 型別就是那一格第 1 層的 nibble 本身**
（`sub_169EB`：`sub_17CD2` 回傳 nibble 與第 2 層的值，nibble 進 `bl`、
第 2 層進 `al`，直接呼叫 `sub_17CB1`）。所以 nibble 6 的格子讀的是型別 6 的
section、nibble 2 讀型別 2，以此類推。

⚠ **只看 `sub_17CB1` 的靜態呼叫端會漏掉這件事**——它們傳的是常數
（型別 3、5、15、16、17），而 `sub_169EB` 傳的是動態的 nibble。
`export_function.py --callers` 看到的是前者，形狀完全正常，
所以「只用到五種型別」這個結論當時看起來很紮實。

### 3.2 哪些 section 是指標陣列

靜態呼叫端用到的型別 3 與 5，section 內部是 **`[16-bit 指標陣列][記錄本體]`**，
陣列長度不另外存——**第一個非空指標指到哪，陣列就到哪為止**。
用 42 個區塊驗證：

| 型別 | 標頭位移 | 結構成立 / 有此 section 的區塊數 |
|---:|---|---|
| 3 | `+0x0C` | **40 / 42** |
| 5 | `+0x10` | **39 / 42** |
| 15 | `+0x24` | 25 / 39 |
| 16 | `+0x26` | 2 / 37 |
| 17 | `+0x28` | 2 / 25 |

型別 3、5 可以當結論用；**15、16、17 的內部格式未解**，
不能套同一套解讀（16 與 17 在部分區塊指到同一個位址，形狀就不一樣）。

另一項全域驗證：**41 / 42 個區塊的第一個 section 正好落在 `P + 0x5C`**，
這同時釘死了標頭大小是 0x5C。

推論等級：型別 3、5 **強證據**；型別 15、16、17 **未解**。

## 6. 這一輪學到的（寫成規則）

- **「地圖是 2048 bytes」這個數字是推出來的，不是讀出來的。** 它來自
  `64 × 64 × 4 bits`，而真正的答案在 `sub_1841F` 裡是一個查表的 `0x600`／`0x1800`。
  自相關驗證通過不代表邊界正確——**驗證通過的是「這區是地圖」，不是「這區到哪為止」**。
- **一個結構驗證失敗時，先問「這個結構本來就該套用在這裡嗎」。** 把 13 個
  section 全部當指標陣列驗，得到 44/393，看起來像整套假說錯了；
  先去查 `sub_17CB1` 實際被用哪幾個型別呼叫，剩下 5 個型別裡有 2 個是 40/42。
  **驗證範圍錯了，比假說錯了更常見。**
