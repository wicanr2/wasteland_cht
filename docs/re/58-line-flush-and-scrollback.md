## 1. `sub_19F12` 做四件事

```
0x19F12  bl ← ds:4672h              ; 目前欄
0x19F16  al ← [bx + 71CDh]          ; 文字組行緩衝區
         al ＝ 0 或 bl ＝ ds:4674h（行首）→ 停
         否則 bl−−，繼續往回找       ; **找最後一個非空字元 ＝ 斷字點**
0x19F28  ds:0CDCCh ← bl             ; 記下斷字點

0x19F2C  ds:8DF8h ≠ 0 時（scrollback 開著）：
0x19F33     ds:8DF6h++                        ; 目前列號
0x19F3F     bx ← 列 × 40 ＋ 8CE0h             ; ×8 再 ×5
0x19F57     es ← seg003
0x19F5C     行首 … 斷字點的字元 → es:[bx + 欄]
0x19F6E     該列剩下的 0x27 個 byte 清 0
0x19F79     bx ≥ 0B4DFh → bx −= 2800h         ; **環形**

0x19F8D  行首 … 斷字點：逐字 call sub_1000F   ; overlay slot 5 ＝ 畫出來
0x19FAC  斷字點之後的字元搬回行首              ; **續行**
0x19FE2  緩衝區從新位置到 0x33 清 0
```

四件事：**斷字 → 寫 scrollback → 送畫面 → 把剩下的搬到下一行**。

## 2. Scrollback：`seg003:0x8CE0`，40 × 256 環形

`0x8CE0 ＋ 0x2800 ＝ 0xB4E0`，而回捲判斷寫的是 `cmp bx, 0B4DFh` / `sub bx, 2800h`
——**40 bytes × 256 列的環形緩衝區**，一列一行文字。
`ds:8DF8h` 是開關、`ds:8DF6h` 是目前列。

組行緩衝區本身在 `ds:71CDh`，一行上限 `0x33`（51 欄）——
`0x19FEC` 的 `cmp dl, 33h` 是清空迴圈的邊界。

| 變數 | 意義 |
|---|---|
| `ds:4672h` | 目前欄 |
| `ds:4674h` | 行首欄 |
| `ds:4675h` | 行尾欄 |
| `ds:0CDCCh` | 這一次的斷字點 |
| `ds:71CDh` 起 | 組行緩衝區（51 欄） |
| `ds:8DF6h`／`ds:8DF8h` | scrollback 的目前列／開關 |

## 3. 與 `0x0D` 的差別：捲不捲

`0x0D`（組行版）走的是 `sub_19EFC`：

```
0x19EFC  ds:46F0h ≠ 0 → 直接 retn      ; 批次結算中就整支跳過（docs/re/55 §3）
0x19F03  call sub_19F12                ; ← 同一支
0x19F0A  call sub_1A0C5                ; 捲動 ＋ 計時器延遲（'<' '>' 可調速）
```

而 `0x08` 那一格**直接指向 `sub_19F12`**（`docs/re/14` §4.1 的跳表）。
所以：

| 碼 | 斷字／送畫面／scrollback | 捲動與延遲 | 受批次旗標影響 |
|---|:-:|:-:|:-:|
| `0x0D` | ✓ | ✓ | ✓ |
| `0x08` | ✓ | ✗ | ✗ |

**`0x08` 是「這一行畫完就好，不要再往下捲」。**

## 4. 語料裡的三條用例

7 次出現裡，**3 次在字母表本身**（`tables[1]`／`[2]`／`[6]` 的 `alphabet_text`，
那是編碼表不是字串）、**1 次在未用槽的解碼雜訊**（`tables[6]` 第 11 條，
`docs/re/17` §1 的不可翻槽）。真正的用例只有三條，而且**全部在字串結尾**：

| 字串 | 出處 |
|---|---|
| `Which way?\r    I\rJ space L\r    K\x08` | 移動方向的十字圖 |
| `P)ool  D)iv cash\x08` | 分錢選單 |
| `Skill points = \x03\x08` | 技能點數（`\x03` 是清到行尾） |

三條都是**多行版面的最後一行**。用 `0x0D` 收尾畫面會多捲一行，
用 `0x08` 就停在原地——與 §3 讀出來的差別完全吻合。

推論等級：**強證據**。整支逐條讀完，而三條語料的位置與機制互相印證；
還沒與實機畫面對拍（要拍到「按了方向鍵之後畫面沒有多捲一行」）。

## 5. 對重製版的意思

`internal/textlayout` 目前把 `0x08` 當成不認識的碼跳過。照這一份要改成：
**結束目前這一行、不換頁、不捲動**。因為三條用例都在字串結尾，
跳過與正確處理的差別只有「後面還會不會多空一行」——
中文化之後行寬改變，這個差別會變得看得見。

Scrollback 本身重製版不必實作（原版也只在 `ds:8DF8h` 開著時才寫），
但**不要把它當成不存在**：`0x0D` 與 `0x08` 都會寫它。

## 7. 這一輪學到的（寫成規則）

- **「語料裡出現 N 次」要扣掉不是字串的那幾次。** 7 次裡有 3 次在字母表
  （編碼表本身也是一串 bytes）、1 次在未用槽的雜訊。
  真正的樣本是 3 條——**先把樣本清乾淨再從樣本推語意**，
  否則會拿雜訊當證據。
- **兩個碼指到同一支函式時，差別在誰包了它。** `0x08` 直接指 `sub_19F12`、
  `0x0D` 指的是包了它的 `sub_19EFC`。看到「這個碼的處理跟那個一樣」
  先確認是同一格還是外面多一層——多的那一層就是它們的差別。
- **追一個未解的碼，會順手掉出別的東西。** 這一輪是 scrollback
  （`seg003:0x8CE0` 的 40 × 256 環形），它跟 `0x08` 沒有直接關係，
  只是剛好在同一支函式裡。**讀完整支比只讀「跟我的問題有關的那幾行」划算。**
