## 1. 入口：清單附加鍵 `0x12` ＝ Ctrl+R

角色畫面的物品頁（`sub_19394`）把清單框架的附加鍵（`ds:470Eh`，
`docs/re/53` §3 的 `0xFE` 那一格）設成 **`0x12` ＝ Ctrl+R**（`0x1948A`）；
表頭字串就是表 2 第 168 條 ` REORDER`。技能清單（`sub_198F0`）同一個鍵。

## 2. 重排迴圈（`0x193AE`）

```
清空 60 bytes 暫存（ds:7931h）；清單只剩表尾 → 不進
存熱區遮罩，換成 0x34（數字＋翻頁＋ESC）
loop：
  sub_19454(0xA8)              ; 表頭換成 ` REORDER`，等玩家選一列
  選到 →
    選中列 ＝ +0x1F → CCEAh ← 這是第幾個被挑走的     ; 裝備索引跟著搬
    選中列 ＝ +0x25 → CCE9h ← 同上（護甲）
    sub_199D9：那一槽 2 bytes 搬進暫存的下一格、原槽清 0
  清單空了（al ＝ 0、CF）→ 收尾
  ESC → 只重畫，**不能中斷**（挑了一半只能挑完）
收尾：還原熱區；+0x1F ← CCEAh；+0x25 ← CCE9h；
      暫存 60 bytes 依序抄回 +0xBD–+0xF8
```

一句話：**照你想要的順序把物品一件一件點走，點完就是新順序**；
裝備中的武器與護甲不管被點到第幾個，裝備索引跟著新位置走。

## 3. 兩個容易寫錯的地方

- **物品的重排不能中斷**：ESC 只是重畫。技能清單那一份不一樣——
  `sub_198F0` 在進迴圈前備份 60 bytes，`0xFF` 且 `dl ＝ 1` 時整包還原
  （`docs/re/92` §3.1）。**兩張清單同一套框架、不同的取消政策。**
- 裝備索引記的是**挑走的順位**（1 起算），收尾直接寫回 `+0x1F`／`+0x25`
  ——因為新順序就是挑走的順序，順位 ＝ 新的清單列號。

remake 的呈現照 `docs/re/131` 的重製決策走訊息視窗；取消政策採技能清單
那一種（ESC 整包還原），因為挑到一半不能反悔在小視窗裡格外容易誤觸。

推論等級：§1、§2 **已確認**（`0x193AE`–`0x19452` 逐指令，`0xA8` 與
字串 168 對上）；「Ctrl+R」是鍵碼 `0x12` 的直譯 **強證據**
（鍵盤層 `sub_18EFE` 對 Ctrl 組合的處理沒逐行讀）。

## 4. 可重跑的完整指令

```bash
python3 - <<'PY'
import json
d=json.load(open('workplace/analysis/dumps/listing.json'))
for x in d['instructions']:
    ea=int(x['ea'],16)
    if 0x19394<=ea<0x1949E: print(x['ea'],x['disasm'])
PY
```

## 5. 這一輪學到的（寫成規則）

- **同一套框架的兩個呼叫端可以有相反的取消政策。** 「這裡不能 ESC」
  不是框架的性質，是呼叫端有沒有先備份的差別——搬行為之前先看
  進迴圈前那三行。
