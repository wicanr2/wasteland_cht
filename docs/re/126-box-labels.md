# 126：框邊上那些標籤（`ESC`、`POOL MONEY`、`ROSTER ON`）

`docs/re/112`（滑鼠熱區）、`docs/re/14` §3（彩色字型）

輸入：`wl.merged.exe`，SHA-256
`cd5b07eaa55f1e1578caa1b05f0bd5331355cd119f387e61b1a8906738e78118`。

實機截圖上，框線中間夾著幾個藍底的小標籤：地圖畫面下緣的 `ROSTER ON`、
設施畫面上緣的 `ESC` 與下面的 `POOL MONEY`、清單右邊的上下箭頭。
它們**不在執行檔的字串表裡**——是一張彩色字型的字模串表，
外加一張「畫在哪、多長、按下去做什麼」的版面表。

---

## 1. 字模串：`ds:CA70h` 起，`0x00` 結束

每一條是一串**彩色字型的字模編號**（不是 ASCII），
編碼與 `sub_17451` 一致：`索引 ＝ (字元 & 0xDF) − 0x29`，空白是 `0x33`。
頭尾各有一個蓋子：`0x17`／`0x16`（左）與 `0x28`／`0x32`（右）。

| 位址 | 內容 |
|---|---|
| `0xCA70`／`0xCA76` | 上箭頭（兩格）|
| `0xCA73`／`0xCA79` | 下箭頭（兩格）|
| `0xCA7C` | `SLOW` |
| `0xCA83` | `FAST` |
| `0xCA8A` | `ESC` |
| `0xCA90` | `NEXT` |
| `0xCA97` | `ESC` |
| `0xCA9D` | `ROSTER OFF` |
| `0xCAAA` | `ROSTER ON` |
| `0xCAB6` | `ENTER` |
| `0xCABE` | **`POOL MONEY`** |
| `0xCACB` | `POOL` |
| `0xCAD2` | `DIVIDE` |
| `0xCADB` | `MAP` |
| `0xCAE1` | `REORDER` |

⚠ **搜尋 ASCII 找不到它們。** 這一族字串在映像裡是字模編號，
`grep POOL` 一筆都不會中，而那與「這個字串不存在」長得一模一樣。
要找就把字串換算成字模編號再搜（`(ch & 0xDF) − 0x29`）。

⚠ **畫出來要記得換色。** overlay slot 19 在 `ds:722Fh` ＝ 0（預設值）時
把 `0x18`–`0x33` 那一段的索引 **＋0x1C** 換成冷色那一組（`docs/re/14` §3），
所以表裡存的是暖色索引、畫面上是藍的。左蓋 `0x17` 落在範圍外**不換**，
右蓋 `0x28` 在範圍內會換——看起來不對稱，但原版存的就是這兩個值。
少了這一步，標籤會畫成紅黃色，而畫面上只是「顏色不太一樣」。

## 2. 版面表：`ds:CBBDh`，17 筆 × 6 bytes

```
+0x00  欄
+0x01  列
+0x02  長度（格數，含頭尾的蓋子）
+0x03  **這個按鈕代表的按鍵**
+0x04  字模串的指標（word）
```

`+0x03` 是按鍵不是編號，逐筆對得上：`ESC` → `0x1B`、`ENTER` → `0x0D`、
`POOL MONEY` 與 `POOL` → `0x50`（`P`）、`DIVIDE` → `0x44`（`D`）、
`SLOW`／`FAST` → `0x3E`／`0x3C`（`>`／`<`）、`ROSTER ON`／`OFF` 與 `MAP` → `0x20`（空白）。
**`P` ＝ 集中金錢**這件事（`docs/re/42`）在這張表上又被印證一次。

逐筆的表由工具倒出來，見
[`generated/ida94/box-labels.md`](generated/ida94/box-labels.md)。要點：

| # | 標籤 | 欄 | 列 | 按鍵 |
|---:|---|---:|---:|---|
| 0–3 | 上下箭頭 ×2 | 39 | 3／10／18／22 | — |
| 6 | `ESC` | 17 | 0 | `0x1B` |
| 8 | `ESC` | 17 | 17 | `0x1B` |
| 9 | `ROSTER OFF` | 15 | 23 | 空白 |
| 10 | `ROSTER ON` | 15 | 17 | 空白 |
| 11 | **`POOL MONEY`** | 21 | 13 | `P` |

三處實機對照：地圖畫面的 `ROSTER ON` 在列 17（`20-map.png`，框的下緣）、
設施畫面的 `ESC` 在列 0、`POOL MONEY` 在列 13（`54-doc-menu.png`）、
清單右邊的箭頭在欄 39（`44-zoom.png`）。

⚠ **`ROSTER ON` 與 `ROSTER OFF` 是兩筆不同的記錄，位置也不同**
（列 17 與列 23）：名單收起來時按鈕在地圖框的下緣，名單開著時在名單框的下緣。
當成「同一個按鈕換字」會畫錯位置。

## 3. 它們同時是滑鼠按鈕

`ds:CAEBh` 起是熱區表（10 bytes 一筆：x1／y1／x2／y2／處理常式），
`0x18860` 那支逐筆比對游標位置，走到 `0xCBBD` 為止。
版面表的 `+0x03` 是動作碼，兩張表配成一組——**標籤畫在哪、點下去做什麼**
是同一份資料的兩面（`docs/re/112`）。

推論等級：§1、§2 **已確認**（表的形狀與三處實機位置互相印證，
`+0x03` 的按鍵值逐筆對得上標籤的字面）；
§3 的兩張表如何配對**未解**（只知道兩者相鄰且 `0x18860` 掃到 `0xCBBD` 為止），
**哪一個畫面畫哪幾筆**也未解——目前是拿實機截圖一張一張認的。

## 5. 這一輪學到的（寫成規則）

- **畫面上讀得到的字，未必是「字串」。** 這一族是字模編號，
  `grep` ASCII 一筆都不中——而那個零命中與「這東西不存在」完全一樣。
  **先問「這段文字是誰畫的」，再決定要用什麼編碼去搜。**
- **版面表的欄位順序用已知位置反推最快。** 六個 byte 裡哪兩個是欄與列，
  拿「右邊那兩個箭頭在欄 39」一比就定了——**先找一筆位置已知的記錄當錨**。
- **剩下的欄位拿語意去對。** `+0x03` 一開始只知道「有一個 byte 每筆都不同」，
  把它與標籤的字面並排（`ESC`→`0x1B`、`POOL`→`0x50`）一眼就看出是按鍵。
  **先把整張表倒出來再解讀欄位，比逐筆猜快得多。**
