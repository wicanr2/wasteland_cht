## 2. 資料模型

### 2.1 地圖

```go
type Map struct {
    Side    int      // D，32 或 64（標頭 +0x2C）
    Section []byte   // 第 1 層，每格一個 nibble（0–15）
    Record  []byte   // 第 2 層，每格 1 byte ＝ 記錄編號
    Graphic []byte   // 第 3 層，每格 1 byte ＝ 圖形編號
    Header  Header   // 記錄區標頭，0x5C bytes
    Raw     []byte   // 原始 bytes，未解區域原樣保留
}
```

三層都是 `Side × Side`，索引一律 `y*Side + x`。第 1 層在檔案裡是一個 byte 兩格
（低 nibble 是偶數格），解碼由 `internal/assets` 負責，規則層拿到的是攤平的陣列。

### 2.2 標頭

規則層會用到的欄位（其餘保留原 bytes）：

| 欄位 | 位移 | 用途 |
|---|---|---|
| `Side` | `+0x2C` | 邊長（32 或 64） |
| `OutsideGraphic` | `+0x33` | 地圖範圍外要畫的圖形編號 |
| `StepTime` | `+0x34`–`+0x35` | 每步的分鐘數 × 256（16-bit） |
| `StepTick` | `+0x36` | 每步的刻 |
| `EncounterDenom` | `+0x2F` | 遭遇機率分母 |
| `EncounterKinds` | `+0x31` | 遭遇種類數 |
| `EncounterSlots` | `+0x32` | 遭遇槽位上限 |
| `TileSet` | `+0x30` | 圖磚組（0–8） |

### 2.3 隊伍位置與視窗原點

**兩個是分開存的**，不要用其中一個推另一個：

```
隊伍座標    ds:46A6h／46A7h
視窗原點    ds:464Eh／464Fh   ＝ 隊伍座標 − (9, 4)
```

視窗是 19 × 9 格，隊伍固定在第 (9, 4) 格，四邊各切半格
（呈現層的幾何在規格 03，規則層只需要維護這兩組座標）。

## 3. 走一步

`Step(dir)`，方向 0 上／1 下／2 左／3 右。**順序照原版，不可重排**：

```
1. 算目標座標           dir → (dx, dy)：上 (0,−1)、下 (0,+1)、左 (−1,0)、右 (+1,0)
2. 四道閘（§3.1）       任何一道擋住 → 整步作廢，時鐘不動、不擲遭遇
3. 更新隊伍座標與視窗原點
4. 推進時鐘（§4）
5. 腳步音效（編號 1）
6. 擲遭遇（§5）
7. 重畫 ＋ 事件分派（§6）
```

⚠ **被擋住時什麼都不推進**——時間、遭遇、事件全都不跑。

### 3.1 四道閘

| 閘 | 判準 |
|---|---|
| 邊界 | `0 ≤ x < Side` 且 `0 ≤ y < Side` |
| nibble | 目標格第 1 層 ＝ **2、3、15** 直接擋住 |
| nibble 10 | 記錄 `+0x00` 的 bit7 ＝ 1 時走詢問流程（見 §6 傳送） |
| 其餘 | 原版還有 `sub_13E9B`／`sub_15CE0` 兩支未讀完 |

**這份清單是下界。** 實作時把「其餘 nibble 一律可通行」寫成明確的預設，
並在遇到與原版不符的地圖時回頭補（驗收條件 §8 有對應項目）。

### 3.1 原地不動的一步

原版的捲動跳表有 **5 筆**，第 5 筆（方向碼 4）是 `clc; retn`（`docs/re/26` §1.1）。
主迴圈用它做「站著不動也會過時間」：

```
IdleStep()
├─ PlayerStepped ← false      ; 這一步不算玩家走的 → 檢定不給經驗值
├─ 時鐘前進（與走一步同一份時間量）
├─ 每 16 刻的體力處理
└─ 遭遇擲骰
   座標不動；**不重跑踩上去的事件**
```

⚠ **不要讓它在閒置時自動跑。** 實機測過：站著不按鍵 45 秒，原版的時鐘
一分鐘都沒走（`docs/re/47` §6.1）——主迴圈在等按鍵時不回頂端。
`IdleStep` 只在**呼叫端明確要求**時跑，不要接在遊戲迴圈的每一幀上。

兩個觸發點都在主迴圈：節拍計數器（`ds:D150h`）滿 `0x400`，
或 `ds:46E1h` 非 0（後者還會播腳步音效 1）。

⚠ **不要把 `PlayerStepped` 順手留成 true。** 站著不動照樣擲遭遇、照樣過時間，
但那樣觸發的檢定**不給經驗值**——這是原版的防刷（規格 07 §3）。

## 4. 時鐘

```go
type Clock struct {
    Frac   uint8   // ds:4658h，分的小數
    Minute uint8   // ds:4659h
    Hour   uint8   // ds:465Ah
    Tick   uint8   // ds:4722h，週期任務用；換地圖歸零
    Total  uint32  // ds:4650h–4652h ＋ ds:722Eh，32-bit 累計，不歸零
}
```

每走一步：

```
frac16 = Frac | Minute<<8
frac16 += StepTime          ; 16-bit 加法，進位自然帶到 Minute
if Minute ≥ 60 { Minute −= 60; Hour++; if Hour ≥ 24 { Hour = 0 } }
Tick  += StepTick
Total += StepTick
if Tick & 0x0F == 0 { 跑週期任務（§4.1） }
```

**分不會一次跳超過 60**（原版只減一次 60），因為 `StepTime` 最大是荒野的 4 分鐘。
照抄這個「只減一次」的寫法，不要寫成 `%= 60`。

晝夜：`Hour < 6 || Hour ≥ 18` ＝ 夜間。晝夜換的是**畫面上的圖形與記錄欄位**，
不影響移動本身。

### 4.1 每 16 刻的體力處理

對隊伍每個人（上限 ＝ 隊伍人數）：

```
CON 兩個 byte 都 0（死亡）        → 跳過
狀態 +0x28 & 0xF0 ≠ 0            → 惡化：Tick & 0x3F == 0 時 CON −1；歸零則設 −1
CON < 0 且 ≥ −10                 → CON +1，再把 +0x26/+0x27 算術右移一位寫回 CON；
                                    歸零補成 1
CON < −10                        → CON −1；**掉破 −50 直接歸零（死亡）**
0 < CON < MAXCON                 → Tick & 0x3F == 0 時 CON +1
                                    （目前選中的角色用 & 0x7F，也就是慢一半）
CON ≥ MAXCON                     → 跳過
```

## 5. 遭遇

```
roll(1..EncounterDenom) == 1 才觸發
掃 section 15 的槽位，+0x03 | +0x05 | +0x07 都是 0 ＝ 空
找到空槽 → +0x03 ← roll(1..EncounterKinds)
           +0x00/+0x01 ← 座標
           方向 ← roll(1..9)
槽位數上限 ＝ EncounterSlots
```

`EncounterDenom` 為 0 時**不擲**（地圖腳本可以把它設成 0 關掉遭遇，
`docs/re/34` op 40）。

## 6. 事件分派

踩上去之後，依目標格第 1 層的 nibble 查 16 筆表。**七個 nibble 什麼都不做**
（0、3、7、11、13、14、15），其餘八個：

| nibble | 行為 | 這一輪要做 |
|---:|---|:-:|
| 1 | 遠看才顯示的描述——**站上去反而不印**（比對隊伍座標） | ✓ |
| 2 | 條件串列（門／鎖／檢定），`+0x0A` 起每 2 bytes 一條 | 規格 06 |
| 4 | 印記錄 `+0x00` 那條訊息 | ✓ |
| 5 | 寶箱：第一次踩到才擲出物品與數量並**寫回記錄** | 規格 05 |
| 6 | 設施（bit7）或腳本指令（44 個 opcode） | 規格 07 |
| 8 | 多選一選單，`+0x03` 起是選項 | ✓（只做選單，動作留給 07） |
| 9 | 印訊息並設旗標 | ✓ |
| 10 | 傳送：讀隊伍槽表 `+0x0B`／`+0x0C` 改寫隊伍座標 | ✓ |
| 12 | 印訊息 | ✓ |

規則層**不印字**——它回傳「要顯示什麼」給呼叫者：

```go
type Event struct {
    Kind    EventKind   // Message / Menu / Teleport / Encounter / …
    Strings []int       // 要印的字串編號（區塊字串表）
    Choices []int       // 選單選項的字串編號
    To      [2]uint8    // 傳送目的地
}
```

## 7. 未解與邊界

- **通行規則是下界**：只確認 2／3／15 擋、10 有條件；`sub_13E9B`／`sub_15CE0`
  兩支還沒讀完。實作先當「其餘可通行」，並記在程式碼註解裡。
- **斜走**：原版程式裡有四個斜走入口，但那張表沒用到（`docs/re/26` §2）。
  remake **不提供斜走**。
- **`ds:4724h`** 那個「非 0 就不重畫」的旗標語意未解，規則層先忽略。
- **選中角色**是誰（體力恢復速度會差一倍）由 UI 決定，規則層收一個索引。

## 8. 驗收條件

0. 原地一步：座標不動、`Moved` 為 false、時鐘前進、`PlayerStepped` 變 false。

**對原版行為驗收，不是只跑單元測試。**

1. 42 張地圖各載入一次，`Side`、三層長度、標頭欄位全部與 `internal/assets`
   解出的一致（已有的 9 個測試涵蓋一部分）。
2. 從出廠存檔的位置 (55, 62)、地圖 0 出發，往四個方向各走 100 步，
   **不得走出邊界、不得踩進 nibble 2／3／15 的格子**。
3. 時鐘：在荒野走 15 步 ＝ 1 小時（每步 4 分鐘）；室內走 240 步 ＝ 1 小時
   （每步 15 秒）。用 `tools/summarize_map_layers.py` 列出的標頭值交叉驗算。
4. `Tick` 每 16 累積跑一次體力處理；健康角色從 CON 1 回到 MAXCON 所需步數
   ＝ `(MAXCON − 1) × 64 / StepTick`。
5. **對拍**：`cmd/wl-shot` 從同一個位置輸出的地圖視窗，與 DOSBox 原版截圖
   逐像素相同。環境已就緒（`tools/dosbox.sh` ＋ `tools/compare_screen.py`），
   標題畫面那一半已經驗完——`TITLE.PIC` **36,864/36,864 吻合**，
   而且位置 (8, 8) 是**掃**出來的，與規格 §2 從程式碼讀出的一致（`docs/re/47` §4）。
   ⚠ 對拍時**位置也要當成待驗的東西**：偏移寫死的話，「解碼錯」與「對錯位置」
   會長得一模一樣。工具會印次佳位置的差距，差距小於一列寬就代表沒對準。
   **地圖視窗那一半也驗完了：0 個不同的像素**（`docs/re/47` §6.4）。
   過程中修掉兩個缺口——隊伍圖示（疊圖編號 7 ＋ `MASKS.WLF` 的 1-bit 遮罩）、
   以及**原版地圖視窗最上面一列留黑**（內容從 `y = 9` 起；圖片視窗沒有這一列）。
6. 存檔 round-trip：走一段路之後寫回存檔，未解欄位 byte-for-byte 不變。
