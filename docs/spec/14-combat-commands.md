## 2. 指令碼

指令碼**不是選單的顯示順序**，是熱鍵字母表 `' ' H A W R E L U` 的索引：

| 碼 | 鍵 | 指令 | 這一份有沒有做 |
|---|---|---|---|
| 0 | `' '` | 沒下令 | ✅（重問） |
| 1 | `H` | Hire | 只保留碼，處理程式未逆向 |
| 2 | `A` | Attack | ✅（要有裝備武器） |
| 3 | `W` | Weapon | 只保留碼 |
| 4 | `R` | Run | ✅ |
| 5 | `E` | Evade | ✅ |
| 6 | `L` | Load/unjam | 只保留碼 |
| 7 | `U` | Use | 只保留碼 |
| 8 | — | 整隊逃跑之後每個人被寫上的碼 | ✅ |

⚠ 選單印的是 `Run / Use / Hire / Evade / Attack / Weapon / Load-unjam`。
**顯示順序與指令碼無關**，中文化改選單文字不會動到規則。

## 3. 一回合的指令階段

```
所有人的指令碼歸零
沒有敵人 → 結束
逐一問每個成員：
    CON ≤ 0（記錄 +0x1D/+0x1E 為 0 或 +0x1E 為負）→ 跳過，不下令
    選指令 → 寫進指令碼；處理程式跑一次 → 回傳值寫進參數
    處理程式回報「重問」→ 這個人再選一次
```

指令碼與參數各是一個「每個成員一格」的陣列，對應原版的 `ds:46D8h`／`ds:46DAh`。

## 4. 迴避

**處理程式是空的。** 迴避不做任何事，效果全在命中門檻那一段：

| 指令碼 | 敵方算命中門檻的基礎值 |
|---|---|
| 5（Evade） | 60 |
| 2（Attack） | 50 |
| 其餘 | 40 |

門檻越高越難被打中（規格 06），所以迴避 > 攻擊 > 其他。

## 5. 逃跑

```
隊伍只有一人 → 直接跑
否則問「Who should run?」：
    取消     → 這個人重問
    Single   → 只有他跑
    Party    → 整隊跑
跑 = 選一個方向（上下左右 ＋ 「不動」共 5 個），然後離開戰鬥回到地圖
```

⚠ **沒有擲骰，也沒有失敗分支。** 逃跑一定成功——不要加成功率。

整隊逃跑會把**每個成員**的指令碼寫成 8、參數寫成那個方向，並結束指令階段。

方向的按鍵有兩組：`I K J L` 與四個方向鍵，**對到同五個方向**。

## 6. 驗收

1. 指令碼照字母表，不照選單顯示順序（拿 `' ' H A W R E L U` 逐字驗）。
2. CON ≤ 0 的成員不會被問到，也不會留下指令碼。
3. 迴避的處理程式不改任何狀態，但門檻基礎值變成 60。
4. 逃跑一定成功；整隊逃跑之後每個人的指令碼都是 8、參數都是同一個方向。
5. 沒有裝備武器的成員選攻擊會被要求重選。
6. 指令階段跑完，每個能行動的成員都有一個指令碼。

## 7. 這份規格**沒有**涵蓋

- Hire／Weapon／Use／Load-unjam 四支處理程式的內容（`docs/re/38` §5）。
- **隊形**——還沒讀到「站位」存在的證據，不要先發明一個。
- 指令碼決定行動之後的完整結算順序（規格 12 只做行動順序）。
