## 2. 存檔容器

存檔是 `GAME1`／`GAME2` **檔尾的一個 MSQ 資源**：

```
game1 0x000253C5    game2 0x00028BC7      ← seek 是 cx:dx，32-bit
+0x00   magic 'msq0'（game1）／'msq1'（game2）
+0x04   checksum（16-bit）
+0x06   0x800 加密段 ＝ 8 × 256 bytes
+0x806  0xA00 未加密段 ＝ **十組按鍵巨集**（10 × 256，出廠全零）
```

- 解密：`key = lo(checksum) ^ hi(checksum)`，逐 byte XOR 後 `key += 0x1F`。
- **checksum ＝ 0 − Σ 明文位元組（16-bit）**。改寫內容後**一定要重算**。
- 兩份輪替：載入時比 32-bit 序號（全域 `+0xF5`），**留大的那一份**。

### 2.1 改寫不是重建

`CLAUDE.md` §4 的硬規則：從原始 bytes 出發，**只蓋已解欄位，未解區域一個 byte 都不動**。
所以資料結構要保留整份明文，寫回時就地修改。

驗收：讀出再寫回，**整個檔案 byte-for-byte 相同**。

## 3. 第 0 筆：全域狀態

| 位移 | 大小 | 內容 |
|---|---|---|
| `+0x00`／`+0x0E`／`+0x1C`／`+0x2A` | 4 × 14 | **四組隊伍槽表**（§3.1） |
| `+0x78`–`+0x85` | 14 | `ds:464Eh`–`465Bh`：視窗原點、32-bit 累計、目前地圖、隊伍人數、時鐘 |
| `+0xD0` | 13 | **地點名稱**（明文 ASCII，出廠 `Ranger Ctr. `）＝ 記憶體的 `ds:7201h` |
| `+0xF5` | 4 | **32-bit 存檔序號** |
| `+0xFE` | 1 | 彩色字型選色（`ds:722Fh`） |

全域記錄載到記憶體 `0x7131`，所以**全域 `+N` 就是 `ds:(0x7131 + N)`**；
例外是 `+0x78` 那 14 bytes，它們是 `ds:464Eh`–`465Bh` 的副本。

其餘出廠為零、語意未解——**原樣保留**。

`+0x78` 那 14 bytes 的細部（`docs/re/27` §7、`docs/re/30` §3）：

| 相對位移 | `ds:` | 內容 |
|---:|---|---|
| 0 / 1 | `464E`／`464F` | 視窗原點 X／Y |
| 2–4 | `4650`–`4652` | 32-bit 累計時間的低三個 byte |
| 5 | `4653` | 隊伍人數 |
| 7 | `4655` | 目前地圖 |
| 8 | `4656` | 隊伍人數（第二個，與 `4653` 出廠相同，差別未解） |
| 10 | `4658` | 分的小數 |
| 11 | `4659` | 分 |
| 12 | `465A` | 時 |

### 3.1 隊伍槽表（每組 14 bytes）

| 位移 | 內容 |
|---|---|
| `+0x00`–`+0x07` | 成員的**角色記錄編號**（0 ＝ 空槽，最多 8 人） |
| `+0x08`／`+0x09` | 隊伍在地圖上的座標 X／Y |
| `+0x0A` | 目前地圖的資源編號 |
| `+0x0B`／`+0x0C`／`+0x0D` | **回程**的座標與地圖編號（nibble 10 踩上去時寫入，不是目的地——`re/60` §3） |
| `+0x0D` | 未解 |

四組的位移 `00 0E 1C 2A` 直接寫在執行檔的 `ds:B239h`。

## 4. 角色記錄（256 bytes）

記憶體位址 ＝ `0x7131 ＋ 編號 × 256`；存檔裡就是第 1–7 筆。

| 位移 | 大小 | 欄位 | 備註 |
|---|---|---|---|
| `+0x00` | 字串 | **名字** | NUL 結尾 |
| `+0x0E`–`+0x14` | 7 | **屬性** | Strength／IQ／Luck／Speed／Agility／Dexterity／Charisma |
| `+0x15`–`+0x17` | 24-bit | **金錢** | 只有「先比大小再扣」的路徑 |
| `+0x18` | 1 | 性別 | 0 ＝ Male、1 ＝ Female |
| `+0x19` | 1 | 國籍 | 0–4 |
| `+0x1A` | 1 | AC | |
| `+0x1B`–`+0x1C` | 16-bit | MAXCON | |
| `+0x1D`–`+0x1E` | 16-bit 有號 | **CON** | 可為負 |
| `+0x1F` | 1 | 裝備索引 | `×2 ＋ 0xBC` 指進物品陣列 |
| `+0x20` | 1 | **技能點** | 建立時 ＝ IQ；每升一級 ＋1（飽和 255） |
| `+0x21`–`+0x23` | 24-bit | **經驗值** | 累計、升級不扣、飽和 `0xFFFFFF` |
| `+0x24` | 1 | **等級** | 建立時 1 |
| `+0x26`–`+0x27` | 16-bit | 受傷前的 CON 備份 | |
| `+0x28` | 1 | **狀態位元** | 八個疾病旗標 |
| `+0x32`… | 字串 | 階級名 | 建立時 `PRIVATE` |
| `+0x80`–`+0xBB` | 30 × 2 | **技能** | 偶數位移 ＝ 編號（1–36）、奇數 ＝ 等級 |
| `+0xBD`–`+0xF8` | 30 × 2 | **物品** | 奇數位移 ＝ 編號、偶數 ＝ 附屬 byte |

⚠ 兩個陣列的迴圈邊界在原版就不一致：搜尋技能掃 `0x80`–`0xBA`（30 槽），
顯示掃到 `0xBC`（多一槽，已經踩到物品陣列前一個 byte）。**照抄，不要「修正」。**

⚠ 物品的附屬 byte **低 6 位是剩餘次數**，用完會把整個槽移除（`docs/re/32` §6）。

### 4.1 衍生規則

| 規則 | 公式 |
|---|---|
| 升到等級 L 需要的累計經驗值 | `(L² − L) × 512` |
| 等級 → 階級編號 | `ds:D522h[等級]`，50 階對到等級 1–131 |
| 學技能到等級 L 的費用 | `基礎費用 × 2^(L−1)`，飽和 `0xFF` |
| 學技能的 IQ 需求 | 技能資料 `+0x00 >> 3` |
| 傷勢等級 | CON 對 `−11 / −20 / −30 / −40` 分五級，CON ＝ 0 是死亡 |

## 5. 未解與邊界

- **`0xA00` 未加密段 ＝ 十組按鍵巨集**（`docs/re/30` §6）：每組 256 bytes，
  對應規格 20 §5.2 的 F1–F10。⚠ **它不進 checksum**——改它不會讓存檔被拒收，
  但照樣要 round-trip。
  **原樣搬運，不解讀。**
- 全域狀態除了上表的欄位外，其餘 bytes 未解。
- `ds:4653h` 與 `ds:4656h` 都像隊伍人數，出廠都是 4，分不出差別。
  規則層兩個都讀進來、都寫回去，不要合併成一個欄位。
- 角色記錄有 127 處存取的位移是算出來的，追不到——**欄位表是下界**。

## 6. 驗收條件

1. **round-trip**：`game1`／`game2` 各讀出再寫回，**整個檔案 byte-for-byte 相同**。
2. checksum 重算的結果與原檔相同。
3. 出廠的四個 Ranger 解出來要對得上：名字 `Hell Razor`／`Angela Deth`／`Thrasher`／
   `Snake Vargas`、七個屬性都在 3–18、MAXCON ＝ CON、階級 `Private`、等級 1。
4. 隊伍槽表：第 0 組有四個成員（記錄 1–4）、座標 (55, 62)、地圖 0；其餘三組全空。
5. 改一個已解欄位（例如金錢）再寫回，**只有那三個 byte 與 checksum 變動**。
6. 兩份輪替：序號大的那份被選中（`game1` 是 20、`game2` 是 0）。
