## 2. 命中判定

兩條路徑共用一個累加器（原版是 `ds:46C0h`）。**累加的永遠是「隊伍成員的本事」**，
方向隨攻守翻轉：

```
累加值 = 基礎值
       + 隊伍成員的 Brawling（技能 1）等級 × 3
       + 隊伍成員的 Agility
       − 對手的行動值（敵人資料 +0x02）
         └ 對手武器類別 ＝ 1（近戰）→ 行動值先做 8-bit ×4；否則累加值另加 5
       夾在 100

隊伍攻擊：命中 ⟺ roll(1..100) <  累加值      基礎 50 或 60
敵方攻擊：命中 ⟺ roll(1..100) ≥  累加值      基礎 40、50 或 60
```

⚠ **技能編號寫死是 1**，不是「拿什麼武器就用什麼技能」——
`sub_1B0F1` 的第一條指令就是 `mov al, 1`（`docs/re/88` §2）。
⚠ **×4 是 8-bit 位移**，行動值 64 以上會繞回（出貨資料最大 20，碰不到）。

基礎值：

| 路徑 | 來源 | 狀態 |
|---|---|---|
| 敵方打隊伍 | `[ds:46D8h + 目標]` ＝ **被打者這回合的指令**：迴避 60、攻擊 50、其餘 40 | 已確認 |
| 隊伍打敵方 | `ds:711Dh[目標的敵方記錄編號]` ＝ **目標這回合的移動計畫**：`0xFF`（不移動）→ 50，否則 60 | 已確認（`docs/re/101`）|

⚠ **會移動的敵人比較好打。** 隊伍那條是 `roll < 累加值` 才命中，60 比 50 容易打中。

⚠ remake 沒有實作敵人在地圖上移動（`docs/re/87` §2），
所以計畫永遠是「不移動」，基礎值實際上一律是 **50**。
接法是把計畫放進 `game.Battle.MovePlan`（`NoMovePlan` ＝ `-1`）、
基礎值由 `game.HitBase(plan)` 算——**不是把常數改成 50**，
這樣移動實作出來的那天 60 那一支會自己亮起來。

## 3. 傷害：兩邊算法不同

### 3.1 敵方打隊伍

```
傷害 = 攻擊資料 +0x05 的高 4 位  +  (攻擊資料 +0x03) 顆 d6
```

攻擊資料表在**記錄區標頭 `+0x04`**，8 bytes 一筆（不是物品表）。

### 3.2 隊伍打敵方——沒有骰

```
傷害 = 距離項                       （未定，實作先當 0 並標成暫代）
     + 裝備武器的技能等級 × 3
     + Dexterity 修正
     + Strength 修正
     + Luck 修正
```

**屬性 → 修正值階梯**（三個修正共用）：

```
屬性 > 13 → (屬性 − 12) >> 1
屬性 < 9  → −((9 − 屬性 + 1) >> 1)
9 ≤ 屬性 ≤ 13 → 0                    ← 死區
```

所有加法都是 16-bit 飽和加（借位夾 0、進位夾 `0xFFFF`）。

## 4. 護甲與結算

**兩邊的護甲機制一樣**：吸收 ＝ N 顆 d6 的和。
角色的 N 來自記錄 `+0x1A`（AC），敵方的來自攻擊資料。

```
實際傷害 = max(0, 傷害 − 吸收)
```

**血量的處理不對稱**：

| | 位置 | 死亡 | 可否為負 |
|---|---|---|---|
| 角色 | 記錄 `+0x1D`（16-bit 有號） | CON ＝ 0 | **可以**，負得越多傷勢越重 |
| 敵人 | `ds:46C8h ＋ 編號×2`（16-bit） | HP ＝ 0 | 不行，減到 ≤0 夾成 0 |

角色扣血時要先把扣血前的 CON 存進 `+0x26`／`+0x27`（自然恢復會用到）。

傷勢等級（`sub_19A1D`，逐值對照見 `docs/re/15` §3）——**索引就是等級**：

| 等級 | CON | 狀態字 |
|---:|---|---|
| 0 | −1 … −10 | `UNC`（昏迷，還救得回來）|
| 1 | −11 … −19 | `SER` |
| 2 | −20 … −29 | `CRT` |
| 3 | −30 … −39 | `MRT` |
| 4 | ≤ −40 | `COM` |
| 5 | **恰為 0** | 骷髏字模（原版主文字字型第 `0x7F` 格）|

⚠ **等級 0 是昏迷不是「沒事」**：這一支只在角色倒下時被呼叫，CON 為正的人
不查它。把 0 當成「健康」會讓死亡（5）與昏迷（0）在名單上對調。

⚠ **`0x7F` 不是 DEL**：中文畫面的半形字型那一格是別的圖形，
所以呈現層要把它送回原版 8 × 8 字模（`TestDeathGlyphComesFromOriginalFont`）。

## 5. 擊殺與經驗值

```
擊殺經驗值 = 攻擊資料 +0x00/+0x01（16-bit） × ((+0x04 的低 4 位) + 1)
```

加到角色記錄 `+0x21`–`+0x23`，**溢位飽和在 `0xFFFFFF`**。
升級檢查另外跑（規格 05 §4.1）。

## 3.1 物品資料表

隊伍這一邊的傷害要查物品資料表（`docs/re/45`）。**表在存檔區、每個存檔槽一份**，
所以它是可變狀態：賣東西改到的庫存欄位要跟著存回去。

| 位移 | 用在哪 |
|---|---|
| `+0x03 >> 3` | 類別（1 近戰、2–13 有射程的武器、14 彈藥、15 護甲、16–18 非戰鬥） |
| `+0x04` | 容量（裝滿時的次數；槍是彈匣） |
| `+0x05` | 技能編號——`§4` 第二項要用的就是它，**不由呼叫端自己猜** |
| `+0x06` | 骰數：武器 ＝ 傷害 Nd6、護甲 ＝ AC |
| `+0x07` | 要用的彈藥物品編號 |

裝備（`sub_1949E`）：類別 15 寫護甲槽並把 `+0x06` 搬進記錄 `+0x1A`（AC），
其餘寫武器槽；再選一次同一個槽 ＝ 卸下。

### 隊伍傷害的第一項

```
顆數 = 武器 +0x06
若 類別 ∈ {8, 9}（反戰車）且 顆數 ≥ x：顆數 = 2 × 顆數 − x（飽和 255）
第一項 = 0 + 顆數 顆 d6
```

`x` 由呼叫端給：主攻擊路徑是 **0**，另一條路是敵人資料 `+0x04` 的低 4 位。
**這一項會擲骰，另外四項不會**——不要為了好算換成期望值。

## 6. 未解與邊界

- `x` 在投擲爆裂物那條路（`0x12E40`）上是什麼，未解。
- 移動計畫的三條分支（換位置／逃跑／逼近）由 `sub_19D2F` 與 `loc_12AA2`
  的兩個判斷決定，那兩支未解（`docs/re/101` §6）。**不擋這份規格**：
  remake 不模擬地圖移動，三條分支一條都走不到。
- 回合結構、逃跑、隊形都還沒讀。這份規格只涵蓋**單次攻擊的結算**。
- `sub_1B108` 裡的「欄位值」與距離修正的細節只到形狀，沒到語意。

## 7. 驗收條件

1. 屬性修正的階梯：3–18 逐值比對手算的表，死區 9–13 必須是 0。
2. 飽和加法：加到超過 `0xFFFF` 夾住、減到負的夾 0。
3. 護甲吸收 ＝ N 顆 d6：固定 RNG 跑 10,000 次，平均落在 3.5N 附近。
4. 角色扣血：CON 可為負、`+0x26` 有記到扣血前的值、傷勢等級門檻正確。
5. 敵人扣血：HP 減到 ≤0 夾成 0，不得為負。
6. 擊殺經驗值：用出廠角色與一組手算的攻擊資料驗算，並確認飽和。
7. 命中判定：同一組輸入下，隊伍側與敵方側的比較方向相反。
8. 類別 ＝ `+0x03` **右移三次**。移四次的話 RPG-7（`0x49`）會變成 4，
   看起來還「像個步槍類別」——測試要釘死這一位。
9. 反戰車武器：`x ＝ 0` 時顆數加倍、`x` 大於顆數時用原值、`2N` 超過 255 要飽和。
10. 隨機項的驗收看**平均**（N 顆 d6 ≈ 3.5N），不要看「有沒有擲出全 6」——
    五顆全 6 是 1/7776，兩萬次也可能漏掉，那會變成偶爾紅一次的測試。
