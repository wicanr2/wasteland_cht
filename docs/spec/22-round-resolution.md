## 2. 一回合的順序

```
指令階段（規格 14）問完全部能行動的人
        │
        ▼
BeginRound：算行動值、排序（規格 12）
        │
        ▼
依序輪到每個行動者：
    隊伍成員 → 依他這一回合的指令做事
    敵人     → 攻擊隊伍裡還能行動的人
        │
        ▼
Over()？ → 是：結束；否：回到指令階段
```

⚠ **指令是「這一回合」的**，不是持續狀態。下一回合重問。

## 3. 一次攻擊

```
命中 ← d100 對累加值（隊伍要 <、敵方要 ≥）
未命中 → 訊息「… misses.」
命中：
    傷害 ← 攻擊方的公式（隊伍走武器骰、敵方走基底 ＋ Nd6）
    吸收 ← 防守方 AC 顆 d6
    實傷 ← max(0, 傷害 − 吸收)
    訊息「hits … for N」
    死了 → 訊息「… died!」＋ 給攻擊者經驗值
```

⚠ **吸收要在扣血之前算，而且吸收滿了不是「沒打到」**——
原版照樣印命中訊息，只是傷害是 0（`re/19` §4）。

## 4. Go 介面

```go
// internal/play

// RoundResult 是一回合結算完的結果。
type RoundResult struct {
    Lines []string // 這一回合的訊息，照發生順序
    Over  bool     // 戰鬥結束了
    Won   bool     // 隊伍贏了（Over 為 true 才有意義）
}

// ResolveRound 把指令階段的結果跑完一回合。
func (s *CombatScene) ResolveRound() RoundResult
```

## 5. 未解與邊界

- **武器與距離還沒接**。命中累加值要武器技能與射程，裝備欄的解讀
  （規格 06 §未解）還沒到能自動判斷的程度，所以這一版用
  `Character.Weapon`（已裝備的物品資料）＋ 距離 0，**並在筆記裡標明是暫代**。
- **敵方的目標選擇**用「還能行動的人裡隨機一個」。原版走 `sub_15036`
  的目標表（`re/51` §8 只讀到頂層形狀），**不假裝已經解了**。
- Evade／Use／Hire／Load 四個指令**這一版只影響防禦值**（規格 14 已解的部分），
  其餘效果未解，照原樣不做事而不是猜。
- 逃跑走規格 14 的既有路徑，不在這一份重做。

## 6. 驗收條件

1. **順序**：固定亂數種子跑一回合，行動順序與 `Battle.Order()` 完全一致。
2. **吸收**：AC 很高的目標會出現「命中但傷害 0」，而且訊息是命中不是未命中。
3. **經驗值**：打死一個敵人，攻擊者的 XP 增加量等於 `EnemyData.KillXP()`。
4. **結束**：敵人全部死掉 → `Over && Won`；隊伍全部倒下 → `Over && !Won`。
5. **回合上限**：不會無限跑（`game.MaxRounds`）。
