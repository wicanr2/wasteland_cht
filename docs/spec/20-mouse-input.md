# 規格 20：滑鼠輸入與每列熱鍵

狀態：**READY**

[`docs/re/25`](../re/25-screen-layout.md)（畫面版面）、
[`docs/re/38`](../re/38-combat-commands-and-flee.md) §2（戰鬥指令熱鍵表）。

## 1. 模型

原版沒有「滑鼠事件」這種東西。滑鼠只做一件事：**把游標位置換成一個按鍵碼**，
換好之後整個遊戲照樣只看鍵盤（`sub_18EFE` 先問滑鼠、問不到才 `int 16h`）。

重製版照抄這個形狀。呈現層拿到點擊之後呼叫

```go
key, ok := input.Click(x, y, screen)
```

換出鍵碼再餵進既有的鍵盤路徑，**規則層完全不知道有滑鼠**。

## 2. 熱區表

21 塊，順序就是優先序：**第一個同時「遮罩有開」且「座標命中」的區域決定結果**，
命中之後不再往後找，即使那一塊算不出鍵碼也一樣（回傳「這一下不算按鍵」）。
座標是原版的 320 × 200 畫布，**邊界含端點**。

| # | 區域 | 算法 |
|---:|---|---|
| 0 | 隊伍名單 | 列 ＝ `(y−0x7D)>>3 ＋ 1`，超過隊伍人數不算；送 `'0'＋列` |
| 1 | 地圖視窗 | 兩組對角線切四個象限 → `I`／`K`／`J`／`L`；中央 16 × 16 送 ESC |
| 2 | 訊息視窗 | 列 ＝ `(y−5)>>3`，查每列熱鍵表；那一列沒登記就不算按鍵 |
| 3 | 底列 | 送 Enter |
| 4–20 | 邊上的固定按鈕 | 各自送一個固定鍵（方向、`<`／`>`、ESC、空白、`P`、`D`…） |

完整座標與鍵值在 `internal/input/mouse.go` 的 `Regions`，值取自
`ds:0CAEBh`（熱區）與 `ds:0CBBDh`（固定鍵）兩張表。

## 3. 遮罩

每個等待輸入的畫面在等之前設一個 32 位元遮罩（原版 `ds:7DF3h` 低 16 位 ＋
`ds:7DF5h` 高 16 位），第 *i* 位對應第 *i* 塊熱區。**遮罩是 0 就完全不收滑鼠。**

這是「戰鬥選單時點地圖沒反應」的機制——不是座標判斷，是那一位沒開。
已知的幾組：戰鬥指令用 `0x0404`、`sub_125BD` 的挑人畫面用 `0x1002`、
`sub_13AE4` 的物品畫面用 `0x0434`。

## 4. 每列熱鍵表

25 格，對應訊息視窗的列（視窗只有 12 列，表比視窗高，所以捲動不必特判邊界）。

| 動作 | 對應 |
|---|---|
| `RowHotkeys.Clear()` | 控制碼 `\x11` |
| `RowHotkeys.Set(列, 字元)` | 控制碼 `\x10`（列號 1 起算） |
| `RowHotkeys.Scroll()` | 文字視窗捲一行 |

## 5. 對翻譯的約束

`\x10` 後面那個字元同時是**畫面上的第一個字**與**點擊該列送出的鍵**，
所以翻譯不能動它。規則與編譯期檢查寫在
[`規格 11`](11-translation-catalogue.md) §5。

## 6. 驗收條件

1. 訊息視窗：`\x10Y` 登記在第 1 列之後，點 y ∈ [5, 12] 得到 `'Y'`、
   點沒登記的列得到「不算按鍵」。
2. 遮罩為 0 時任何座標都不產生按鍵。
3. 熱區重疊處（地圖視窗與訊息視窗在 x 104–280、y 8–100 重疊）由**地圖視窗**贏。
4. 地圖視窗四個象限各得到 `I`／`K`／`J`／`L`，中央小框得到 ESC；
   `EscAsSpace` 打開時中央改送空白。
5. 隊伍名單超過隊伍人數的列不產生按鍵。
6. 捲動一次之後第 2 列的熱鍵移到第 1 列，最後一格補 0。

## 7. 還沒解的

- 打字型密語（`BIRD`、`DIPSTICK`）的比對程式碼還沒定位（`docs/re/43` §7）。
  **不影響本規格**：那條路走鍵盤，與熱區無關。
- 固定按鈕表 `ds:0CBBDh` 的 `+0x00`／`+0x01`／`+0x02` 與 `+0x04`／`+0x05`
  （疑似欄列與標籤指標）還沒對上，目前只用到 `+0x03` 的鍵值。
