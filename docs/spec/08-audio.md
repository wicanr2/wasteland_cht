# 規格 08：音效

狀態：**READY**

依據：[`docs/re/44`](../re/44-audio.md)（直譯器、聲部結構、位元組碼、九首資料）。
資料由 `tools/summarize_sfx.py` 從 `seg005` 倒出，不需要 IDA。

---

## 1. 模型

原版是一台跑在計時器中斷上的位元組碼直譯器，輸出到 PC 喇叭。重製版照抄這個形狀：

```
內部：tick(126.36 Hz) → 四個聲部各推進一步 → 仲裁出一個聲部 → 一個 8253 除數
外部：把「除數 ＋ 開關」變成聲音（方波合成，取樣率由呈現層決定）
```

**規則層只呼叫 `Play(n)`**，其餘全在音效層。`internal/game` 不認識聲音。

## 2. 為什麼不混音

PC 喇叭一次只發得出一個音。原版四個聲部的意義是「同時排隊的序列」，
每個 tick **挑第一個還在發聲的**（編號小的優先），不是四個疊在一起。

⚠ **照抄這個仲裁**。把四個聲部混起來會比原版「豐富」，但那是另一個遊戲的聲音。

## 3. 聲部狀態

`docs/re/44` §3 的 19 個欄位照搬。實作用具名欄位而不是 `[0x2E]byte`——
位元組碼是用**位移**定址的，所以要留一張「位移 → 欄位」的對照表，
`0xFF`／`0xFE` 指令查它。**位移不在表裡就是未解的欄位，寫進去但不影響輸出。**

## 4. 每個 tick

照 `docs/re/44` §3.1 的順序，一步都不能換：

1. 時值為 0 → 這個聲部跳過
2. 閘控 `+= 閘控增量`
3. 頻率除數 `+= 滑音增量`
4. 顫音：相位 `+=` 增量、環繞、`(相位 >> 4) + 波表基底` 取一個 byte 當**高位元組** × 深度
5. 輸出除數 ＝ 顫音偏移 ＋ 頻率除數
6. 時值 == 封套門檻 → 封套位移 ← `0x10`、步進倒數 ← 1
7. 時值 `-= 1`；歸零 → 解下一批位元組碼
8. 封套步進倒數 `-= 1`；歸零 → 讀下一段封套

## 5. 位元組碼

| opcode | 形狀 | 語意 |
|---|---|---|
| `0xFF` | `FF <欄位> <u16>` | 設欄位。欄位 ≠ 0 繼續解；**欄位 == 0 結束這一批** |
| `0xFE` | `FE <欄位> <u16 位址>` | 計數器為 0 → 無條件跳；否則減 1，非零才跳 |
| `0xFD` | `FD <u16 位址>` | 換寫入基底（讓這個序列去設定別的聲部） |
| 其餘 | `<聲部×音長> <音高>` | 見 §5.1 |

### 5.1 音符

```
聲部 = op >> 5
音長索引 = op & 0x1F
時值 = 音長表[索引] × (聲部.音長倍率 或 1)
音高 = 下一個 byte & 0x7F，加上聲部的移調
    除數 = 半音表[音高 % 12] >> (音高 / 12)
下一個 byte 的 bit7 = 還有下一個音符
```

⚠ **音長索引 0–19 才在表內**（`docs/re/44` §5）。20–31 在原版會讀到全域變數。
重製版**照樣接受 0–31**，超出範圍回時值 0（該聲部靜音）並記一筆——
不要夾住成 19，那會讓一首本來會停的音效變成一直響。

## 6. 資料

九首，全部在 `seg005`。重製版從**原版執行檔**讀（玩家自備），
不另外散布——與其他原版素材一致（`CLAUDE.md` §7）。

| 表 | `seg005` 位移 | 形狀 |
|---|---|---|
| 半音表 | `0x0174` | 12 × u16 除數（最低八度 C1 ＝ 32.70 Hz） |
| 音效表 | `0x0192` | 9 × 4 × u16（音效 → 四個聲部的起點；0 ＝ 這個聲部不參與） |
| 音長表 | `0x01DB` | 20 × u8 |
| 位元組碼 | `0x01F2` | 到 `seg005` 結尾 |

## 7. 觸發

`Play(n)` 照 `sub_1CBD3`：把該音效四個聲部的起點各自寫進聲部、
**清掉整個結構**、時值設 1（下一個 tick 就開始解）。起點為 0 的聲部不動。

觸發點是全檔掃出來的（`docs/re/44` §6.1），不是猜的：出貨的執行檔裡
只有五個直接呼叫點——1 ＝ 走一步、2 ＝ `0x16B7C`、4 ＝ 升級、5 ＝ `sub_11438`、
7 ＝ 消耗物品與地圖腳本 op 26／35。**0／3／6／8 沒有呼叫端。**

- 音效 0（全部靜音）**重製版要留著**：它是關掉音效 6 的唯一方式。
- 3／6／8 照樣實作。原版沒接上不代表資料是壞的，
  而重製版不得替它們發明觸發時機（`CLAUDE.md` §5：不發明遊戲規則）。
- 編號一律**由呼叫端傳**，音效層不猜。

## 8. 驗收條件

1. 長度要對得上原版資料：八首自己會停，tick 數分別是
   0 ＝ 1、1 ＝ 5、2 ＝ 3、3 ＝ 71、4 ＝ 225、5 ＝ 121、7 ＝ 109、8 ＝ 161；
   **音效 6 永遠不停**（跑回開頭重來），只有 `Play(0)` 關得掉。
   測試要抓到「跳回開頭」而不只是「還在跑」——後者和失控分不出來。
2. 音高表**照原樣用**：十一個半音在 12-TET 的 ±0.12 音分內，
   **E 是 −2.91 音分（原始資料的錯字，`docs/re/44` §5）**。
   測試要同時擋住兩件事：把 E 修正掉，以及改用公式算頻率。
3. 音效 4 解出來的音序是 F3 F3 F3 F3 C3 F3 C4——那是唯一一首旋律，
   而且與 `docs/re/31` 的「升級播音效 4」對得上。
4. 仲裁：兩個聲部同時發聲時，輸出的是編號小的那一個。
5. 音長索引 ≥ 20 回時值 0，不夾住。
6. **沒有原版執行檔時整個音效關掉，遊戲照跑**（與翻譯目錄、字型一致）。

## 9. 這份規格**沒有**涵蓋

- 方波→取樣的合成細節（呈現層的事；`internal/audio` 只吐「除數 ＋ 開關」的時間序列）。
- 音效 3／6／8 該在什麼時候播。原版沒接上，重製版也不發明。
- 音樂。**原版沒有音樂**——`seg005` 裡就這九首，沒有別的音訊資料。
