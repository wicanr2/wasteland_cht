## 2. 共同形狀

```
檢查前提 → 不成立就留一句訊息、回報「重問」
成立就叫出一個選單 → 回傳選擇（＝ 指令的參數）
```

⚠ **處理程式不執行動作。** 換武器沒有真的換、裝填沒有真的填——
只記下「選了什麼」，動作在結算階段。與迴避（處理程式是空的）同一套設計。
**不要在這一層做任何狀態變更**，Use 寫的那一格除外（§5）。

## 3. Weapon

```
物品陣列裡一件都沒有 → 訊息「You don't have anything.」，重問
否則 → 開物品清單，回傳選中的槽
```

物品陣列 ＝ 角色記錄 `+0xBD` 起、**30 槽、stride 2**，值為 0 表示空槽。

## 4. Hire

### 4.1 指令階段

```
候選 ＝ 這場遭遇裡「還有敵人」的組（loc_1382B）
候選 0 → 訊息「No one is within range.」，重問
否則 → 開清單（標題 ＝ 字串 63「Which group?」），回傳選中的組號
取消（原版回 0xFF）→ 重問
```

⚠ **候選數不看「能不能雇用」**（`loc_1382B` 只數「數量欄非 0」的組）。
把篩選提前會讓「按下去才發現不能雇用」這個原版行為消失。

### 4.2 結算階段（`docs/re/110`）

順序固定，**不要重排**：

```
1. 隊伍已經 7 人      → 字串 95「No room in roster.」，結束（連骰都不擲）
2. 遭遇記錄 +0x09     → bit1 沒設、或高 4 位是 0 → 失敗
3. section 17 取第「高 4 位」筆記錄 ＝ 那個 NPC（完整的 256 byte 角色記錄）
4. NPC 記錄 +0x31 ＝ 0 → 直接成功（不檢定）
5. 否則擲骰：< 5 → 失敗
6. 招募者 (魅力＋智力)/2 ＋ 魅力 ＋ 等級 ＋ 骰  ≥
   NPC   (魅力＋智力)/2 ＋ +0x31 ＋ 等級        → 成功
成功：整筆 256 bytes 抄進隊伍的下一個記錄槽、槽表補一格、
      NPC 記錄 +0x31 ← 招募者的魅力、印 +0x30 那條字串、那一組從戰場移除
失敗：印字串 44「⟨名字⟩ tries to hire 」＋ 組名 ＋ 字串 81「 but fails.」
```

骰是**長度可變的**（`sub_19C84`）：擲一顆當基準，再擲一顆累加，
**兩顆同點就換新基準繼續**，不同點才停。所以值域從 3 起跳，不會是 2。

⚠ **魅力在招募者那一側算兩次**（平均裡一次、單獨再加一次）。
官方手冊那句「你想雇用 NPC 時，他的反應也看這一項」講的就是它。

⚠ 存檔要**先把整筆記錄原樣寫下去、再蓋已解欄位**——
少了第一步，新隊員的未解區域會是上一個佔用那一格的人留下的殘骸。

## 5. Load／unjam

三道檢查，順序固定：

| 檢查 | 不過的結果 |
|---|---|
| 有沒有裝備武器 | **靜靜結束，不印訊息** |
| 這把武器吃不吃彈匣 | 訊息「…'s weapon can't be reloaded.」，重問 |
| 物品陣列裡有沒有對應的彈匣 | 訊息「… has no more clips.」，重問 |

三道都過就接受這個指令。

## 6. Use

先選「物品／技能／屬性」，選完把一個 byte 寫進**每個角色一格**的陣列
（原版是 `ds:A9FDh + 角色編號`），然後把畫面切回地圖。

⚠ **索引是角色編號不是隊伍位置**——同一個角色換到別的隊伍位置，這一格跟著他。
那個 byte 的欄位配置（哪幾個 bit 是類別、哪幾個是編號）**還沒逆向**，
所以這一層只負責存放與取出，不解釋內容。

## 7. 驗收

1. 四支都不改任何狀態（Use 寫的那一格除外）。
2. 前提不成立時回報「重問」，而且游標不前進。
3. Weapon：空手時不開選單；有東西時回傳的是槽編號。
4. 物品陣列的數與找都只認 `+0xBD` 起 30 槽、stride 2，值 0 是空槽。
5. Load 的三道檢查照順序；沒裝備那一道**不留訊息**（其餘兩道會）。
6. Use 的那一格以角色編號為索引；換隊伍位置不影響。

## 8. 這份規格**沒有**涵蓋

- 物品清單選單的回傳值編碼（`sub_19394`）。
- Use 選完之後三條分派各自做什麼。
- `ds:A9FDh` 那個 byte 的欄位配置。
