## 2. 敵人資料表

每張地圖一張，位址寫在記錄區標頭 `P+0x04`／`P+0x05`，**8 bytes 一筆**，
索引 ＝ 地圖記錄裡的敵人型別。

| 位移 | 內容 |
|---|---|
| `+0x00`／`+0x01` | 16-bit 基礎值：**生怪時是基礎血量、擊殺時是經驗值基值** |
| `+0x02` | 行動值欄位（規格 12 的 `speedOf`；也被命中門檻減去） |
| `+0x03` | 傷害骰數 N |
| `+0x04` 低 4 位 | 經驗值倍數 −1 |
| `+0x05` 高 4 位 | 傷害基底 |
| `+0x04` 高 4 位、`+0x06`、`+0x07` | **未解**，原樣保留 |

**第 0 筆恆為全零 ＝ 沒有敵人。** 型別 0 不生怪，也不要當成「表是空的」。

## 3. 一場遭遇有三組

三組的數量與型別都寫在地圖記錄裡，位移是固定的：

| 組 | 型別 | 數量 |
|---|---|---|
| 0 | `+0x03` | `+0x04` |
| 1 | `+0x05` | `+0x06` |
| 2 | `+0x07` | `+0x08` |

數量為 0 的組直接跳過。每組最多 10 隻（30 bytes 只放得下 10 個 16-bit 血量），
**超過就會寫進下一組**——原版沒有防呆，remake 要夾住並記一筆，
不要靜靜溢出（原版資料是不是保證 ≤ 10 沒有驗過）。

## 4. 血量

```
基礎 = 敵人資料 +0x00 | +0x01 << 8
血量 = ⌊基礎 / 4⌋ + 1d(基礎 & 0xFF) + 256 × 1d(基礎 >> 8)
```

⚠ 三件事照抄：

1. **高低位分開各擲一次**，不是擲一次 16-bit。基礎 < 256 時高位是 0，
   `1d(0) ＝ 0`，公式退化成 `⌊基礎/4⌋ ＋ 1d(基礎)`。
2. **每一隻各擲各的**，同組同型別的血量不一樣。
3. 42 個區塊裡有 8 筆基礎值 > 255（`docs/re/37` §3.2），
   所以高位那一項**不是死碼**，不要簡化掉。

血量是 16-bit 無號，扣到 ≤ 0 夾成 0（規格 06）。

## 5. 距離

```
距離(dx, dy) = 表[10 × |dy| + |dx|]        dx ≤ 9、dy ≤ 4
```

表是 **5 列 × 10 行的原始資料，逐格照抄**。值大致等於 `10 × √(dx² + dy²)`，
但**任何取整都重現不了全部 50 格**（最接近的四捨五入也差 5 格），
偏差在 −1 … +2 之間。用公式生會有五到十二格對不上，
而症狀是「命中率差一點點」——玩得出來，查不出來。

`|dx| > 9` 或 `|dy| > 4` 時原版會讀到表後面的零區——那是**視窗外**，
remake 直接回報「超出範圍」，不要假裝距離是 0。

## 6. 驗收

1. 型別 0 不生怪；數量 0 的組不佔格子。
2. 血量落在 `⌊基礎/4⌋ + 1` 到 `⌊基礎/4⌋ + 基礎` 之間（基礎 < 256 時）。
3. 同一組 10 隻的血量**不會全部相同**（各擲各的）。
4. 數量 > 10 會被夾住並回報，不會蓋到下一組。
5. 距離表 50 格與原版的原始 bytes 逐格相同（**測試的對照組要是原始 bytes，不是公式**）。
6. 遭遇生成 → 規格 12 的 `Battle` → 打完，1,000 場不 panic、血量不溢位。

## 7. 這份規格**沒有**涵蓋

- **逃跑與隊形**——還沒逆向（`docs/re/36` §5）。
- 遭遇佇列 `ds:A96Fh` 是誰填的（誰決定「這一格有遭遇」）。
  目前只能由呼叫端指定，不能從地圖自動長出遭遇。
- 敵人資料 `+0x04` 高 4 位、`+0x06`、`+0x07`。
