## 2. 佇列

64 bytes ＝ **4 個隊伍組 × 4 個槽 × 4 bytes**，第 g 組從 `16 × g` 開始。

| 位移 | 內容 |
|---|---|
| `+0x00`／`+0x01` | 遭遇所在格的 x／y |
| `+0x02` | 資源（地圖）編號 |
| `+0x03` | 與最近那一組隊伍的距離 |

⚠ **每次掃描都整個清空重建。** 這是「目前視野裡有哪些遭遇」的快照，
不是待辦清單——不要做成會累積的佇列。

## 3. 掃描

```
對視窗裡的每一格（9 列 × 19 行，原點是視窗原點，夾在地圖邊界內）：
    第 1 層 nibble ≠ 3 且 ≠ 15 → 不是遭遇
    取這一格的地圖記錄
    距離 = 距離表(格 − 隊伍)            ← 規格 13 §5
    距離 > 記錄+0x00 → 略過              （察覺距離上限）
    這一格沒有敵人 → 略過
    距離 ≤ 記錄+0x01 → 進佇列            （主動距離）
    距離 < 該組的接戰值 → 進佇列
    否則 → 略過
```

9 × 19 就是地圖視窗，也正好是距離表涵蓋的範圍——**視窗外沒有遭遇**，
所以距離查表不會越界。

## 4. 接戰值與「哪一組最近」

每個隊伍組的接戰值 ＝ 該組成員接戰值的**最大值**：

| 值 | 條件 |
|---|---|
| 0 | 不能行動（CON ≤ 0） |
| 15 | 能行動 |
| 254 | 能行動且射程條件成立（**那條路還沒逆向，先當成旗標由呼叫端給**） |

距離上限是 98，所以 15 ＝ 只有貼身才算數、254 ＝ 任何距離都算數。

接著對四個隊伍組各評一次這一格：

```
該組不在這張地圖／這一格不在該組的視窗內／該組沒有敵人可打 → 不適用
距離 ≤ 記錄+0x01 或 距離 < 該組的接戰值                    → 記下「距離」
否則                                                      → 不適用
```

⚠ **記下的是距離，不是接戰值。** 然後挑**距離最近的那一組**——
四組全都不適用就整格略過。那個距離寫進佇列 `+0x03`，那一組決定放進哪四個槽。

槽內**由近到遠**排；四槽滿了就擠掉最遠的那筆。
如果這筆本來就在佇列裡而且原本就在最近那一組的槽，什麼都不做。

## 5. 與敵方記錄同步

掃描收尾時，敵方記錄（規格 13）如果**不在佇列裡**（比對 x／y／地圖三個 byte）
就整筆清成 0。走出視野的遭遇會被丟掉。

## 6. 驗收

1. nibble 3 與 15 才是遭遇；其餘 14 個值都不是。
2. 掃描不越出地圖邊界，也不掃視窗外。
3. 距離 > 察覺上限的格子完全不進佇列。
4. 距離 ≤ 主動距離一定進；否則要看接戰值。
5. 佇列每次掃描重建，不會累積上一輪的內容。
6. 同一組四槽滿了之後，**距離最遠**的那筆被擠掉；槽內由近到遠排。
7. 掃完之後，不在佇列裡的敵方記錄被清空。

## 7. 這份規格**沒有**涵蓋

- 決定接戰值 15／254 的那條路（`sub_199F1`／`sub_19D2F`）。
- 記錄 `+0x09 >> 2` 的用途。
- 在地圖上畫敵人圖示（那是呈現層）。
