## 2. Section 記錄定址

```
標頭位移 = 執行檔 ds:B9E0h[型別]        ; 24 筆，0 表示這個型別不存在
section 起點 = word(標頭 + 標頭位移)     ; 區塊內位移
記錄位址   = word(section 起點 + 編號×2)
```

**取一格的記錄時，型別就是那一格第 1 層的 nibble 本身**，第 2 層的值是索引
（`sub_169EB`）。所以 nibble 2 的格子讀型別 2、nibble 6 讀型別 6。

型別 `0x10` 是例外：**它的指標陣列裡存的是腳本 opcode 不是位移**，
要取原始 word 不能解參考。

型別 3 與 5 的 section 是 `[16-bit 指標陣列][記錄本體]`，
**陣列長度不另外存——第一個非空指標指到哪，陣列就到哪為止。**

## 3. 檢定

檢定是全遊戲共用的一個骨架，技能與屬性只是不同的填法。

```
門檻 B = 難度 × 5 + 15
骰   = 2d6 逢同點續擲（sub_19C84）
       骰 < 5 → 直接失敗，不看任何加成
本事 A = 骰
        + 該技能對應的屬性值        （技能檢定才有；屬性位移在技能資料 +0x01）
        + 技能等級 × 3              （技能檢定才有）
        + 指定的屬性值              （屬性檢定：位移由條件參數給）
成功 ⟺ A ≥ B
```

- 只要骰得成（≥ 5），**不論成敗都給經驗值 ＝ 骰值**——但要先過 `ds:916Bh`
  那道開關：**只有玩家自己走出來的那一步之後的檢定才給**（`docs/re/32` §7.1）。
  自動步（站著讓時間流逝、每 1024 個時鐘刻走的那一步）把開關清成 0，之後的檢定不給。
  ⚠ 開關記的是**最後一次移動**，不是每次檢定各自設——玩家走一步之後，
  接下來所有檢定都給，直到下一次自動步。不要改成 per-check。
- 屬性檢定有兩個特例：位移 `0x18`（性別）比相等、`0x24`（等級）比大小，**都不擲骰**。

### 3.1 檢定成功之後會練等

```
沒學過這個技能              → 不升
技能等級 ≥ 角色等級         → 不升        ← 技能等級上限就是角色等級
技能等級 ≥ 難度             → 不升
門檻 = (難度 − 技能等級) ÷ 2 + 1
roll(1..10) < 門檻          → 技能等級 +1（飽和 255）
```

## 4. 條件串列（nibble 2）

地圖記錄 `+0x0A` 起，**每 2 bytes 一條**，逐條試到成功或碰到 `0xFF`：

| byte | 內容 |
|---|---|
| `+0` | 高 3 位 ＝ 型別；低 5 位 ＝ 難度（0–31） |
| `+1` | 型別相關的參數 |

| 型別 | 參數 | 判定 |
|---:|---|---|
| 0 | 技能編號 | 有這個技能才試 → 技能檢定 |
| 2 | **角色記錄位移** | 屬性／等級／性別檢定 |
| 3 | 一個數 | 與隊伍人數相等 |
| 4 | 金額 | 金錢夠不夠（**只比不扣**） |
| 1、5、6、7 | 物品編號 | 身上有沒有 → 有的話**消耗一次** |

物品的附屬 byte **低 6 位是次數**，減到 1 之後再用就把整個槽移除；
高 2 位原樣保留。

## 5. 地圖腳本（nibble 6）

記錄 `+0x00` 的 bit7 決定走哪條：

- **bit7 ＝ 1**：索引 `& 0x7F` 進 `ds:A4E0h`（5 個設施畫面：商店、醫生、
  技能訓練師、存檔處、未定）。設施要用到的 13 bytes 地點名稱在記錄裡。
- **bit7 ＝ 0**：經 section 型別 `0x10` 換成 opcode，進 `ds:A4EAh`（44 個指令）。

直譯器的狀態：

```
PC        目前這筆記錄（ds:46AEh）
下一步    記錄 +0x01/+0x02
CF        指令回報：0 ＝ 繼續、1 ＝ 停
```

44 個指令的完整語意在 [`docs/re/34`](../re/34-map-script-opcodes.md) §2。
分成六類：

| 類 | 指令 | 說明 |
|---|---|---|
| 分支 | 0、1、3、15、36、43 | 依地圖／條件／時鐘／座標／相鄰格／持有物品換「下一步」 |
| 遭遇控制 | 18–25、27、28、40–42 | 加減標頭 `+0x2F`／`+0x31`／`+0x32`，各有上下限 |
| 世界改寫 | 6、8、9、29、30、32–34、37、38 | 往 section 5 放東西、複製記錄、批次改 section 3 |
| 角色 | 7、10–12、16、17 | 狀態旗標、全隊變性、沒帶某物品就扣血 |
| 時間 | 4、14、35、39 | 時間戳、倒數顯示、算過了多久 |
| 其他 | 2、13、26、31 | 畫面、nop、等待、中止 |

## 6. 事件處理（其餘 nibble）

| nibble | 行為 |
|---:|---|
| 1 | 記錄 `+0x00` 起一串字串（bit7 ＝ 續接）；**隊伍就站在這一格時不印** |
| 4 | 印記錄 `+0x00` 那條 |
| 5 | 寶箱：`+0x02` 起每 2 bytes 一組。第一個 byte `< 0x80` 是**還沒決定的類別**——擲出具體物品、設 bit7、**寫回記錄**；數量同樣擲一次。`0x00` 結束、`0xFF` 結束並開隊伍名單 |
| 8 | 選單：數出 `+0x03` 起有幾個選項（最後一個 bit7 ＝ 結束），收 `'1'`–`'9'` |
| 9、12 | 印訊息 |
| 10 | 傳送：隊伍槽表 `+0x0B`／`+0x0C` |

## 7. 未解與邊界

- **自動步本身還沒實作**。`ds:916Bh` 的語意已解（§上），但「方向碼 4」那條路
  （`sub_1651A(4)` → `sub_1649E`）到底怎麼走完，還沒讀——目前只有玩家步，
  所以開關實務上一直是 true。不要因此把開關拿掉。
- 條件型別 1／5／6／7 判定路徑相同，為什麼分四個編號未解。
- opcode 2（overlay 畫面）與 26（`sub_1142B`）語意未解。
- nibble 8 的選項各自對應什麼動作未讀。
- 段落編號是純文字，**不做任何段落機制**；中文化在文字層替換
  （`docs/re/33`、`CLAUDE.md` §3.2）。

## 8. 驗收條件

1. 42 張地圖的每個 section 型別 3／5／15／16／17，指標陣列都解得開，
   記錄位移落在區塊範圍內。
2. 把 42 張地圖裡所有 nibble 2 的格子的條件串列全部解析一遍，
   **型別與難度都在值域內、`0xFF` 收尾**，不得有解析不了的。
3. 檢定：固定亂數種子跑 10,000 次，骰 < 5 的比例與 2d6 續擲的分佈相符；
   門檻公式用手算的邊界值逐一比對。
4. 練等：技能等級永遠不超過角色等級。
5. 腳本：把 42 張地圖裡 nibble 6 的記錄全部跑一次分派，
   **不得有未知 opcode**（超出 0–43 就是解析錯了）。
6. 寶箱：同一格踩兩次，第二次的內容與第一次相同（生成結果有寫回記錄）。
