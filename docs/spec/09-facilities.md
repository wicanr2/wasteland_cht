## 2. 怎麼進到設施

踩上第 1 層 nibble ＝ 6 的格子，記錄 `+0x00` 的 **bit7 ＝ 1** 時，
`& 0x7F` 就是設施編號（0–4）：

| 編號 | 設施 | 畫面用的 ALLPICS 圖 | 名稱在記錄的哪裡 |
|---:|---|---:|---|
| 0 | **醫生** | 0 | `+0x07` 起 13 bytes |
| 1 | **商店** | 1 | `+0x07` 起 13 bytes |
| 2 | **技能訓練師** | 2 | `+0x04` 起 13 bytes |
| 3 | 存檔處 | 3 | `+0x03` 起 13 bytes |
| 4 | 未定 | — | — |

那 13 bytes 是**地點名稱的明文**，會被複製到 `ds:7201h` 印出來，
存檔的全域 `+0xD0` 存的就是它。

## 3. 商店

```
價格 = 基礎價 − (基礎價 >> n)
```

- 基礎價 ＝ 物品資料 `+0x00/+0x01`（16-bit），表在 `ds:7A31h`，95 筆 × 8 bytes。
- `n` ＝ 這筆地圖記錄的 `+0x03`（折價指數：0 ＝ 原價、1 ＝ 半價、2 ＝ 75%…）。
- 只有物品資料 `+0x02` 非 0 的才會出現在清單上。
- 買賣扣款走金錢欄位（`+0x15`–`+0x17`，24-bit）：**先比大小，不夠就失敗**。

## 4. 醫生

先看這個角色需要什麼，再決定選單上有哪幾項：

| 選項 | 按鍵 | 價格 | 條件 |
|---|---|---|---|
| **Exam**（檢查） | `E` | 記錄 `+0x05` | 這張地圖有檢查服務 |
| **Healing**（療傷） | `H` | 記錄 `+0x04` **每點 CON** | CON < MAXCON |
| **Curing**（治病） | `C` | 記錄 `+0x06` **每種疾病** | 狀態 `+0x28` 非 0 |
| 換人 | `P` | — | |

```
要治的點數 = MAXCON − CON        （16-bit 減法）
療傷總價   = 要治的點數 × 記錄 +0x04
治一種病   = 記錄 +0x06，成功後把該狀態位元清掉
```

錢不夠時印 `You don't have enough money.`；沒病時印 `You have no diseases.`。

## 5. 技能訓練師

用規格 05 §4.1 與 `docs/re/32` §2 的公式：

```
IQ 需求  = 技能資料 +0x00 >> 3
基礎費用 = 技能資料 +0x00 & 7
升到等級 L 的費用 = 基礎費用 × 2^(L−1)，飽和 0xFF
```

兩道檢查照原版順序：先 IQ、再技能點。

## 6. 未解與邊界

- 設施 4 的身分未定（`0x1B4F0`：逐隊員設 `+0x4B` 的 bit0 ＋ 四階段動畫）。
- 存檔處（`0x1A2C0`）的選單各項還沒讀。
- 醫生的實際扣款與套用只解到價格欄位與選單，逐行流程未讀——
  **規格照公式實作，並在程式碼註明這一層是從價格欄位推的**。
- 商店買賣的完整互動迴圈（挑物品、賣出價）未讀。

## 7. 驗收條件

1. 價格公式：`n` ＝ 0–3 各驗一組，`基礎價 − (基礎價 >> n)` 逐值比對。
2. 療傷：CON 10／MAXCON 28、單價 5 → 總價 90；付得起就回滿、付不起要失敗。
3. 治病：清掉指定的狀態位元，其餘位元不動；錢不夠不清。
4. 學技能：IQ 不足與技能點不足各自回對應的失敗原因（規格 05 已驗）。
5. 掃 42 張地圖所有 bit7 的設施格，**編號都要落在 0–4**（規格 07 已驗）。
