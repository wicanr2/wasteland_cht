## 1. 產生器：五個位元組的進位鏈

```go
type State struct{ s [5]byte }   // 對應 ds:465Ch–4660h

func (r *State) Next() byte {
    r.s[0]++
    a := r.s[0]
    carry := false
    for i := 1; i < 5; i++ {
        a, carry = addc(a, r.s[i], carry)   // adc
        r.s[i] = a
    }
    return a                                 // 回傳最後一次 adc 的結果
}
```

原版的 `sub_18E6B` 是 `inc` ＋ 一次 `add` ＋ 四次 `adc`，**沒有乘、除或移位**。
每次 `adc` 的結果都寫回對應的位元組，回傳值是最後一個位元組。

### 1.1 初值與種子

映像裡五個位元組是 `00 00 00 00 00`，**全檔沒有任何設種子的程式碼**
（兩道全檔掃描：直接定址寫入點只有那五條 `mov`；取址掃描零命中）。

熵來自**鍵盤輪詢的次數**：`sub_18EFE` 每輪詢一次就推進一次產生器，
所以序列取決於玩家花多久按鍵。

**remake 的取捨**：這個行為要照做（不然「等久一點再按」的差異會消失），
但**存檔要把五個位元組一起存**，否則讀檔後的序列與原版不同。
原版的存檔範圍已知包含 `ds:464Eh`–`465Bh`，**`465Ch` 起的 RNG 狀態不在裡面**
（[`re/27`](../re/27-game-clock.md) §7）——也就是原版讀檔後 RNG 從當時的記憶體狀態繼續。
remake 若要可重現的存檔，**存 RNG 狀態是偏離原版的設計決定，要在文件標明**。

## 2. 擲骰

| 函式 | 原版 | 語意 |
|---|---|---|
| `D6()` | `sub_18E5F` | 1..6 |
| `Roll(n)` | `sub_18E41` | 1..n |
| `SumD6(base, n)` | `sub_19D86` | base ＋ n 顆 d6（16-bit） |
| `PairD6()` | `sub_19C84` | 2d6，逢同點續擲並累加 |

### 2.1 `D6`：拒絕取樣

```go
for {
    v := next() & 7
    if v < 6 { return v + 1 }
}
```

取低三位得 0..7，**6 與 7 直接重抽**。是拒絕取樣不是取模，所以六面等機率。

### 2.2 `Roll(n)`：遮罩 ＋ 拒絕取樣

```go
if n <= 1 { return n }        // ⚠ n=0 回 0、n=1 回 1，原樣送回
mask := byte(0)
for v := n; v != 0; v >>= 1 { mask = mask<<1 | 1 }   // 不小於 n 的最小 2^k−1
for {
    v := next() & mask
    if v < n { return v + 1 }
}
```

回傳 **1..n 閉區間，等機率**。`n = 0` 與 `n = 1` 的邊界行為要照抄——
呼叫端有依賴（`docs/re/13` §3.2）。

### 2.3 `SumD6(base, n)`：累加 n 顆 d6

回傳 16-bit（原版分成低位 `AL`、高位 `DL`）。`n = 0` 時回傳 base。

### 2.4 `PairD6()`：會爆開的檢定骰

```go
sum := 0
for {
    a, b := D6(), D6()
    sum += a + b
    if a != b { return sum }     // 同點就再擲一對，繼續累加
}
```

最小值 3（1+2），理論期望 8.4。11 個呼叫端，是規則層的通用檢定骰。

## 3. 未解與邊界

- 原版的累加器用的是 8-bit 加法鏈，`SumD6` 的高位進位行為在極端值下要照抄，
  不要換成 Go 的 `int` 直接加——顆數大時結果會不一樣。
- `Roll` 的呼叫端有 24 個，**其中哪些期望「1..n」哪些期望「0..n−1」尚未逐一確認**；
  實作照原版回 1..n，呼叫端自己減。

## 4. 驗收條件

`tools/rng.py` 的自我測試就是驗收基準，Go 版要重跑同一組：

| 檢查 | 期望 |
|---|---|
| 全零狀態的前 7 個輸出 | `1 6 21 56 126 252 206`（＝ `C(n+4,5) mod 256`） |
| 第 8 項 | `25`（與二項式的 24 分歧，代表進位開始回饋） |
| `Roll(0)`／`Roll(1)` | `0`／`1` |
| `Roll(3)` 值域 | {1,2,3} |
| `Roll(100)` 值域 | 1..100 |
| d6 分佈（60 萬次） | 各面偏差 < 3% |
| `SumD6(0,6)` 平均 | 21.0 ± 0.1 |
| `PairD6()` 平均 | 8.4 ± 0.1 |
| 300 萬次呼叫 | 狀態不重複 |

前七項等於二項式係數是**「初值真的是全零」的獨立佐證**：
只要初值不是全零，第一個輸出就不會是 1。Go 版若第一項不是 1，就是初始化寫錯了。
